## Positive Observations

- **The oracle section (§3) is the strongest part of this document and should be preserved as-is.** O-1's third conjunct (the seam's pre-advisory behaviour still happened) is exactly what makes an escalation property falsifiable against a build where the seam swallowed the halt; O-2's positive-presence pre-condition kills the vacuous "output == input" comparison on a fixture that never held the content; O-3's counted oracles are the correct answer to identical-envelope behaviours. Defining them once by name, and referencing them from property rows, is why 189 properties stay readable.
- **O-5 (precedence-defeating fixtures) is a genuinely rare discipline and it is applied, not just declared.** PROP-REF-03, PROP-A3-06, PROP-A4-04, PROP-A5-03 and PROP-A2-08 each name the earlier branch their fixture must defeat. This is the class of defect that ships silently and this document closes it.
- **The prohibitions (§6.4) obey AC-4.6 without being asked twice.** Each of PROP-PROH-01…04 pairs the negative with O-1 on the same execution, and PROP-PROH-03 explicitly demotes the source grep to "a cheap secondary" behind the behavioural spy-count oracle. That is the right ordering and it is stated, not implied.
- **Set-equality is used where it matters.** PROP-INFRA-04, PROP-XA-08, PROP-GATE-06, PROP-REF-01, PROP-ENV-12 and PROP-SUM-01 are all driven off the exported constant rather than a hand-written list, so a deleted case fails and an added member fails until it has a case. PROP-GATE-06 closing the registry loop in both directions is a nice piece of design.
- **The reuse instinct is correct throughout.** `guardVerdict` / `effectiveGuardPaths` for X-e (verified at `orchestrate-dev.js:731`, `:708`), `commitPaths` / `gitWithLockRetry` for A2's commit (`:6905`, `:6862`), `checkPrCi` for `ciStatus` provenance (`:5927`), `driftGenerators.js`'s `seeded` / `resolveSeed` (`:76`, `:134`) for every generator property, and `mergeDoubles.js` / `tmpGitFixture.js` / `guardFixtures.js` composed rather than re-authored. No parallel mechanism is invented. This is also consistent with `DECISIONS-test-oracle-mechanics.md` DEC-ORACLE-03 (one canonical double per gate).
- **Every line-cited claim about existing code in §1's grounding table verified against the working tree** — all 25 dev-module citations, all 8 queue-module citations, the three `driftGenerators.js` citations and the guard-hook citations (`guard-harvest-before-delete.sh:35`, `:43`, `:57-59`) land on the symbol claimed. `\bgit\s+rm\b` in the guard's regex (`:37`) is where PROP-HARV-03 says it is. This is the standard the review checklist asks for and it was met on the first pass.
- **Traceability is complete in both audited directions.** All 51 REQ acceptance criteria and all 5 NFRs appear in §12.1 with at least one property; all 36 PLAN §3 tasks appear in §12.2, and the three that carry no property (A-34, A-35, A-36) each say why rather than leaving the reader to infer it. §12.3's claim that no `advisory*` file exists in `pdlc/workflows/__tests__/` today is correct.
- **§13 is the right way to handle upstream disagreement.** The A1 `verifyGate` contradiction and the P-4 closure weakening are both real — I confirmed them independently (PLAN §8.2 vs TSPEC §5.5/§6.3; PLAN §6.5 P-4 vs TSPEC §5.1's JSDoc). Naming them, asserting the invariant that holds either way, and deferring the representation to the owning author is exactly correct behaviour.
- **§2.5's `describe.skip` packaging rule is the honest answer to a real constraint.** Phase I's script-owned gate does run the whole suite and throw (`orchestrate-dev.js:8113`), so RED-terminal waves are not available; wrapping red in skip and pairing it with a zero-skips-remaining check is the only shape that works here, and the document says so plainly rather than pretending waves can end red.
