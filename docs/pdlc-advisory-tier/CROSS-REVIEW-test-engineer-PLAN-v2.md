## Positive Observations

- **The skip discipline is the right resolution to F-01, and it is empirically true rather than plausible.** I ran it: a `describe.skip`-only file with a body that cannot even import exits 0 and reports the case as skipped. It also has in-repo precedent the PLAN did not need to cite but which strengthens it — `skipSink.js:17-21` deliberately places direct `describe.skip` outside the run-scoped skip comparator's domain, naming `guardMatrix.test.js`'s 70 `it.skip.each` rows. The discipline composes with the existing gate rather than fighting it.
- **§3 preamble step 3 answers Q-04 better than I asked.** Moving the red evidence into the 🟢 task's own commit pair, and then making §9.2 refuse a single-commit green task, converts "TDD happened" from a claim into an artifact a DoD reviewer can read off `git log`. That is a stronger contract than the batch boundary it replaces.
- **§6.4 is now genuinely mechanical, and I could not break it.** Enumerating the 24 names in-document (rather than by reference to a TSPEC section whose rows are partly prose), excluding the five `(reused)` symbols from the denominator, and reducing over `fnMap` declaration ranges is the correct shape. Both commands ran; `fnMap` carries real names despite `"transform": {}`; the reducer prints two comparable numbers. The added instruction that an unresolved name is *itself* a finding closes the last hole — a renamed symbol cannot silently shrink the denominator.
- **§6.5's properties are mostly falsifiable against a wrong implementation, not merely against a throw.** P-1's per-key independence ("corrupting key *k* leaves every key ≠ *k* equal to the value parsed from the uncorrupted input, and puts exactly *k* into `invalidKeys`") and P-2's partition claim ("every generated input matches exactly one rule or parses cleanly, never two, never none") are both genuine set-equality-shaped oracles, and P-7's append-safety law (rendering N and concatenating equals appending one at a time) makes the newest-last invariant a property of the renderer rather than of its caller. The seeding discipline is inherited from the shipped generator rather than reinvented, and the note that properties never replace the named FSPEC cases ("a property that subsumed a case would hide which case failed") is exactly right.
- **A-34's two-form discharge rule is a model for how to write an unverifiable task.** Naming `RESULT: unverified — no runtime available` as *fully* satisfying §9.4, while naming an inferred result as mock data that `dod-verify` binds to, removes the incentive to fabricate — and §6.3's requirement that the `RESULT:` line survive harvest verbatim keeps the honest answer durable.
- **The DAG survived the revision intact.** A-00's removal renumbered nothing: 36 tasks, 36 ownership rows, `{"ok":true}`, 20 executor batches, every `planBatch` equal to `max(dep batch) + 1`, no cycle, no unresolved dependency, ids unique. §9.1's re-execution claim is exact.
- **§10.1 item 5 declares the out-of-scope repair instead of hiding it**, with the repo-wide blast radius stated ("every future feature's wave gate reads the repaired command"). A Phase DOD reviewer meets it as a deviation rather than discovering it in a diff — which is the whole point of an open-items table.
- **§8.2's T-03-6 expansion is the right test, and the mutation check is the right proof.** "With the gate replaced by `() => ({ passed: true })` the case fails" is a mutation oracle stated at PLAN altitude — it is only its *ownership* I am flagging in F-01, never its content.

## Recommendation

**Needs revision**

This is a strong revision: all eleven v1 findings and all four questions are resolved, several of them
better than asked. The two remaining Highs are both consequences of the new mechanisms rather than
defects in them, and both are small edits.

1. **F-01** — the skip discipline needs one stated rule ("a block's un-skipper is the task that lands
   the last symbol its cases exercise") and two consequential edits: `advisoryDriver.test.js` has one
   declared green owner (A-22, batch 9) but §8.2 assigns T-03-6(b)'s gate cases to A-23/A-24
   (batches 10/11), and T-02-4/T-02-5 sit in a file un-skipped at batch 6 while §3's own A-22 row
   claims their mechanism at batch 9. Either way an un-skip goes red inside a wave, and
   `orchestrate-dev.js:8113-8118` halts the run — the exact outcome the discipline was introduced to
   prevent.
2. **F-02** — decide the tracking question for `.claude/pdlc.config.json` rather than deferring it.
   The file is untracked and not gitignored; CI runs bare `npm test` on a fresh clone
   (`pr-tests.yml:75`), so A-01's unguarded read of it is red on both matrix legs and Phase PUB halts.
   Commit the file, or guard the case with a positive assertion on the absent-config path.

Then F-03: restate P-4 over `classifyEnvelope`'s real signature (`{inside, reason, matched}` from
`TSPEC:517`) — determinism plus `reason ∈ ADVISORY_REFUSAL_REASONS ∪ {null}` and
`inside === (reason === null)` are the invariants a wrong implementation actually breaks.

The three Lows are a prose/procedure mismatch in §6.4's denominator, a `documentOracles` noise source
in the coverage command, and P-9's unspecified empty-input case. Fold them into the same revision.

Nothing about the DAG, the ownership manifest, the doubles strategy, the coverage procedure or the
property catalogue needs rework — all four were verified by execution and all four hold.
