## Positive Observations

- **The AC/NFR coverage matrix is genuinely complete, and I checked it row by row.** Every one of REQ §3's 51 acceptance criteria (AC-1.1 … AC-10.5) and all five NFRs appears in §12.1 with at least one named property. That is the single thing this review exists to verify, and it holds — including the ones easiest to lose: AC-8.6's no-checks-named-in-the-summary (PROP-A5-14, PROP-SUM-05), AC-10.5's *don't widen the merge catalogue* (PROP-ESC-07's own-property snapshot), and AC-9.3's harvest-guard extension (PROP-HARV-03…06).
- **The seven record fields and the eight escalation fields are transcribed from the REQ, not derived.** PROP-REC-02's field list is byte-for-byte AC-9.1's ("timestamp, seam, diagnosis, confidence, envelope determination, action taken or escalated, evidence citations"), and PROP-ESC-01's is AC-10.1's seven plus AC-10.2's decision sentence first. §2.4 makes the transcription discipline explicit and names the normative source per literal — that table is the reason a later cosmetic edit to the operator-facing files reads as a decision rather than a refactor (§13.3 item 2 says so in as many words).
- **The prohibitions carry a positive on the same path, which is exactly what AC-4.6 asks for.** §6.4's preamble quotes AC-4.6's rationale and then PROP-PROH-01…04 each pair the negative with O-1. PROP-PROH-03 goes further and demotes the source grep to "a cheap secondary", asserting `ciStatus` provenance behaviourally via a call-count spy and last-return-value identity — that is the right instinct for AC-4.3, whose whole point is that no value may come from anywhere but the rollup.
- **Refusals are proved exhaustively rather than by sampling.** PROP-REF-01 pins AC-3.6's eight reasons as an ordered list *and* as a set, PROP-LIFE-12 parameterises the O-1 triple off the exported constant so a newly-added reason fails until it has a case, and PROP-REF-03 uses a fixture that genuinely satisfies two triggers so the "first matching trigger wins" clause is tested rather than assumed. AC-3.6's closing sentence asked for set-equality; it got set-equality plus order plus precedence.
- **X-a gets one property per enumerated operation, as AC-3.5 demands.** PROP-XA-01…07 map one-to-one onto AC-3.4(a)'s seven operations, and PROP-XA-08 adds the enumerability check so a deleted clause fails. §6.2's framing — "fixing a red test by editing the test is the pipeline's most dangerous failure mode" — is the REQ's own language, and PROP-A5-18 re-asserts it at the seam where an agent is most likely to try it.
- **Every code citation I checked is accurate at branch head.** All 24 grounding rows in §1 verified: `guardVerdict` `orchestrate-dev.js:731`, `effectiveGuardPaths` `:708`, `commitPaths` `:6905`, `gitWithLockRetry` `:6862`, `checkPrCi` `:5927` (rollup read at `:5933`), `raisePrAndVerifyCi` `:6337`, `rebaseOntoDefault` `:6254`, `dodVerifyLoop` `:6273`, `parseDodStatus` `:6059`, `DOD_MAX_ITERATIONS = 3` `:25`, `defaultAppendFile` `:6805`, `MERGE_ESCALATIONS` `:1321`, `MODEL_DEFAULT` `:1578`, `MODEL_IMPLEMENTATION` `:1621`, `buildFinalReport` `:8595`, `parsePlanTasks` `:2039`, `parseImplementationConfig` `:181`, the wave gate `:8113`, the wave-prompt lines `:5850`/`:5851`, the guard-message consumers `:8342`/`:8348`; queue-side `parseTriageVerdict` `:302`, `triagePrompt` `:653`, `precheckDependencies` `:630`, `parseQueue` `:116`, `parseReqFrontmatter` `:232`, `updateQueueStatus` `:358`, `rewriteStatus` `:1086`, `buildQueueReport` `:1221`, the blocked-pre-check skip `:890-897`; the guard hook's early-exit `:35`, token regex `:43` and refusal message `:57-59`, including the `\bgit\s+rm\b` alternative PROP-HARV-03 relies on (`:37`). Every FSPEC case id referenced exists in FSPEC §18.
- **§12.2 and §12.3 are honest about what they cannot cover.** All 36 PLAN tasks appear, and the three that carry no property (A-34, A-35, A-36) each say *why* in their own row rather than leaving a reader to infer it. §12.3's claim that no `advisory*` file exists today is correct — `pdlc/workflows/__tests__/` has none — and the five shipped helpers it composes with (`mergeDoubles.js`, `driftGenerators.js`, `seams.js`, `guardFixtures.js`, `fixtures/tmpGitFixture.js`) all exist.

- **Disabled-tier inertness is stated on named artifacts, matching NFR-3's own wording.** PROP-DIS-03's created-file set equality against an authored fixture, with PROP-INFRA-03 re-asserting the `scenario` header first so staleness fails distinctly from a real diff, is a stronger oracle than the report-text comparison NFR-3 explicitly declined — and the red direction ("any file created outside that literal set fails, whether or not this feature named it") is named.
