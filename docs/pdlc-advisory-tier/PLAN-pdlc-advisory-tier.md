## 1. Summary

Build the **advisory tier** specified by TSPEC §§2–11: an off-by-default, config-gated layer that, at
five named seams where the pipeline today halts or skips, dispatches one bounded advisory agent,
enforces an envelope in the pipeline's own control flow, and either resolves under a gate, escalates,
or does nothing — recording every invocation and every escalation.

**Shape of the work.** One impure driver (`runAdvisorySeam`) plus a dozen pure exported leaves, wired
into four existing call sites and one new post-PUB step. Concretely:

| Deliverable | Where | TSPEC |
|---|---|---|
| Advisory constants, config parse, model-rung ladder | `pdlc/workflows/orchestrate-dev.js` | §3 |
| Verdict/disposition types, `runAdvisorySeam` driver, budgets | `pdlc/workflows/orchestrate-dev.js` | §4 |
| Envelope classifier, refusal ladder, owned predicates | `pdlc/workflows/orchestrate-dev.js` | §5 |
| A3/A4/A5 `SeamOps` + Phase DOD / Phase PUB wiring | `pdlc/workflows/orchestrate-dev.js` | §7, §8 |
| Advisory record, escalation log, report summary, post-PUB distil | `pdlc/workflows/orchestrate-dev.js` | §9, §10 |
| A1/A2 `SeamOps`, seam-token routing, queue report summary | `pdlc/workflows/orchestrate-queue.js` | §6 |
| Dev export list + queue prelude bindings | `pdlc/workflows/build-runtime.mjs` | §2.3 |
| Delete-guard extension to the `ADVISORY-*` class | `pdlc/hooks/scripts/guard-harvest-before-delete.sh` | §9.3 |

**Scale constraint that shapes the batching.** Three of the four source files are single physical
files that many tasks must edit — `orchestrate-dev.js` (8,642 lines at HEAD `ca55bb6`),
`orchestrate-queue.js` (1,587 lines), `build-runtime.mjs` (383 lines). Batch-safety rule 2
(single-writer-per-batch per physical file) therefore forces the dev-side and queue-side
implementation tasks into two **serial chains**, run concurrently with each other and with the
red-test wave. That is the reason this PLAN has 18 batches for 36 tasks: the parallelism is real but
it is across files, never within one.

**Not in scope.** No task edits `pdlc/workflows/dist/` — those artifacts are generated by
`implementation.postWaveCommand` (`node pdlc/workflows/build-runtime.mjs`) and committed under
`implementation.postWavePathspecs` (`pdlc/workflows/dist/`), both already configured in
`.claude/pdlc.config.json`. Hand-editing them is a Definition-of-Done violation (§9).

## 2. Pre-flight gate and baseline status

### 2.1 The rebase TSPEC §13.6 asks for is already satisfied — verified, not assumed

TSPEC §13.6 and risk R-5 require the PLAN's first task to be a rebase onto `26c3f1c`-or-later,
because "every symbol this document cites postdates this branch's base". **That precondition already
holds on this branch and needs no task:**

```
$ git rev-parse HEAD                                  → ca55bb6
$ git merge-base --is-ancestor 26c3f1c HEAD           → true   (REQ behavioral pin)
$ git merge-base --is-ancestor 5d66c48 HEAD           → true   (TSPEC citation pin)
```

Both pins are ancestors of the branch head, so the tree the implementation batches patch already
contains every symbol TSPEC cites. Task **A-01** replaces the rebase with the assertion that makes
that fact machine-checked rather than remembered — which is also what the standing pre-flight-gate
rule asks for: assert baseline-symbol *existence* at HEAD, never the new shape a dependent task
creates.

### 2.3 Halt-state recovery, scoped by path

If a batch halts mid-flight, recover by the **paths that batch owns** (§4's manifest), never
`git checkout -- .`, which would destroy earlier batches' landed work:

```bash
git status --short                       # see what the halted batch left
git checkout -- <exact paths from the halted task's manifest row>
node pdlc/workflows/build-runtime.mjs    # regenerate dist/ from the restored sources
```
