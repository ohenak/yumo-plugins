## Notes for the remediator

1. F9 and F10 are the cheapest and highest-leverage: a default-on behaviour change is currently
   invisible in every operator-facing surface (`pdlc.config.example.json`, `OPERATIONS.md`,
   `CLAUDE.md`, `pdlc/README.md`). The sibling test convention already exists at
   `pdlc/engine/__tests__/advisory-config-example.test.js` — copy it.
2. F1 and F12 are the same defect seen from two angles. Deleting the refusing `main` and recording
   a DECISIONS entry ("capture is a programmatic API; fixtures are committed artifacts") closes
   both without writing new capture code.
3. Row 21 (AC-5.1c, `enabled`) is a two-line test. Add `{ learningsInjection: { enabled: "false" } }`
   and assert both that `config.enabled === true` and that `NTC-KEYTYPE` names `enabled`.
4. F8 / row 9: prefer fixing the test (child-process composition) over weakening PROPERTIES §O.7 —
   the stronger property is the one that catches module-cache regressions, which this codebase is
   exposed to because `runScenario` deliberately reuses a cached `await import`.
5. Nothing in this review was fixed. This document is evaluation only.
