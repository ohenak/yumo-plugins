Only the first half is that reading. At HEAD, a wrong-typed value for a declared key is *not* malformed in either sibling: `parseAdvisoryConfig`'s `boolField`/`positiveInt`/`positiveNumber` push the key onto `invalidKeys` and substitute the declared default (`pdlc/workflows/orchestrate-dev.js:1989-2008`), returning `sectionMalformed: false` (`:2028`), and the run continues **enabled** with a non-fatal notice — `Advisory config: using defaults for {keys}` (`:13683-13684`). `sectionMalformed: true` is reached from exactly one place, the section-present-but-not-an-object guard (`:1981`; `parseMergeConfig` identically at `:123`). ## Positive Observations

- The BR-5 revision is the model form of a discharged measurement obligation: the rule states the bound, the paragraph states which of two bounds binds on the real corpus and why, and AT-07 asserts the rule under **both** regimes instead of picking the fixture where the interesting bound happens to fire. The count bound is now falsifiable in the direction it can actually fail.
- `RSN-NO-MATERIAL` was added where it belongs rather than where it was easiest: Step 5 drops the document *before* the count bound, so it consumes no slot; BR-9's catalogue, AT-19's set-equality closure, D-12 and E-33 all move together; and A-3 was rewritten to stop asserting the falsified universal. Catalogue closure survived the addition intact — I re-checked BR-9's six ids against AT-19's six.
- Deleting `RSN-TRUNCATED` rather than inventing a predicate for it is the right trade, and the FSPEC says so in the rule: no predicate over a document's own bytes separates truncation from E-19's legitimately-short document, so a fixture could not construct the branch. Shrinking a closed catalogue to what tests can reach is worth more than the lost expressiveness.
- BR-4's handling of the AC-2.2 conflict is exactly the right shape: it does not quietly re-scope the property, it states which of the 89 measured documents the rename-invariance claim cannot hold for, replaces it with a strictly stronger achievable property, and routes an erratum rather than leaving REQ and FSPEC to disagree in silence. AT-10 then pins the three orderings the rule must be independent of.
- AT-02's widening from "the classified dispatches" to "every agent invocation the run makes" is the difference between an oracle that can catch a misclassification and one that cannot; paired with BR-1's note that the lists are read off the classification, the set-equality claim is now falsifiable against the real dispatch universe.
- Every existing-code claim added in this round checks out at HEAD: the `34-postgres-audit-repository` document carries exactly `## Implementation Learnings`, `## Cross-Feature Findings`, `## Process Findings` (lines 3, 110, 130 — none of BR-6's five); the harvest section titles carry the numeric prefixes BR-6 cites (`pdlc/skills/harvest-learnings/SKILL.md:81-110`); the corpus globs match `LS_FILES_ARGV` (`consolidate-learnings.js:1338-1346`). Only BR-14's precedent claim fails, and it is F-01.
