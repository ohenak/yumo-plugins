## Positive Observations

- **The core product promise is genuinely delivered and genuinely wired.** AC-1.1 is not a builder tested in isolation: `learningsDispatchSet.test.js`'s `runScenario` (`:172-239`) drives the real `mainDev` default export end-to-end over a seamed filesystem and git, and `LI-AT-01` (`:257-278`) asserts that an authoring dispatch's *composed prompt* — the thing an author actually receives — contains the prior feature's material identified by source path. `LI-AT-02` (`:280-296`) then asserts the carrying set **equals** the authoring set by set equality over call indices, not containment, so a dispatch that silently stopped injecting reds. That is the AC → production caller → served artifact walk done properly, and it is the hardest part of this feature to get right.
- **C-4's advisory framing is faithful to the REQ, clause for clause.** `LEARNINGS_BLOCK_PREAMBLE` (`orchestrate-dev.js:2422`) states all three things BR-7 enumerates — prior-feature context, neither a requirement nor an upstream document to be traced, may be disregarded without leaving a gap — in wording that closely tracks AC-1.4's own. And C-8's non-displacement is proven structurally rather than asserted: `LI-AT-06` (`:437-459`) checks that the disabled run's prompt is a strict **prefix** of the enabled one, which is a stronger and more durable claim than "the manifest is still present".
- **Self-exclusion is decided from the path, before any read.** `isLearningsSelfPath` (`:2460`) matches both `docs/{f}/` and `docs/completed/{f}/`, and `selectLearnings` tests `excluded` **before** `readOk` (`:2486-2489`) so a self document can never be mis-reported `RSN-UNREADABLE`. That ordering is a small thing that would have produced a genuinely confusing report line, and it was thought about.
- **Fail-open is total, and the arm inventory proves the arms are entered.** `gatherLearningsCorpus` (`:2474`) wraps the whole shell in one outer `try/catch` and gives every per-file read its own inner one, so a listing fault and a single unreadable file degrade at different granularities — exactly C-7's "'I could not find out' never collapses into 'there is nothing'". `learningsArmInventory.test.js` then drives all twelve arms and asserts the observed reason sets **set-equal** the frozen catalogues rather than being contained in them, so an arm that stops firing reds. This is the right shape for a coverage obligation a line-coverage gate cannot see.
- **The catalogues are hand-transcribed, not imported.** `HAND_TRANSCRIBED_TARGET_DOCTYPES` and `HAND_TRANSCRIBED_COMPOSITION_SITE_SET` (`learningsDispatchSet.test.js:451-457`) spell the six doc types out as literals rather than importing `LEARNINGS_TARGET_DOCTYPES`, and the baseline guard's digests are hand-copied rather than read from `MANIFEST.json` (`learningsBaselineGuard.test.js:71-79`). Both are deliberate refusals of the implementation echo, and both are documented as such at the point of use.
- **`RSN-NO-MATERIAL` is grounded in a measured document, not invented.** FSPEC BR-6 names the real corpus file that carries none of the five priority sections, and the drop happens *before* the count bound so it consumes no slot (`orchestrate-dev.js:2372`) — which is what keeps a zero-byte contribution from being indistinguishable from a real one in the operator's rows. The reasoning is written down where the code is.
- **The disabled state is an absent key, not an empty one.** `buildFinalReport` spreads `learningsInjection` conditionally on the `advisory` precedent (`:15954`), and `LI-AT-31` asserts `hasOwnProperty` is `false` (`:423`) rather than merely falsy. AC-5.1a's distinction between "absent" and "present-and-empty" survives serialisation, which is the form an operator actually reads.

## Recommendation

**Needs revision**

Three High findings gate this round. The feature's product promise — a prior feature's lessons reaching the next author, bounded, deterministic, fail-open — is delivered and is proven against the real `main()`, and I want to say plainly that the hard part is done well. What is not yet done is the *guarding* of the promise's negative half: two of the three ACs that exist to catch a regression leaking injection into places it must not reach are currently unable to fail.

Exactly what must change before I can approve:

1. **F-01 — rebuild and stage `pdlc/workflows/dist/`.** Run `node pdlc/workflows/build-runtime.mjs`, stage `pdlc/workflows/dist/pdlc-cli.mjs`, commit. `consolidationBuild.test.js` `T32` must be green on the branch as committed. This is one command.
2. **F-02 — give AC-4.3 a real oracle.** `LI-AT-29`'s five observables are absent report keys and the comparison is `null === null` on both arms. Replace them with gate inputs that exist — the `phases[]` iteration counts, the parsed verdict records, the approval-anchor writes — or observe them through a recording seam. The acceptance bar is a mutation: break the injection boundary deliberately and watch `LI-AT-29` red.
3. **F-03 — wire the recorded baseline to an assertion.** The fixture, the capture script and the drift guard all ship; nothing compares a composed prompt to them. Read `fixtures/learnings-baseline/{caseId}/{i}.txt` and assert byte-equality against the disabled run's corresponding prompts (and, per PLAN §DoD item 4, the empty-corpus, unlistable and admits-nothing runs). Until this lands, AC-5.1a's "that committed pre-feature fixture, **not a second branch of this run**" is unmet by construction, and the three test titles claiming baseline comparison should be reworded to say what they actually compare.

The seven Medium findings (F-04…F-10) are recorded and should be addressed, but they do not gate this round on their own. F-06 additionally needs the two upstream errata resolved before the implementation can be made to match a single stated rule; F-10 is a scope decision for the operator rather than a code change, and I would be content with a REQ amendment naming the POSTMORTEM-D remediations as in-scope.

Two observations on the review process itself, offered rather than filed. First: F-02, F-04 and F-05's tautological clauses are the same defect three times — an oracle written over a field that does not exist, or over a set filtered so the predicate cannot fail. A cheap standing check would be a "the instrument fires" control assertion beside every negative claim; `LI-AT-33/34` already does this deliberately (`:706`), and it is the reason that test is trustworthy where the others are not. Second: this feature's own LEARNINGS will be the material a later feature is injected with. F-02 and F-03 are exactly the kind of lesson worth harvesting into it.
