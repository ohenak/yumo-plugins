| F-01 | High | Local | **C-1 names a REQ authoring dispatch that does not exist at HEAD.** `PHASE_DISPATCH.R` sets `creator: null` (`pdlc/workflows/orchestrate-dev.js:3629`), and the pipeline dispatches nothing for it: `if (dispatch.creator)` guards the only creator dispatch (`orchestrate-dev.js:13505-13508`, comment "`creator: null` (Phase R) reviews a document this pipeline did not write, so there is nothing to dispatch"), reaffirmed at the Phase R call site — "No creator (`PHASE_DISPATCH.R.creator` is null — the REQ arrives authored)" (`orchestrate-dev.js:13760-13761`). One of the six members of C-1's closed set therefore has no dispatch to inject into, and AC-1.1 ("any of the six authoring dispatches named in C-1 is composed") cannot be exercised for it. A TE deriving the AC-1.1 test suite gets five cases and one that cannot be written. Either drop REQ from C-1 and say where a REQ author is grounded instead (the REQ is authored outside `orchestrate-dev`), or state the separate integration point that would carry it and scope it explicitly. | C-1, AC-1.1, §1.2.1 |
| F-02 | High | Local | **"Exactly the six authoring dispatches" is not a closed, run-invariant set at HEAD, so AC-1.2's set-equality check cannot be written.** Three separate facts break the count. (a) Phase D is conditional: it runs only when the `DECISIONS_WARRANTED` trailer says so, defaulting true on absent/malformed input (`orchestrate-dev.js:5204-5239`, prompt at `9411-9412`) — a run with `DECISIONS_WARRANTED: false` has five, not six. (b) Every phase adds one **optimizer** dispatch per failing review round (`reviewLoop` step (g), `orchestrate-dev.js:7655-7660`), and the optimizer is an author writing the same document, sharing the creator's session (`M-2`, `:7657`). (c) **Erratum** author dispatches and their land-proof retries are themselves tagged `dispatchKind: "authoring"` (`orchestrate-dev.js:12821`, `:12915`), alongside the creator (`:13515`). AC-1.2 asserts a cardinality of six and byte-identity for "every other dispatch"; against HEAD it is either false or vacuous depending on the run, and the failure is invisible under a fixture that converges on iteration 1 with no DECISIONS. State the rule over the dispatch taxonomy that already exists (`dispatchKind === "authoring"` and phase membership), not over a hand-counted six, and say explicitly whether optimizer and erratum dispatches for an in-scope document are in or out — NG-5 excludes reviews, implementation, DoD and harvest but is silent on both. | C-1, AC-1.2, NG-5 |
| F-03 | High | Local | **AC-3.4's only testable half is the absence half, and its positive half has no trigger or output to assert on.** The AC pairs "the report surfaces it as a note against the named source document" with "**no** erratum round is opened". The negative conjunct already holds at HEAD for free: `parseErrata` ignores any line whose doc type is outside `ERRATUM_DOC_TYPES` rather than erroring (`orchestrate-dev.js:6945` regex, `:6971-6975`), so a `LEARNINGS` erratum line is dropped today, with or without this feature — a test asserting only "no erratum round opened" passes against the pre-feature baseline and proves nothing. The positive conjunct is what would make the oracle falsifiable, and the REQ defines neither what the author emits to raise the note (there is no such channel; `ERRATUM:`, `VERDICT:` and `DECISIONS_WARRANTED:` are the parsed trailers) nor what the report field looks like. It also asks the author to produce something new, which contradicts G-5 ("this feature changes what an author is told, never what the pipeline requires an author produces") and NG-3. Resolve the contradiction in one direction: either drop the positive conjunct and make AC-3.4 purely a preservation statement over the erratum mechanism, or define the emit-side grammar as a registered catalogue entry per C-9/DC-01 and amend G-5. | AC-3.4, G-5, NG-3, C-6 |
| F-04 | High | Local | **The report's enumerated contents contradict AC-2.3, so the two cannot both be satisfied.** AC-3.1 enumerates what the report carries per authoring dispatch — "the source document paths selected, in the order used, and the total bytes injected" — and AC-3.2 enumerates the unselected rows with a reason "drawn from a closed set (below the count threshold's cut, dropped for the total byte bound, excluded as the authored feature's own, unreadable, unparseable)". AC-2.3 separately requires that "the report states for each such document that it was bounded" — a per-**selected**-document fact. It fits neither enumeration: AC-3.1's selected rows have no per-document field for it, and AC-3.2's five-member closed reason set is about documents that were *not* selected and contains no bounding/truncation member. A completeness test over these contracts must be a set-equality check over the full enumeration (a silently deleted case is exactly what containment misses), and today set-equality against AC-3.1/AC-3.2 falsifies AC-2.3. Add the per-selected-document bounded flag to AC-3.1's enumeration and re-close both sets. | AC-2.3, AC-3.1, AC-3.2 |
