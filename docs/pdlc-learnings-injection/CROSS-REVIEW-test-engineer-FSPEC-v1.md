| F-01 | High | Cross-Feature | **The malformed-configuration branch is not decidable, so AT-32 cannot be written.** BR-14 and E-23 make "section present but malformed (`learningsInjectoin`)" a distinct behaviour from `enabled: false`, and AT-32 asserts a catalogued notice fires on it. But a misspelled *section name* is not a present section: it is an absent section plus a stray top-level key. The shipped precedent this feature must live beside proves the distinction is invisible without a new rule — `parseAdvisoryConfig` returns `degraded(false)` (no notice) when the section key is missing (`pdlc/workflows/orchestrate-dev.js:1985`), and only sets `sectionMalformed: true` when the key is present but not an object (`pdlc/workflows/orchestrate-dev.js:1988-1989`); `parseMergeConfig`'s operator string carries the same meaning verbatim (`pdlc/workflows/orchestrate-dev.js:1537`). As written, AT-32 can pass only by hard-coding the literal `learningsInjectoin`, which is an implementation echo, not an oracle. Fix: state the decidable predicate in BR-14 — either (a) malformed means *present but not an object / values of the wrong type*, and the typo case is deliberately indistinguishable (then AC-5.1b's example must change), or (b) an explicit unknown-top-level-key rule with a stated matching rule (exact set of recognised sections, and anything else notices), which AT-32 can then exercise with a key the fixture author chooses freely. | BR-14, E-23, AT-32, Step 0.3 |
| F-02 | High | Local | **BR-6's section catalogue is an enumerated closed contract with no completeness test and no negative-with-positive pair.** BR-6 fixes six rows — five injected in priority order, Approval Record `never` — and REQ O-4 is discharged on it, but no AT asserts set equality over that enumeration and no AT asserts Approval Record material is absent. Deleting the `never` row, or silently adding a seventh section (A-3 anticipates one), fails no test. AT-11 only checks that *present* sections appear in priority order. Fix: add an AT over a fixture document carrying all six sections whose oracle is (i) set equality between the section names appearing in the block and the five injected rows, **in BR-6's priority order**, and (ii) the Approval Record's distinctive fixture text is absent *while* the five injected sections' distinctive texts are present — the negative conjunct paired with a positive one on the same path (DC-01, DC-05). | BR-6, AT-11, AT-12, reverse trace AC-2.3 |
| F-03 | High | Local | **The byte-accounting basis is undefined, so AT-11/AT-12/AT-13/AT-17 are unwritable at byte precision.** BR-6 always injects "a one-line identification of the feature and its `Date Completed` value" first, BR-7 adds delimiters and a source-path label, and BR-8 records "bytes injected" per document plus a per-dispatch total. Nothing says whether the identification line, the delimiters, the source-path label or the section headings count toward `maxBytesPerDocument`, toward `maxTotalBytes`, or toward the recorded byte counts. A test writer given AT-11 ("the material taken does not exceed the bound") cannot compute the expected number, and two implementations differing by exactly the header bytes both pass. This is black-box observable — the block's bytes — so it belongs here, not in TSPEC. Fix: state one accounting rule in BR-6 and have BR-8's "bytes injected" name the same quantity, then let AT-11/AT-13 assert a literal expected byte count transcribed from the fixture rather than recomputed by the test. | BR-6, BR-7, BR-8, AT-11, AT-12, AT-13, AT-17 |

Fix: AT-02/AT-03 must state that the observed universe is **every agent invocation the run makes**, not every classified one, and that the block-carrying subset equals the authoring-classified subset over that universe. | BR-1, BR-11, AT-02, AT-03, A-2 |
| F-05 | Medium | Local | **AT-22 as written is not CI-executable and invites an implementation echo.** AC-6.1 requires every test to run in CI against fixtures; AT-22 says the selection is "reproduced by hand". If the reproduction calls the production selector the test is a tautology; if it reimplements it, the reimplementation is the thing under test. Fix: restate AT-22 as — given only the report's run-level record (ordering key value per document, three thresholds) and the fixture corpus bytes, an **independently transcribed literal expected selection** (paths in order, committed in the fixture) equals the recorded selection; plus the DC-01 set-equality test over the record's two members. | BR-10, AT-22 |

## Positive Observations

- **BR-4's measured basis is real and reproduces exactly.** At HEAD: `yumo-plugins` 9/9/9 (`docs/**/LEARNINGS-*.md`, excluding `docs/discarded/`), `regime-ledger` 80/78/78, total 89/87/87 — matching the table verbatim. The two documents named as carrying no `Date Completed` row genuinely carry none (`docs/completed/43-wheel-rationale-contract/LEARNINGS-wheel-rationale-contract.md`, `docs/completed/34-postgres-audit-repository/LEARNINGS-postgres-audit-repository.md`), and the free-text example `2026-06-09 (Phase H harvest; partial close-out)` occurs verbatim (`regime-ledger docs/completed/02-macro-prediction/LEARNINGS-macro-prediction.md:7`). Measuring before fixing the key, and then making the tiebreak load-bearing because 2 of 89 documents force it, is exactly the discipline that keeps AT-09/AT-10 honest.
- **The upstream correction in BR-4 is right, and correctly surfaced.** REQ AC-2.2 asks for both a path-byte tiebreak and directory-rename rank-invariance, which cannot both hold; replacing the rename property with "the ordering is a pure function of (key value, path)" is the stronger achievable invariant, and routing it as an ERRATUM rather than silently dropping it is the correct move.
- **Repo claims check out where they are made.** F-O-4's vendoring claim is accurate (`pdlc/engine/scripts/prepack.mjs:20`, `MODULE_NAMES = ["orchestrate-dev.js", "orchestrate-queue.js"]`); the authoring classification BR-1 consumes exists and does cover erratum dispatches (`pdlc/workflows/orchestrate-dev.js:12821`, `:12915`), which is what makes E-30 true rather than hopeful; A-1's config home exists (`.claude/pdlc.config.example.json`, `implementation.testCommand`).
- **The two closed catalogues, the empty-rows-vs-missing-field rule, and the `RSN-TRUNCATED` / bounded-flag distinction are specified precisely enough to test as written** (BR-3, BR-8, BR-9, AT-19/20/21/28) — these are the parts of the document a test engineer can implement today without asking a question.
- **AC-6.2's recorded pre-feature baseline, committed and never regenerated by the branch under test, is the right shape for a byte-identity oracle** and forecloses the usual self-blessing failure mode.

## Recommendation

**Needs revision**

Four High findings gate. Three of them are single-sentence additions to existing rules — the byte-accounting basis (F-03), the section-catalogue completeness pair (F-02) and the dispatch universe AT-02/AT-03 observe (F-04). The fourth (F-01) needs a decision rather than a sentence: either the operator-typo case is detectable under a stated unknown-key rule, or it is not detectable and AC-5.1b's example changes upstream. Everything else in the document is at the right altitude and, in Group 3 and Group 4 especially, unusually precise — the revision is narrow, not structural.
