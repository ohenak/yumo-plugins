| F-01 | High | Local | **`RSN-SELF` has no recording path, so AC-1.3 cannot be tested.** §D.6 decides self-exclusion in `gatherLearningsCorpus` "before any read", and §I.3's `CorpusEntry` typedef (`{path, feature, text, readOk}`) carries no self marker, while §I.4's shell returns only `{unlistable:false, entries}`. So a self document is either dropped by the shell — and then `selectLearnings`, which owns `rejected[]`, can never emit `RSN-SELF` — or passed through with `readOk:false`, which is `RSN-UNREADABLE`, not `RSN-SELF`. ## Positive Observations

- **The grounded-premises table survives independent verification, premise by premise.** I re-ran all twelve. `MODULE_NAMES = ["orchestrate-dev.js", "orchestrate-queue.js"]` is at `pdlc/engine/scripts/prepack.mjs:20` (P-1). The four `authoring` sites are real, and the fourth genuinely is the positional argument at `orchestrate-dev.js:7663` that a naive grep for `dispatchKind: "authoring"` misses (P-2) — finding it is the difference between a correct BR-1 universe and a silently incomplete one. `dispatchAndVerify` does receive `_git` and `_readFile` via `wrapperSeams` (`:12381-12394`, `:8862-8878`) and composes `prompt` at `:8978` (P-3). `LS_FILES_ARGV` is at `consolidate-learnings.js:1338-1346` and is module-private, exactly as §I.1 says (P-4). The corpus predicate run at HEAD yields **9** documents totalling **300,152** bytes, every one opening `# LEARNINGS — {feature}` and every one carrying a bare-ISO `Date Completed` — the byte total matches §A.4 to the digit (P-5, P-6). `ADVISORY_DEFAULTS.enabled` is `false` at `:1944` (P-11/ERR-1). This is the most reliably grounded TSPEC I have reviewed on this feature; the findings above are about test *design*, not about invented anchors.
- **ERR-1, ERR-2 and ERR-3 are all correct, and ERR-2 is a real testability catch.** The land-proof retry at `orchestrate-dev.js:12915` does carry `dispatchKind: "authoring"` and is a second block-carrying dispatch inside one erratum round; FSPEC E-30's singular phrasing does miss it, and AT-02's set equality would have been asserted over an incomplete universe. Raising it as an erratum rather than papering over it in §T.6 is the right call.
- **AT-33/AT-34 are paired on one instrument, deliberately (DC-03).** §T.6 states that both tests live in one file and share one call-log instrument, so the absence claim (AT-34) never stands alone. That is the exact anti-pattern the domain constraints were written for, and it was pre-empted rather than discovered in review. F-10 is about where the *expected* set comes from, not about the pairing.
- **The catalogues are frozen arrays with hand-transcribed expectations (DC-14).** §D.1's justification — arrays rather than enums specifically so a test can `toEqual` a literal without importing the module's own value as its expectation — names the oracle-echo hazard and designs it out. §D.2's four-row closure table then says which enumeration each set-equality test ranges over, including the deliberate exclusion of `phaseId`/`docType`/`mode` from BR-8's row closure.
- **§T.4 is exactly the right instinct.** Noticing that `RSN-COUNT` would be *named* by a completeness test and *exercised* by nothing under §4.1's defaults, and then naming `COUNT-BINDING` and its mirror `BYTES-BINDING` so each bound is asserted where it binds and asserted not to bind where the other does, is what turns a registered catalogue member into a tested one.
- **The layer table makes AC-6.1 structural.** Splitting every FSPEC rule into a pure function and leaving one twelve-line IO shell means Groups 2–4 need no harness and can make no model call by construction, rather than by a convention someone has to police.

## Recommendation

**Needs revision**

Six High findings. The architecture is sound and unusually well grounded — the placement argument (P-1), the single attachment point (P-2/P-3) and the reuse of consolidation's own pathspec (P-4) are all correct and correctly evidenced, and I would not ask for any of them to change. What needs another pass is the part of the document that has to be true for the tests to be writable:

1. **Give `RSN-SELF` a home in the data flow** (F-01) — one field on `CorpusEntry` or a second member on the shell's return.
2. **Decide what `maxBytesPerDocument` bounds** (F-02) and restate §D.5 against it, so the `ABRIDGED` marker is not inside its own budget.
3. **State the multi-dispatch rule for the run-level record** (F-03) and fixture a run whose two dispatches observe different corpus states.
4. **Make §T.3 executable** (F-04): the concrete merge-base capture procedure, and what a legitimate re-capture looks like.
5. **Move the baseline's falsifying anchor out of the capture script's own output** (F-05).
6. **Give AT-29 something that can red it** (F-06), or say plainly that BR-11's isolation is structural and name the structural argument instead of a test.

The Medium findings (F-07 … F-12, F-16) are all mechanical: one signature to reconcile, one return type to widen, one over-claim about the coverage gate to soften, one expected-value source to move off the implementation, three property strategies to route, one AT map to enumerate, and one test-double source to disambiguate. None of them needs a design change.
