| F-01 | Medium | Local | **DEC-LI-09's new absence conjunct has no positive control, so it can go vacuous exactly when it matters.** Conjunct 2 asserts that `orchestrate-dev.js` at the recorded sha "contains no `selectLearnings`, `gatherLearningsCorpus` or `LEARNINGS_CORPUS_ARGV`". A grep for a symbol that does not exist under *any* name — because implementation renamed it, or the transcription carries a typo — is absent at the baseline sha **and** absent at HEAD, and the conjunct passes for the wrong reason. The entry calls conjunct 2 "the load-bearing one", which makes its silent degradation the whole guard's failure mode: conjunct 1 admits any ancestor, so the pair collapses back to the vacuity v1 F-02 asked to close. Fix: hand-transcribe the symbol list **once** and assert it in both directions — present in `pdlc/workflows/orchestrate-dev.js` at HEAD, absent at the recorded sha. The HEAD half is the positive control that makes the absence half falsifiable, and it costs one extra assertion over a list the guard already carries. | DEC-LI-09 §Decision, conjunct 2; `D-O-2` |
| F-02 | Medium | Local | **DEC-LI-05's *Mechanically detected* trigger names an oracle that is green in precisely the case it claims to catch.** The trigger reads: a refactor that stops building `prompt` by concatenation "reds AC-4.1/AC-5.1a's byte-identity oracle, since the empty-block identity holds by construction only under concatenation". But those ACs assert byte-identity for the **empty-block** case, and inserting an empty string mid-prompt is byte-identical to appending it — the oracle passes under a suffix→insertion move, which is exactly the move that forfeits the structural guarantee this entry buys. The oracle cannot see the change it is credited with detecting, so the label is wrong in the same way v1 F-06 asked the labels to be right. Fix: either relabel this trigger *Review-time judgement*, or give it a real mechanism — a positive suffix oracle over a **non-empty** block asserting `composed.endsWith(block)` and `composed === prompt + block`, which reds on any insertion refactor and is one assertion in a test the design already needs. The same question applies more weakly to DEC-LI-07's *Mechanically detected* trigger, which says a `BR-14` change "reds the transcription": prose in this document is not under test, so the claim holds only if the five-state table is transcribed into the implementation's configuration cases — worth naming the test that carries it rather than the table. | DEC-LI-05 §Re-evaluation triggers; DEC-LI-07 §Re-evaluation triggers |
| F-03 | Low | Local | **`D-O-6`'s call-count oracle does not state its filter, and unfiltered counters cannot hold.** "`_git` enumeration calls **equal** the number of injecting dispatches" is only true of calls whose argv is the corpus enumeration; a pipeline run drives `_git` for commits, branch checks and land proofs many times over, and `_readFile` for every document the run touches. ## Positive Observations

- **The `_git` correction was made properly rather than minimally.** The easy repair was to soften the Constraints row; instead DEC-LI-02 names both channel implementations, contrasts `rtGit` with the four siblings that do wrap their `await`, disposes of the misleading docblock by explaining what it is actually describing, and then follows the correction downstream into DEC-LI-04's failure handling and into a new test-double obligation. That is the full chain from a false premise to the test that would have caught it. Every part of it re-derives at HEAD.
- **`D-O-6` states the reason the count conjunct cannot be dropped.** "The behavioural case alone is satisfiable by a memo keyed on something that happens to change" is the sentence that stops a future implementer from deleting the awkward half of the oracle. Obligations that carry their own defence survive contact with the next reviewer; ones that carry only an instruction do not.
- **The three added trigger proxies are numbers, not adjectives.** Corpus count ~30 against the **9** the frozen argv returns at HEAD (re-run: `git ls-files --cached --others --exclude-standard -- ':(glob)docs/*/LEARNINGS-*.md' ':(glob)docs/completed/*/LEARNINGS-*.md'` → 9), ~15 catalogue members, and 2 MiB against `RT_READ_CACHE_MAX_BYTES = 2097152` (`runtime-adapter.js:124`). A judgement trigger with a measurable prompt is a different object from one without, and the document now distinguishes them consistently.
- **The DC-18 → `DEC-LAYER-01` citation repair is in the right direction, and the characterisation of DC-18 is accurate** — it is an oracle-surface rule about glob-ranged guards (`DOMAIN-CONSTRAINTS.md:506`) and says nothing about who owns tunable numbers. Note for the author, not a finding: `DEC-LAYER-01` (`docs/_decisions/DECISIONS-spec-layer-boundary.md`) exists and is a layer-boundary decision, but its enumerated classes are tie-breaks, reader indices, seam verb sets and fixture construction — it moves decisions **down** from FSPEC to TSPEC/PROPERTIES and does not itself say REQ owns threshold values. The substantive claim is true and provable from REQ §4.1 directly; only the authority is a loose fit.
- **The new DEC-LI-04 alternative is grounded rather than asserted.** "The role prompts already instruct every author to read `docs/_constraints/DOMAIN-CONSTRAINTS.md` and `docs/_decisions/`" holds: `pm-author`, `se-author` and `te-author` SKILL.md all carry those references, so G-6's second clause really is discharged elsewhere and widening the argv really would double-deliver. Recording a rejected alternative *because a future reader will think of it* is the use of an Alternatives section that pays for itself.
