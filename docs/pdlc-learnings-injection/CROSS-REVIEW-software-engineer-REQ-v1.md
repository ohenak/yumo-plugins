## Findings

| ID | Severity | Scope | Finding | Section ref |
|----|----------|-------|---------|------------|
| F-01 | High | Local | **"Exactly six authoring dispatches" does not match the dispatch model at HEAD.** `PHASE_DISPATCH` (`pdlc/workflows/orchestrate-dev.js:3625-3735`) gives every phase two author-side slots, a `creator` and an `optimizer`, not one dispatch per document. Three consequences make AC-1.1/AC-1.2 unsatisfiable as written: (a) Phase R has `creator: null` (`orchestrate-dev.js:3629`, and the comment at `:10350` — "Phase R's REQ arrives already authored and `pm-author` is its only writer"), so a REQ approved in round 1 produces **zero** REQ authoring dispatches, and AC-1.1's "each of the six carries material" is false with no defect present; (b) Phase D is conditional — `DECISIONS_WARRANTED` (`orchestrate-dev.js:5204-5239`, default `true` on a malformed trailer) can skip DECISIONS entirely, so the count is five or six, never fixed; (c) optimizer dispatches recur **once per revision round**, so a run makes many more than six author-side dispatches. Restate C-1 over `(phase, slot)` pairs — creator and optimizer of R/F/T/D/P/PR — and state whether re-injection happens on every round or once per phase (the byte cost of §4.1 multiplies by rounds, not by phases). | C-1, AC-1.1, AC-1.2 |
| F-02 | High | Cross-Feature | **Corpus enumeration is reinvention of a shipped mechanism, and the seam the REQ implies cannot do the job.** `defaultListFiles` (`orchestrate-dev.js:11586-11603`) is non-recursive and *filters directories out* of its result, so it cannot discover `docs/{p}/` or `docs/completed/{p}/` at all. The sibling feature already ships the enumerator for exactly this corpus: `enumerateCorpus(_git)` in `pdlc/workflows/consolidate-learnings.js:1339-1352`, `git ls-files --cached --others --exclude-standard` over `:(glob)docs/*/LEARNINGS-*.md` and `:(glob)docs/completed/*/LEARNINGS-*.md`, with an `{unlistable, detail}` degrade path that is exactly C-7's fail-open shape. `docs/completed/pdlc-consolidation-agent/DECISIONS-pdlc-consolidation-agent.md:527` names "`_listFiles` gaining directory enumeration" as the trigger that would retire that choice — i.e. HEAD has not gained it. §1.2 records neither fact, and G-6/§1.3 claim composition with consolidation while omitting the one component that is literally reusable. Record the precedent in §1.2 and state that corpus membership is that same enumeration. | §1.2, C-3, G-6 |
| F-03 | High | Local | **C-5's "makes no model call" is false on one of the two live channels.** Under the Claude Code runtime adapter, listing and reading files *are* model dispatches: `rtListFiles` calls `RT.agent(...)` with `RT_IO_MODEL` (`pdlc/workflows/runtime-adapter.js:963-991`) and is wired as `_listFiles` at `:1161`, with `_readFile: rtReadFile` at `:1152`/`:1197`; an unrecognised reply degrades to `unreadable`. Under the engine the plain-Node defaults are left in place (`pdlc/engine/lib/run.mjs:16-21`), where C-5 holds. So C-5 and AC-2.5 (byte-identical across two runs) are true only of the engine channel. Either scope C-5/AC-2.5 to the engine channel explicitly, or restate C-5 as "no model *judgement*" and add the corpus state C-7 currently lacks: a listing reply that fails the sentinel grammar (`unreadable`) must resolve to "inject nothing, record why", not to an empty corpus. | C-5, C-7, AC-2.5 |
| F-04 | High | Cross-Feature | **Malformed configuration is required to be silent, which violates DC-01's receive side.** AC-5.1 folds three preconditions into one criterion — `enabled: false`, section absent, section malformed — and requires for all three that "the run report carries no injection summary at all — key absent, not present-and-empty". `docs/_constraints/DOMAIN-CONSTRAINTS.md:31-33` (DC-01) requires that the REQ state behaviour for absent, malformed and truncated input "with an exact fallback **and an observable log signal**". As written, an operator who typos `learningsInjectoin` gets a run byte-identical to a deliberate disable, with nothing in the report to distinguish them. Split AC-5.1: malformed/unparseable config keeps the disabled *behaviour* but must emit a catalogued notice (C-9) and appear in the report. | AC-5.1, C-9, DC-01 |
| F-05 | Medium | Cross-Feature | **Corpus membership for untracked and gitignored LEARNINGS files is left open, and a sibling DECISIONS explicitly asks this REQ to close it.** C-3 defines the corpus by directory only. The shipped enumerator's `--exclude-standard` means a gitignored LEARNINGS file is *not* corpus, and `docs/completed/pdlc-consolidation-agent/DECISIONS-pdlc-consolidation-agent.md:512-521` names "REQ/FSPEC answering the ignored-file question" as its re-evaluation trigger, measuring at HEAD that the `:(glob)` pathspecs, not the flag, are what exclude `docs/discarded/`. A REQ that reads the same corpus and does not answer the question leaves two consumers free to diverge. State it: tracked-or-untracked, ignored-or-not. | C-3, AC-2.6 |
| F-06 | Medium | Local | **§1.2 claim 1 overstates today's readership.** "LEARNINGS is written and read only by humans and consolidation" is not what HEAD does: `orchestrate-dev.js:8761-8778` reads `docs/{feature}/LEARNINGS-{feature}.md` as the tier-2 approval-record source, and `:6300-6318` scores it against `LEARNINGS_SECTIONS` for structural completeness. The *narrower* claim the REQ needs — no dispatch composed for an authoring role references a **different** feature's LEARNINGS — is verified true (only own-feature paths appear at those sites). Narrow the sentence, and note the tier-2 reader as an existing consumer C-2's self-exclusion must not disturb. | §1.2 item 1, C-2 |
| F-07 | Medium | Local | **AC-5.1's "byte-identical to the pre-feature baseline" is not measurable.** Nothing at HEAD captures a composed dispatch as a stored artifact, so "the pre-feature baseline" names a value no test can obtain once the feature lands. AC-1.2 already states the same property in the form that *is* measurable — "byte-identical to the same run with injection disabled" — which is a differential within one commit. Restate AC-5.1 in AC-1.2's form. | AC-5.1 |
| F-08 | Medium | Local | **AC-2.2's ordering key is unparseable at HEAD and the total order has no stated tiebreak.** The metadata row exists — `\| Date Completed \| {date} \|` (`pdlc/skills/harvest-learnings/SKILL.md:74`) — but the value is free text and the completeness criterion checks the table's presence, not the row's parseability (`orchestrate-dev.js:6046-6065`, `:6300-6318`), so unparseable dates and ties are the common case, not the exception. O-2 acknowledges the measurement is owed, but AC-2.2 is stated as if recency were reliably available. Require a byte-order-over-path final tiebreak so the ordering is total by construction; the corpus-side precedent is `byteCompare` in `consolidate-learnings.js:1637`/`:1648`. | AC-2.2, O-2 |
| F-09 | Medium | Local | **AC-5.2 is an absence-only oracle.** "No file written anywhere" passes vacuously on a run where injection never activated — which is precisely the state AC-5.1 describes, so the two criteria are satisfiable by the same inert run. Pair it with a positive assertion on the same path: the run read *these* corpus files (AC-3.1's report rows are the natural witness) and wrote none. The sibling suite already states this discipline explicitly — `pdlc/workflows/__tests__/consolidationPredicate.test.js:46` ("positive membership, not an absence-only claim"). | AC-5.2 |
| F-10 | Medium | Local | **AC-3.2's reason set is prose, not a closed enumeration with ids.** Five reasons are listed inline ("below the count threshold's cut, dropped by the total byte bound, excluded as the authored feature's own, unreadable, unparseable"). C-9 invokes DC-01, which requires a closed catalogue on the emit side; a prose list cannot carry a set-equality assertion, and a deleted case cannot be caught. Lift the reasons into a table with stable ids in §4 or §5 so the owning test asserts set-equality over the full enumeration. | AC-3.2, C-9 |
