| F-01 | High | Cross-Feature | **Generalising the ❌ text removed the only discriminator its recovery act 1 depends on, and on the Iterations-write source act 1 now instructs the operator to delete a *legitimate* `HALT-REASON:` line — reaching the terminal `A > H` state the v2 fix was written to prevent.** Before v3.0 the ❌ text named the failed write (*answering line unconfirmed*), so act 1's *"delete the region's trailing unconfirmed region line"* had a decidable subject. v3.0 collapses three sources into one text — `Refused — region line unconfirmed at {path}` — and widens act 1 to *"the answering line, **or the halt's `HALT-REASON:`** — if one is present"*. Take the **failed Iterations write**, which AC-1.4's ordering makes the **first** clause to run (3 → 1 → 2): clause 1 never runs, so **no region line was attempted**, yet the operator reads a refusal naming a *region line* and a repair telling them to delete the trailing one. On a re-halt the trailing region line is the **previous** halt's confirmed `HALT-REASON:`. Nothing in the file marks a line confirmed or unconfirmed — *present* and *unconfirmed* are different predicates and only the first is observable — so an operator following the recovery as written deletes a real halt's line: `H` drops by one against an unmoved `A`, giving `A > H` permanently (each later halt and clearance increments both together), so AC-1.5(4)'s `A < H` gate **never grants a window again**.
