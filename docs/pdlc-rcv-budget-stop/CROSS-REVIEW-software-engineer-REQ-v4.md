## 3. Findings

Scanned the changed sections only. **One High**, and it is on the one clause this revision changed
without my having asked for that particular value: `postmortemStatus`. v1.3 said *"`resolved` — or
unset"*; my v3 F-04 line closed that as fine. v1.4 replaced it with a hard pin to `none` and cited
the shipped code for it — and the cited code does not produce `none` on this path.

| ID | Severity | Scope | Finding | Section ref |

| F-01 | **High** | Cross-Feature | **`postmortemStatus` is pinned to `none` on the step-4 refusal, and the shipped disposition logic returns `written` there — the citation names a default the halt path never uses.** AC-1.5(4) now states: *"`postmortemStatus` reads **`none`** — the shipped default `buildFinalReport` always emits (`orchestrate-dev.js:5035`, `:5054`), no post-mortem being written this run and `gatePostmortem` unset"*, §6's *Refusal phase-row text* row repeats *"`postmortemStatus` is `none` here"*, and O-10 hardens it into an oracle: *"`postmortemStatus` asserted **equal to `none`** with step G's `unresolved` as its negative control."* I traced the value at HEAD. `:5035`/`:5054` are `buildFinalReport`'s **default parameter** and its pass-through — they are only reached when the caller omits the field, and **the halt path never omits it**: the catch block computes it at `orchestrate-dev.js:4875`–`:4901` and passes it explicitly. That computation is a three-branch chain: (1) `if (gatePostmortem)` ⇒ `"unresolved"` — correctly excluded, the REQ says step 4 does not set it; (2) `else if (err && err.postmortemStatus)` ⇒ whatever the thrower named — the REQ says nothing about this seam; (3) `else if (haltPhase)` ⇒ probe `docs/${featureName}/POSTMORTEM-${haltPhase}-${featureName}.md` via `checkFileFn`, and **`if (confirmation.ok) postmortemStatus = "written"`**. On a step-4 refusal branch (3) is the one that runs — `haltPhase` is non-null because the REQ requires *"a ❌ phase row is recorded"* and `haltPhase` is read off the last ❌ row (`:4870`–`:4871`) — and the probed file **exists by construction**: the whole premise of the refusal is a post-mortem the operator resolved, carrying a corrupt reset region. So the shipped code yields **`written`**, not `none`, and O-10's leg fails against a faithful implementation of every other clause in the REQ. The shipped comment at `:4877`–`:4879` says exactly why this is not a code defect to be fixed silently: *"a step-G refusal names an EXISTING, unresolved POSTMORTEM. The existence check below would call the same artifact `"written"` — the refusal's whole point is that it was not written by this run"* — step G solved it by setting `gatePostmortem`, which is the branch this REQ forbids itself. The step-4 refusal therefore has **no honest value in the shipped four-member enum**: `none` is false (a post-mortem exists), `written` is misleading (not written this run), `unresolved` is false (the operator resolved it) — and the REQ closes the door on the fourth option by adding *"no value outside the shipped enum `none | unresolved | written | write_failed`."* This is the third round in a row that a value has been pinned against a **cited** authority that does not say what the citation claims (v2 F-02: a rule the table broke; v3 F-01: a catalogue row that said the opposite). **Resolve by stating the mechanism, not only the value.** The clean route already exists in the shipped chain: branch (2), `err.postmortemStatus`, lets the thrower name its own disposition, exactly as `checkConverged` already does per the comment at `:4884`–`:4887` — so the REQ can say *"the refusal throws with an explicit `postmortemStatus`, which is `X`, reaching branch 2 of `orchestrate-dev.js:4883` and never the existence probe at `:4890`"*. Whichever value `X` is, it must be justified against a code path that produces it, it must be stated for **both** row-B variants (the unconfirmable-append variant has the same ❌ row, the same non-null `haltPhase` and the same existing file, and §6 states nothing about its `postmortemStatus`), and §6's row plus O-10's negative-control leg must move with it. If the honest answer is that no shipped enum member fits, that is a finding against the enum and belongs in the REQ as a stated extension — not papered over with the member whose emitted side effect (F-02) says the opposite of the truth. | AC-1.5(4) *"a refusal is not a halt"*, fourth bullet; §6 *Refusal phase-row text*; O-10; `orchestrate-dev.js:4875`–`:4901`, `:5035`, `:5054` |
| F-02 | Medium | Local | **Pinning `postmortemStatus` to `none` makes the shipped halt path emit "No POSTMORTEM was written." on a refusal whose sole cause is a post-mortem that exists — an operator-visible string §6 does not account for.** `orchestrate-dev.js:4922`–`:4923` reads `if (postmortemStatus === "none") { emit("No POSTMORTEM was written."); }`. That emit is **coupled to the very value AC-1.5(4) pins**, and it fires on the same path, in the same report, immediately above the ❌ text this REQ mints. The operator would read `Refused — reset region corrupt at docs/f/POSTMORTEM-R-f.md (invalid-window-start …)` followed by *"No POSTMORTEM was written."*, then be told by the recovery text to hand-repair a line **in that file**. The REQ has been careful about precisely this class of contradiction — *"the operator-facing text is **this refusal's own**, not step G's, which would state the opposite of the truth"* — and then reintroduces it through a field's side effect rather than through a string it names. §6's claim that *"§6's **three** refusal-render rows are the closed list of strings this REQ mints"* stays literally true (this string is shipped, not minted) while the operator sees a fourth line on the refusal that no row governs. Required, and it falls out of F-01's fix: either choose a `postmortemStatus` that does not trigger `:4922`, or state that this emit is suppressed on the step-4 refusal path and give O-10 a leg asserting its **absence** — as a negative control, in the same shape as step G's two strings already have. Whichever way, the coupling must be stated, because an implementer reading only §6 will not discover it. | AC-1.5(4) fourth bullet; §6 preamble and *Refusal phase-row text*; O-10; `orchestrate-dev.js:4922`–`:4923` |
