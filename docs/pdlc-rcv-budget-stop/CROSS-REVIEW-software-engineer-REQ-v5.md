| F-01 | **High** | Cross-Feature | **The pinned queue-reset string is emitted *unconditionally* by the halt catch, so §6's "Replaces the shipped generic … on this path only" describes a substitution the shipped code has no seam for, and O-10 asserts as a negative control a string that a faithful implementation always prints.** v1.5 did the right thing by pinning the bytes and citing the site: *"`Recover: set the {feature} row in docs/_queue/QUEUE.md back to pending, then re-run the queue.` (`orchestrate-dev.js:4928` — not `:1795`'s different recovery string)"*. Both halves check out at HEAD — `:4928` is the template literal, `:1795` is `checkConverged`'s different `Recover: resolve it per AC-2.4, …`. What the citation does not carry is the **control flow one line above it**. `:4922`–`:4924` is `if (postmortemStatus === "none") { emit("No POSTMORTEM was written."); }` — guarded, which is exactly why v4's F-03 was closable by choosing `written`. `:4927`–`:4929` is **not guarded by anything**: it is a bare `emit(...)` in the catch, after the queue-row write, on **every** halt class, with the shipped comment at `:4925`–`:4926` stating the intent — *"exactly ONE recovery act is offered. A direct re-invocation is deliberately not offered — the queue row is the single entry point."* The step-4 corrupt-region refusal is step-G-shaped and therefore reaches this catch (the REQ requires that, O-6), so it reaches `:4928` too. Three consequences the document must resolve, not one. **(a)** §6's *Refusal recovery text* row says *"Replaces the shipped generic (AC-1.5(4)'s pinned bytes) on this path only"*, and AC-1.5(4) says the halt reason names the sanctioned repair *"instead of the shipped generic (pinned above), which on this path reproduces the refusal on every iteration"*. **Instead of** is a substitution, and there is nothing to substitute at: `haltReason` (`err.message`, `:4862`) and this `emit` are **different channels**. Writing the repair into `haltReason` does not remove the generic line; the operator gets both, and the last line they read is the one the REQ says reproduces the refusal every iteration — the precise operator harm AC-1.5(4) invokes to justify minting its own string. **(b)** O-10 asserts *"step G's shipped strings (`Refused — unresolved POSTMORTEM at …` and the pinned queue-reset string) as **negative controls** *for that entry class*"* — i.e. the pinned string asserted **absent** on the corrupt-region refusal. Against shipped code it is present, so that leg fails against a faithful implementation of every other clause, which is the same failure mode v4's F-01 filed one round ago about `none`. **(c)** The queue-reset string is **not step G's**: `:4928` fires on every halt class — convergence, DoD, PUB, entry-validation — so calling it *"step G's shipped strings"* mis-describes it and hides (a) from a reader checking only step G. **Resolve by stating the mechanism, as F-01 of v4 was resolved.** The honest options are two, and the REQ must pick one and say so: (i) the emit at `:4928` becomes **conditional** on this refusal — a stated change to shipped behaviour, in AC-1.5(4) and in an O-* obligation, with O-10's negative control then correct as written; or (ii) the generic is **not** suppressed and the refusal's repair text is *additional* — in which case §6's *"Replaces"* and AC-1.5(4)'s *"instead of"* both become *"in addition to"*, O-10 drops the pinned string from its negative controls and instead asserts the **order and both lines**, and AC-1.5(4) must say why an operator told *"re-run the queue"* under a refusal that re-fires on every re-run is acceptable. (i) is what the document plainly intends; it is (ii) that the shipped code currently gives you for free. Whichever is chosen, the unconfirmable-append variant must be re-stated in the same breath: it *wants* `:4928`'s line, so a conditional suppression must be scoped to the corrupt-region variant alone, and §6's *Unconfirmed-append text* row — *"whose recovery text is the **shipped generic** queue-reset string, in AC-1.5(4)'s pinned bytes"* — is only free of charge under (ii). | AC-1.5(4) *"a refusal is not a halt"*, third bullet; §6 *Refusal recovery text* and *Unconfirmed-append text*; O-10; `orchestrate-dev.js:4922`–`:4929`, `:1795` |

The second half does not hold, because of what the same criterion pins **for this entry class** twenty lines above: the unconfirmable-append variant's ❌ text is `Refused — answering line unconfirmed at {path}` and its recovery text is the generic *"set the `{feature}` row … back to pending, then re-run the queue"*, justified in terms that are false for this sub-case — *"the fault is transient, **nothing is hand-repairable**"*.
