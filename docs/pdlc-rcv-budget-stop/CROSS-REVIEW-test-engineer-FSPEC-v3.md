| F-10 | Medium | Local | **AT-REG-06 asserts whole-file byte-equality, but clause 3 attempts a write before the confirmation it is said to fail — so the conjunct can red on a correct implementation.** The row's `Then` says *"the post-mortem's bytes are **unchanged**"*, and names that conjunct load-bearing (*"the dispatch-count and byte-equality conjuncts are the ones that fail if the entry re-authors"*). But the flow's own statements are narrower and, read together, do not support it. §7.3 orders the clauses **3 → 1 → 2** and confirms clause 3 by an **equality read-back** — i.e. clause 3 **writes first, then reads back**. §8.1 **B-HALT-3** says that when no `Iterations` heading is found *"the loop inserts one rather than failing"*, at end of file when there is no `## Reset Region`. On an unreadable post-mortem no heading can be located, so the specified behaviour is: insert the render, read back, fail, refuse (B-HALT-4). Whether the file's bytes then differ depends entirely on what *unreadable* means in the fixture — a file that is undecodable (invalid UTF-8) is perfectly **writable**, and the insert lands; a file that is permission-denied for both read and write does not, and the bytes are unchanged. **No `Given` pins which.** Note the FSPEC never claims the stronger form itself: §7.2 and §7.3 and E-8 all say *"the **region** is byte-unchanged"* — true either way, since clause 3 writes outside the region span. Only AT-REG-06 escalates it to the file. This is the F-09 defect class one more time: a test author who hits the red will weaken the conjunct, and the weakened form no longer falsifies a re-author. **Fix (either is fine, the first is stronger):** (a) state in §7.2 that when the file cannot be **read**, clause 3 attempts **no write** and the entry refuses immediately — then whole-file byte-equality is a total, deterministic oracle and the fail-closed claim is genuinely total; or (b) scope AT-REG-06's conjunct to what §7.3 guarantees — the region span, the `## Recommendation`, and every pre-existing section byte-unchanged — and let the dispatch-count conjunct carry the no-re-author discrimination | §11.3 AT-REG-06; §7.2 (¶ *"such a halt records nothing"*); §7.3 order/confirmation table; §8.1 B-HALT-3 |

The clause selects the first for every granting row, and AT-CLR-04's entry 1 does dispatch (`W = 1`, highest existing 1, so rounds 2…3). So entry 1 converges — good, that is what stops the append-and-strip that made *"nothing appended on either entry"* false at v2. Under the other outcome it is entry 1 that appends. Either way one of the row's conjuncts is false, which is exactly what v2 F-09 was raised to stop. This is a residue of F-09's fix, not a re-litigation of it — the clause is right and I would keep it. **Fix, and it is constructible:** name entry 2's precondition in the row — a **`forcePhases` re-entry after entry 1's convergence**. I checked the arithmetic: entry 1 approves at round 2, so highest existing becomes 2, `D = 3 ≤ E = 3`, the gate still observes `A = H = 1`, nothing is granted, `W` is unchanged, and entry 2 still has a round to dispatch. Every conjunct the row exists for survives, and the state is reachable rather than constructed | §11.4 AT-CLR-04 and the convergence clause; §6.1 B-CLR-4 |

## Positive Observations

- **F-09 was answered where it mattered, and answered as an outcome.** §11.4's clause fixes the *dispatch outcome*, explicitly not the fixture (*"which verdict sequence produces convergence is PROPERTIES' (O-10)"*), which is the right altitude and the right half of the split. It also writes down the failure mode it exists to prevent, so the clause survives an editor who does not have this review. AT-CLR-02a — F-02's entire fix, and the row I said I would hold a round for — is now a writable, discriminating oracle. That is the round's main result and I want it recorded as one.
- **F-08's fix generalised the relation rather than patching the awkward member.** Replacing *same counts* with an enumerated gate-relevant relation, plus the worked pair (`H = 3, A = 1` ~ `H = 2, A = 1`) and the stated reason same-counts fails, means the family can grow at target state without the pairing rule being renegotiated. F-13 is a field missing from that enumeration, not a fault in the idea.
- **§7.2's discriminator is stated in the safe direction and says which way it is safe.** *"When the discriminator cannot be evaluated, the halt takes the *existing* path"*, with the asymmetry argued (*a false creating reading is unrecoverable; a false existing reading costs one refused entry*). That is a rule a test author can apply to a case nobody enumerated, which is what a fail-closed rule is for. Choosing **file presence** over the region read or the shipped status is also the only one of the three that is decidable when the file cannot be read.
- **E-14b and §7.3 disposition the clause-3 creating-halt cost instead of leaving it implied**, and name the surprising part (*a fully authored post-mortem with no `## Reset Region` and `H = 0` — a file that reads like a recorded halt but records none*). Naming the misleading artifact is what lets an operator recognise it; the two-clearance cost is then arguable rather than mysterious.
- **AT-REG-06 was promoted from a read-only assertion to a whole-entry one.** *"The phase is entered **and run to its end** — the row asserts the whole entry, not the read alone"* is the correct shape: the v1.1 row could pass on an implementation that read correctly and then quietly re-authored. F-10 is about one conjunct's scope, not about the promotion, which is right.
- **AT-CLR-04's Given is now labelled a constructed state with the reachability argument attached** (`WINDOW-START: 1` needs `D ≥ 4`; `WINDOW-RESUMED: 1` is B-CLR-2, unreachable at this ship) and justified against E-13. Saying *"this row is evidence about the gate, not about production reachability"* is a better answer than inventing a reachable fixture that tests something else.
- **I re-derived every arithmetic claim in the changed rows again**: AT-REG-06 (`W = 1`, highest 3 ⇒ `S = 4 > E = 3`, a halt is reached — correct), AT-REG-07's worked pair, AT-CLR-04's window (`D = 2 ≤ E = 3`), the F-11 fix I propose (`D = 3 ≤ E = 3` after entry 1 converges at round 2), and §6.1's `S`-vs-`D` restatement (`W ≤ D` holds on B-CLR-2 because a `no-revision:` halt requires a round to have run). Nothing in the changed sections is arithmetically wrong. §13.1 was updated for AT-REG-06's new branches with no orphans.
