| F-01 | High | Local | **The new start-below-`W` leg's control asserts the wrong outcome — it is off by one against AC-1.5(1)'s own arithmetic.** O-10 leg (4) reads: "`W = 4` with every cross-review file removed ⇒ the entry starts at **4**, dispatches, overwrites nothing; control, `highest + 1 = 6` at `W = 4`, **halts on the budget path**." At `W = 4` the window is `{4, 5, 6}` (clause 1: end = `W + 2`). `highest + 1 = 6` means highest existing round **5**, so the derived start is 6 — the **last admitted round of the window**, which by clause 1's own worked example ("with `W = 1`, a branch whose highest existing round is 2 is admitted round 3 only") **dispatches**. The budget halt needs `highest + 1 = 7`. As written the pair has no discriminator: both legs dispatch, so the leg that exists to prove the origin does not widen the window proves nothing, and an implementer who trusts the control encodes `end = W + 1`. Under the alternative reading — that "highest + 1" names the highest round rather than the start — the leg is ambiguous and still unwritable without asking. This is the leg added to close v1's F-02, i.e. the one carrying that finding's whole remedy. | §8 O-10 leg (4); AC-1.5(1)–(2) |
| F-02 | High | Local | **AC-1.3 and AC-1.4 give opposite answers for the Iterations section on the commonest new case, and O-10's equality leg is unwritable as a result.** AC-1.3: when the loop halts on the budget, the Iterations section reports the effective budget *and* "the rounds **this entry** ran — `0` there — so the two are never conflated where the operator reads them". AC-1.4's no-re-author clause: a halt finding an existing post-mortem "**changes nothing else in the file** — no authoring dispatch, every other section … byte-unchanged", and O-14 draws the consequence explicitly: "this REQ requires only that everything outside the reset region is byte-unchanged, which fixes that file's Iterations section as **left as the prior halt wrote it**". A zero-round budget halt on a document whose post-mortem already exists is reachable and is **exactly the case AC-1.4 calls the commonest new one** (entry admitted no rounds with `A = H` and a resolved post-mortem). On it, the operator reads the *previous* halt's `rounds run {k}` — the conflation AC-1.3 exists to prevent — while O-10 owes "an equality on §6's declared render … `rounds run 0` on the zero-round halt". A test author cannot write that equality: on the re-halt fixture the section is required by one clause to read `0` and by another to be byte-identical to a section that reads `k > 0`. O-14 offers "unless FSPEC states otherwise and amends the clause", which defers the **decision**, not an oracle — an AC may not be undecidable pending FSPEC. | AC-1.3; AC-1.4 (no-re-author); §8 O-10, O-14 |
| F-03 | Medium | Local | **The re-halt byte-comparison oracle is unsatisfiable on every reachable fixture, because the strip it must tolerate lands outside the span it excises.** O-10's re-halt leg: "leaves every byte outside the region unchanged — **a byte comparison with the region span excised** plus the dispatch count". But AC-1.4 clause 2 strips **every unfenced `RESOLVED:` line, wherever it sits** — and those lines are not region lines ("a `RESOLVED:` line is *never* a region line … they quantify over disjoint sets"). A re-halt is reachable only through a post-mortem the operator resolved (an unresolved one refuses the phase, M-7a), so **every** re-halt fixture carries an unfenced `RESOLVED: yes` outside the region, which the halt removes. The declared comparison therefore fails deterministically on the fixture it is declared over. The predictable repair under time pressure is to loosen it to a substring or section check — losing the assertion, which O-10 itself lists as load-bearing under DC-03. State the excision as *"the region span **and clause 2's stripped lines** excised"*, or state the oracle as byte-equality against the file with clauses 1 and 2's edits applied. | §8 O-10 (re-halt leg); AC-1.4 clause 2 |
| F-04 | Medium | Local | **AC-1.2's repo-wide quantification and O-13(b) contradict each other, so the criterion's observable — a repo-wide grep — has no decidable pass condition.** AC-1.2: "afterwards there is **no second place where the budget's value is written down**, in production **or in test code**, and a test needing the budget obtains it from the one declaration." O-13(b) requires enumerating every assertion encoding today's width "**including an acceptance-test *title* naming the width**", stating for each whether it is re-expressed over the constant "or is a **genuine width-5 expectation that changes value**" — i.e. some test-code sites keep a written-down literal, now `3`. Both cannot hold. The consequence is testability, not style: AC-1.2's only stated observable is the absence of a second written-down value, and a reviewer or a CI grep cannot decide whether a title reading *"halts after three rounds"*, or a genuine width expectation, is a violation or the sanctioned outcome. Either scope AC-1.2's quantification (e.g. to values the pipeline or a test **reads as the budget**, excluding prose and deliberately-pinned expectations) or have O-13(b) require every enumerated site re-expressed over the constant with no exception. | AC-1.2; §8 O-13(b) |
| F-05 | Low | Local | **One property bound is undefined on a legal draw.** O-10's property obligation asserts "`W` **never exceeds the greatest well-formed `WINDOW-START:` present**" over generated line sequences — but the generator's domain plainly includes sequences with **no** well-formed `WINDOW-START:` at all (leg 3's shape, and every region of only `HALT-REASON:`/`WINDOW-RESUMED:` lines), where the bound is a max over the empty set and `W` is `1` by §4.1. State the bound as *"…or `1` when none is present"* so the property is total over the domain it declares. | §8 O-10 (property obligation) |
| F-06 | Low | Cross-Feature | **A paired-end justification went stale in this revision.** `pdlc-rcv-split.md` §6 redirects catalogue §3's *"fixed by `pdlc-rcv-budget-stop` §6"* on the ground "**since `REQ-RCV-01` mints no operator string (its §6)**". v2.7 makes that false: §6 now states it "mints exactly **one** operator string, added at v2.7: AC-1.3's Iterations render". The redirect itself remains correct (catalogue §3's clause is about row B's ❌ refusal text, and this REQ mints no *refusal* string), so nothing mis-resolves today — but the split file is the artifact a test author consults to decide which §6 fixes a string, and its stated reason no longer holds. Re-word split §6's parenthetical to "mints no **refusal** string", matching this REQ's own wording. §10's paired-edge rule ("a revision to either is carried to the other within the same revision") is the rule at issue. | §6; `pdlc-rcv-split.md` §6 |
