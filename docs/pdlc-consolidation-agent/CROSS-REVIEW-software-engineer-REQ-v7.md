| F-01 | High | Local | **Now that the id is derived from `phase` + `artifact` alone and `merged` is in NFR-4's key set, an id can be proposed exactly once in the life of the repository — which makes AC-5.3's remediation unreachable on the AC-3.1 route.** Replay it with the revision's own rules. Pass P promotes failure mode X (`phase` = DOD, `artifact` = `pdlc/skills/dod-verify/SKILL.md`), derives id `x` "from the promotion's `phase` and its target `artifact`, and from **nothing else**" (`:362-363`), opens a PR whose `PDLC-CONSOLIDATION-PROMOTIONS` trailer carries `x` (`:244`), and the operator merges it. Two later passes return `recurred` for `x`, so AC-5.3 fires: "it is flagged `ineffective` and the pass proposes either a revision or a retirement — an edit that did not work is not left in place indefinitely" (`:419-421`). Both alternatives, on the guard-set route, are PRs (AC-5.4 `:427-429`, AC-3.1). Both target the same `phase` and the same `artifact` — a revision edits that file again, a retirement removes the edit from that file — so **both derive id `x`**; the pass is forbidden from minting a variant (`:375`). NFR-4 then fires first: "A pass whose promotion's id is already on a PR in state **open or merged** opens nothing for it, records `duplicate-suppressed`" (`:516-517`), and `merged` is in the key set "deliberately" (`:519`). So the pass records `duplicate-suppressed` and opens nothing — permanently, because a merged PR never leaves the key set. AC-5.3's guarantee is not merely weakened, it is unreachable on the route AC-5.4 sends guard-set retirements down; the same argument bars any *later* re-promotion of a retired id, so the pipeline can promote a given `(phase, artifact)` pair once and never again. This is the exact hazard the REQ names as its own motivation — "no promotion is ever retired … An improvement process that cannot be wrong cannot be trusted to be right" (`:59-61`). It is a REQ-level defect because it is a contradiction *between two requirements*, and because the key set and the derivation basis are both enumerated here: FSPEC cannot carve an exception into a key NFR-4 states as closed. The fix is one clause, in NFR-4 or AC-5.1: key the suppression on `(failure-mode-id, action)` with `action` over the closed set `promote` / `revise` / `retire` — an AC-5.3 remediation is a different action on the same id and is never suppressed by the promotion that created it; or state that a promotion flagged `ineffective` is removed from the key set. Whichever, AC-5.3's disjunction field (`revision` / `retirement`, `:421`) already names the vocabulary. | NFR-4, AC-5.3, AC-5.4, AC-5.1 |
| F-02 | Medium | Local | **AC-3.3's "a retirement … with its own id" is underivable under AC-5.1's derivation-purity rule, and the `PDLC-CONSOLIDATION-PROMOTIONS` trailer's membership rule does not say whether a retirement is in it.** AC-3.3 reads "A retirement (AC-5.4) may share that PR, with its own id and its own commit" (`:258-259`). "Its own id" requires a value distinct from the retired promotion's; AC-5.1 forbids producing one, both by construction (the id is a function of `phase` and `artifact`, and a retirement names the same pair) and explicitly ("the pass never mints a suffixed variant, which would break derivation purity and with it NFR-4", `:375`). So AC-3.3 asks for a value the document's only id-minting rule cannot yield. The second half is the trailer: the REQ-CONS-03 preamble defines `PDLC-CONSOLIDATION-PROMOTIONS: {sorted failure-mode-ids}` as "one id per promotion the PR enacts" (`:244`) and AC-3.3 places the retirement outside "promotions" grammatically ("multiple promotions in one pass … **A retirement** may share that PR"). Whether the retirement's id joins the trailer is therefore undecided, and the two readings differ materially: in the trailer, the retirement PR itself becomes a suppression key for the id it retires; out of the trailer, the trailer stops being set-equal to the ids the PR enacts, which is what NFR-4 and AC-3.3's "commit → promotion is readable without counting" both rely on. A PROPERTIES author writing the set-equality check over that trailer has no way to decide which enumeration to transcribe. This is separate from F-01 and needs its own sentence: F-01 decides whether a remediation may be *opened*, F-02 decides what id it *carries* and whether that id is advertised. Cheapest resolution consistent with F-01's fix: state that a retirement or revision commit carries the retired promotion's `failure-mode-id` plus the `action` discriminator, and that the trailer enumerates `{id}:{action}` pairs — one grammar, one enumeration, both keys derivable. | AC-3.3, AC-5.1, AC-5.4, REQ-CONS-03 preamble |
| F-03 | Medium | Local | **NFR-4's newly-relocated URL requirement contradicts AC-7.2's biconditional, and the contradiction is reachable on the most ordinary suppressed path.** This round moved the duplicate URL's home from AC-3.5's proposal file into the log row: NFR-4 now says the pass "records `duplicate-suppressed` with that PR's URL **in its log row and its AC-7.1 report**" (`:516-517`) — v6 said "with that PR's URL (AC-3.5)", i.e. into the fallback artifact, which was consistent. AC-7.2 is unchanged and states a biconditional: the terminal report row "carries the PR URL **when and only when** a PR was opened" (`:494`). Now take AC-1.4's second cause — "every promotion it would have made was suppressed as a duplicate (NFR-4)" (`:201-203`) — which §4b confirms is the ordinary case, not a corner: "A pass whose **every** promotion was `duplicate-suppressed` promoted nothing new and is therefore `no-op`" (`:588`). That pass opened **no** PR, so AC-7.2 forbids its row to carry a PR URL; NFR-4 requires exactly that row to carry one. Both are enumerated contracts a test transcribes directly — AC-7.2's "when and only when" is a biconditional oracle, and it is falsified by a `no-op` row that carries a URL, so the two ACs cannot both be satisfied by one implementation. The mixed case is no better: a `promoted` pass that opened a PR for one promotion and suppressed another needs *two* URLs in one row with no rule for telling them apart, which AC-7.2's single-URL grammar does not express. Fix at the REQ layer because both sentences are requirements: either scope AC-7.2 to "the URL of a PR **this pass opened**, when and only when it opened one" and give the suppressed promotion's URL a distinct, named field (`suppressed-by:` alongside the reason code, which is where a reader would look anyway); or revert NFR-4's relocation and keep the duplicate URL in the AC-3.5 proposal artifact as v6 had it. The first is better — it puts the evidence on the channel a `/loop` operator actually reads — but either closes it. | NFR-4, AC-7.2, AC-1.4, §4b |
