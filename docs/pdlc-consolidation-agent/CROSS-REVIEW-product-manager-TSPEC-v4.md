## Positive Observations

- **F-10 was cleared by doing both things, not by choosing the cheaper one.** I asked for either a closed divergence or an erratum plus a falsifier. The revision raises the erratum *and* mints the falsifier, and it separates the two correctly: §13.3 asks the REQ whether "one enumeration" may be held by pins rather than by an equality (a product question), while §7.1 ships the pins so the answer is not blocking. The reasoning for why an equality is unavailable is the strongest part — "a set-equality assertion would be red on correct code" is a real argument, not a convenience, and it is backed by §10.4's two measured classes rather than asserted.
- **§10.4 corrects its own false claim by name and shows the measurement.** The bullet says outright that the earlier text "is **false, and it contradicted §7.1 point 2 of this same document**", reproduces the command, and states the numbers. I re-ran it independently and got exactly five paths with and without `--exclude-standard`, and seven without `:(glob)`. A spec that says "an earlier draft of this bullet said X, that is false, here is the measurement" is more useful to the next reader than one that quietly edits the sentence — the wrong belief was plausible enough to survive three rounds, and now it cannot recur.
- **The product trade behind `--exclude-standard` is now stated as a trade and priced.** "A `.gitignore`d LEARNINGS file is a file its own repository has said is not part of its record, and consolidating it would promote evidence into `DOMAIN-CONSTRAINTS.md` from a source no reviewer will ever see in a diff" is a product argument, correctly reasoned from where the pass's output lands. Declaring the choice provisional and routing it upstream rather than settling it in a technical spec is exactly the channel discipline F-10 asked for, applied to a question I did not require to be routed.
- **§11.2's `asAsync` now specifies the deferral kind and proves why the other kind cannot work.** The microtask/macrotask table is the sharpest new piece of reasoning in the revision: a microtask deferral is drained by the test's own `await main()` continuation, so the broken implementation would have been green — "specifying it as a microtask would have shipped a test that can only pass". The wrapper defers *recording* with resolution for the same reason, and the paragraph says why (the write's only observable *is* the double's accumulated text). The revision also narrows its own claim honestly: T-13 covers the intra-`finishPass` `await`s, and §10.2's two `return await finishPass(…)` sites are conceded as a stack/`try` improvement rather than counted as coverage.
- **T-13's conjunct (ii) grew a take-side precondition, unprompted, for the right reason.** "A bare absence is equally true of a `refused` / `skipped-cadence` fixture or a take that never landed, so without it the AC-1.3 half passes vacuously" — the marker test now observes the marker **present during the pass** and gone after. AC-1.3 is a guarantee an operator feels directly (a stuck marker blocks every later pass), and this is the difference between a row that covers it and a row that coexists with it. The mutation obligation attached to it ("delete one `await`, expect RED, restore … a test whose falsifier has never been observed is a claim") is the right thing to demand of the only oracle for an otherwise unguarded invariant.
- **§12.2's "a named gap is not a licence to ship uncovered" is the correct resolution of F-12, stated as a rule.** The paragraph distinguishes the erratum (asks the FSPEC whether the register should carry an id) from the local case (makes the obligation falsifiable meanwhile) and says they are "complementary, not alternatives". Both new cases are well-formed: T-12's negative carries its positive control **in the same case**, so "no proposal file was written" cannot pass on a fixture that wrote nothing, and §12.3's new parser paragraph shows why a prose clause beside an id list contributes to neither side of the set equality — the invariant is restated in both directions rather than assumed.
- **§11.1's executed-row counter is now derived from behaviour, not from the table.** "It is **not** read from the fixture table's length — that is derivable from the table itself and would be self-satisfying"; the counter increments as each row's **last** statement, after its own assertions pass. The three cases are then walked (interpreter dies at row 4 of six ⇒ `3` ⇒ red; a swallowed throw never increments ⇒ red; a wholesale skip ⇒ `0` ⇒ the one legitimate pass). That is the difference between an all-or-nothing invariant and a restatement of the fixture table.
- **§11.3(f)'s fixture rule is moved into the code that must obey it.** "A constraint a later contributor must not violate is one they must be able to read where they are working" — the no-git-visibility-fixtures rule is written into `consolidationDoubles.js`'s fixture-builder header, beside where `seams.js` and `advisoryDoubles.js` state their own. A rule that lives only in a TSPEC is a rule the next contributor will not see.
