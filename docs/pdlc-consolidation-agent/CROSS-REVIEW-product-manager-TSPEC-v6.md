## Positive Observations

- **F-17 is answered by disposition, not by argument, which is the harder of the two.** The revision could have won the argument — its case that no seam can separate a released marker from a truncated one is airtight, and I verified the premise again at HEAD (`rtWriteFile` `:802`, `rtAppendFile` `:863`, `rtListFiles` `:905`, `rtGit` `:945`; no removal verb anywhere in the adapter). Winning it would have justified saying nothing. Instead §7.3 names the FSPEC row it cannot satisfy, §10.3 splits row 4 so the unreachable arm has a row of its own, §12.3 tells a future test-writer that the register's full *Given* "would be red on correct code", §13.1 records the decision with its rejected alternatives, and §13.3 hands the product question to its owner. That is five places a reader could arrive from, each carrying the same reading.
- **The erratum states the product question, not the technical one.** "*When a pass dies mid-take, must the durable log witness it?*" is the sentence a REQ author can actually decide, and §13.3 puts both answers on the table with their costs rather than presenting the shipped one as obviously right ("Both are defensible — a truncated marker is weak evidence of anything actionable"). It also separates what belongs to whom in one clause: the choice "belongs to the REQ/FSPEC author and not to the adapter's verb set". This is the third round running where this document routes an upstream defect instead of absorbing it, and the routing has got more precise each time.
- **AC-1.3's own wording turns out to sanction the release form, and the decision row found it.** §13.1 row 13 cites `REQ-…:155-156` for "in-place rewrites of a whole small file", and the REQ says exactly that at `:155-156` — "taking and releasing it are in-place rewrites of a whole small file". So rejected alternative (c), the removal seam, is not merely expensive; it contradicts the shape the REQ already settled. Finding the requirement that pre-decides a rejected alternative is better evidence than the engineering argument beside it.
- **§5.5's new paragraph corrects a claim that was true only under jest — and finds a real safety hole doing it.** The old table row said the module defaults give "ordinary operation"; the revision qualifies it to "under jest only" and then explains why `_checkFile` is the one seam where that matters: its probe is *supposed* to be negative on a healthy tree, so a default returning a legal `{ok:false, reason:"file_missing"}` would be indistinguishable from a quiet tree and "AC-1.3's mutual exclusion would be off in production, and every L2 fixture would stay green". The dynamic-import premise verifies (`orchestrate-queue.js:949` is `const { readFileSync } = await import("fs")`), and so does the contrast it draws: `checkFileNonEmpty`'s catch does return `{ok:false, reason:"file_missing"}` (`orchestrate-dev.js:3690-3692`), and the paragraph is right that the shape is correct for a *document* probe and wrong for a *lock* probe. A silent-failure mode of AC-1.3 that no fixture could have caught, found from a table row's adverb.
- **The `rtConsInjections()` set-equality row is grounded in this repo's own recorded mistake.** `runtime-adapter.js:1098-1100` carries the note verbatim — "`_writeFile`'s adapter existed since the first bundle but was never in this object" — and the row cites it as evidence that an unwired seam is a shipped failure mode here, not a hypothetical one. The precedent test it names is real (`adapterProbe.test.js:253-258`, "wires all three into `rtDevInjections`"), and the row widens it from per-name containment to set equality with the reason stated: containment "is exactly the assertion that would still pass with `_checkFile` missing, which is the failure".
- **Two test-mechanics corrections this round both moved an assertion onto the path where it was needed.** §11.1's counter disjunction moves from `afterAll` to its own unconditional `test()` declared last, because jest skips a block's `afterAll` when every test in it is skipped — so the all-skip world's `executed === 0` would have been unobserved in the one world the sentence claimed to cover. §11.2's drain moves into a `finally`, because a trailing drain runs only when the assertions passed, i.e. "present in every run that did not need it, absent from every run that did". Both are the same class of defect and both are stated as the mechanism, not the fix.
- **§11.1 records what the new L4 case does *not* cover, and ties the gap to the open erratum.** The fixture is `git init` + `git add -A`, so `--exclude-standard` is inert in it: the case pins the `:(glob)` half of pin (a)'s argv and not the flag half. Rather than quietly adding an ignored fixture member, the paragraph explains that doing so would pin the answer §13.3 has declined to give, and states both branches of what happens once it is answered. Declining to test something because testing it would prejudge an open upstream question — and saying so — is a discipline I have not seen elsewhere in this document set.
