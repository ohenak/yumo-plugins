| F-01 | Medium | Local | **AT-F21's stated falsifier for the middle prohibited behaviour is inverted against the document's own two predicates, so conjunct (3) cannot catch the default it is written to catch — and the fixture never pins the field that would let it.** The row closes: "the three prohibited behaviours … a halt on `undefined`, a `route ?? \"degraded\"` default (**which would make a legacy record *close* an id**, the unsafe direction §8.4 refuses), and a silent rewrite — and each is red on **exactly one** of these conjuncts". Both halves are wrong, and both are checkable against rules in this document. (i) BR-33c (`:2422`) and §8.4 step 1 (`:1356`) define open as "**no** record for that id carries `action: retire` with a `route` **other than** `degraded`" — so a record whose missing `route` is defaulted to `degraded` can never close an id; it leaves it **open**, which is the *same* outcome the skip rule produces. The default that would actually close an id is the opposite one (`route ?? "constraints"`, or any non-`degraded` value) on a `retire` record. (ii) The other `route` reader agrees: BR-25 (`:2401`) makes a pair `enacted` only "with a `route` other than `degraded`, and `absent` otherwise", so `?? "degraded"` yields `absent` ⇒ re-proposed — again identical to the skip rule. Conjunct (3) therefore asserts nothing about the default on either reader, and conjunct (4) is green too (an in-memory default writes no bytes back). Compounding it, the Given never states `E`'s `action`: unless `E` carries a record with `action: retire` **and** a missing `route`, the open-list conjunct is satisfied vacuously — every `promote`-only id is open under any default.
