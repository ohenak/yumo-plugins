| F-01 | Medium | Local | **The two new gate pins take their expected value from the module under test, so they are an implementation echo — they catch a swap and nothing else.** §12.1 says the exported `deps` object's five values are pinned: three runners `===` `run.mjs`'s correspondingly-named exports (`run.mjs:381`, `:422`, `:478` — all three verified at HEAD), and "the two gate values `===` `cli.mjs`'s own exports of those names" (`:1387-1394`). The runner pins are real oracles: the expected value comes from a *different* module, so a mis-wired default is red. The gate pins compare `mod.deps.startupFor` against `mod.startupFor` — both imported from the unit under test — which is true by construction for every implementation except the one the TSPEC names (`startupFor: liveAdapter`). Rename or rewire `startupFor` itself and both sides move together, silently. The gap matters here more than usual because these are exactly the two keys this round introduced, and the whole reason they exist is that the leg cannot afford an env-dependent default. Cheapest fix that stays a literal transcription rather than a derivation: add one discriminator per gate key that is written down in the spec, not read off the module — e.g. `deps.startupFor.name === "startupFor"` and `deps.liveAdapter.name === "liveAdapter"` (a swap fails, a rename fails, and neither expected string is derived from the import), or state in §12.1 why the self-referential `===` is the strongest bar available for a module-local binding so a later reader does not mistake it for the runner pins' strength | AC-5.3 |

## 4. Positive Observations

- **The round chose the harder, more honest fix over the one I asked for.** My v8 F-02 offered a cheap out: pin the ladder with `--plugin-root` and `--allow-api-key-billing` and the leg goes deterministic. §9.3 writes that alternative down, shows it is *writable* (both flags really are in `queue`'s and `dev`'s closed flag sets, `bin/pdlc.mjs:93-103`, and the opt-in widens `apiKeyPolicy` at `:144` past the only refusing auth row, `lib/auth.mjs:88-95`), and rejects it anyway because it leaves four ambient preconditions load-bearing for a leg whose entire question is what the command body put in an argument object (`:1362-1372`). That is the right trade for AC-5.3 — the shipped subprocess tests keep the real ladder (`__tests__/cli.test.js:86`, `:102`, `:114`), and the division of labour is stated rather than implied.

- **"Silent-zero" is named as a failure *shape*, not just fixed as an instance.** §9.3 and §12.2's new fake row both say the same thing: an env-driven refusal leaves `captured` empty, and every loop-shaped assertion passes over an empty array — "the same shape TE v7 F-39 removed one level down" (`:1355-1360`, §12.2's new row). Naming the recurrence is what makes the response general instead of local, and it is what produced the capture-count rule below rather than a second one-off fixture patch.

- **Counts before contents, positively stated, on every runner leg.** §12.1 now asserts `captured.length === 1` where a runner should be reached and `=== 0` where it should not, *before* anything about the captured objects (`:1697`); §7.2 does the same for the injection-level leg with `captured.length === 2` plus `stopReason === "bound-reached"` (`:854-872`). Both are positive observations paired with the negative claim, which is the oracle rule applied rather than cited. The `stopReason` pin is the better half: `LOOP_STOP_REASONS` really is a closed four-member frozen set at `run.mjs:317`, so a decayed fixture lands on a *different named member* rather than on `undefined`, and the decay path the section describes is real — a recording `main()` returning `{outcome: "idle"}` stops on pass 1 as `"exhausted"` (`run.mjs:505-508`), leaving exactly the one-entry `captured` that makes a per-pass comparison vacuous.

- **The five recorder return shapes are derived from the lines the leg actually executes, and they check out field by field.** §9.3 `:1397-1409` names each stub's return because the command bodies keep running past the seam. Verified against HEAD: `formatStartup` spreads `result.banner` first (`lib/startup.mjs:485-486`) — hence `banner: []`; `emitReport` reads `startup.pluginVersion`/`pluginRoot` and calls `adapter.getApiKeySource()`/`getPauseLog()` (`bin/pdlc.mjs:323-342`) — hence those four stub members; `cmdQueue` destructures `{passes, outcome, stopReason, exitCode, loop}` and then reads `loop.iterations`/`loop.maxIterations` (`:434-452`) — and the stub supplies precisely those, with `passes: []` flowing safely into `emitReport(last && last.report, …)` because `exitCodeOverride: 0` wins over the `!report` branch (`:346-347`). "None of this is fixture decoration — each field is read by a line the leg executes" is a claim I could falsify field by field, and it survives.

- **K-3 re-priced itself upward rather than absorbing the change quietly.** The cost row went from "one exported binding, one defaulted parameter" to four exported bindings and a five-key parameter, with the reason each export exists spelled out (`:1891-1895`). A cost table that only ever grows when someone asks is a cost table nobody trusts; this one moved on its own.
