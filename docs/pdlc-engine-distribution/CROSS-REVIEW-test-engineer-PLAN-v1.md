## Positive Observations

- **Every `file:line` citation in the document is accurate at HEAD.** Spot-checked all of them, and none drifted: `orchestrate-dev.js:2839` / `:6736` / `:10429` are the three `"commit"` invocations, enclosed by `buildA5SeamOps` / `appendApprovalAnchors` / `commitPaths` respectively; `orchestrate-queue.js:1603` / `:1645` are `commitQueueRow` / `commitAdvisoryRecord`; those five are the **complete** set of `git commit` sites in both modules, so T19's set-equality is stated against a set that really is closed today. `seam-contract.test.js:47-63` are the two literal seam lists, `:67` / `:72` the two `deepEqual`s, `:223` `UNOVERRIDDEN_IO_SEAMS`, `:277-280` PROP-PARITY-15 — all exactly as described. `build-runtime.mjs:274` and `:307` are the two generated `rewriteStatus` closures, and `rewriteStatus` really does take seven positionals today (`orchestrate-queue.js:1522-1530`), so "8th argument" is right. `_assert-suite-wide.mjs:195-213` really does push failures in both directions. This is the most reliably grounded PLAN I have reviewed in this feature.
- **The batch DAG is mechanically correct.** All 55 rows satisfy `Batch = max(dep batch) + 1` with no exceptions, no cycles, no dangling ids. §6 Rule 1's spelled-out cases (T44, T43, T45, T48, T50, T49, T41, T42, T51, T52) each re-derive to the stated number.
- **§2 ↔ §3 is a genuine bijection**, cell-for-cell, in both directions — `validatePlanContract` will pass on this table.
- **Single-writer-per-file-per-batch holds everywhere**, including the six-writer `lib/catalogue.mjs` chain across six consecutive batches. §1.3's framing of the catalogue as a serialisation point is the right diagnosis and the edges implement it.
- **The catalogue constraint is correctly read.** "A task may not register a message id in one batch and emit it in a later one" is exactly what `checkMessageCatalogue`'s registered-but-never-emitted arm enforces, and every catalogue-touching task registers *and* emits within itself. This is the kind of oracle-shape reasoning that prevents a whole batch of red.
- **T47's ordering discipline is exemplary.** "capture counts asserted first — `=== 1` where reached, `=== 0` where not… `captured.length === 2` and `stopReason === "bound-reached"` asserted **before** the `captured[i]._provenance === p` identity comparison" is precisely how you stop an identity assertion passing vacuously over an empty array. Please keep this wording verbatim into PROPERTIES.
- **T24 states positives, not absences.** "produced-kind set-equality with **positives**", with the unmarked-content claim paired against a marked harness commit message on the same run, is a correctly falsifiable negative.
- **T20's inertness oracle is byte-identity**, not "no error" — the strongest available form for P-1.
- **T16 and T17 both ship falsifiers** (one-byte mutation; mutations against fixture copies), and T16 runs against a **real `npm pack` into a temp dir** rather than a simulated file list. T17's "non-matrix name expression ⇒ `unexpandable`" and "job-level `uses:` ⇒ `unexpandable`" are honest fail-closed states rather than silent skips. Confirmed against HEAD that `pr-tests.yml` really does need **per-job** matrix expansion — `unit-tests` has two matrix keys and `engine-tests` one — so the finding that motivated it was real.
- **§5's integration points are checkable and correct**, including the non-obvious one: jest's `testPathIgnorePatterns` already excludes `/__tests__/helpers/`, so T04's `provenanceDoubles.js` will not be collected as an empty suite — a trap that has bitten this repo's shape before.
- **§1.2 and §7's "not in scope" are explicit about N-1…N-6**, and the three already-raised errata are described with enough mechanism that a reader can verify each independently.

## Recommendation

**Needs revision**

Five High findings, so this is mandatory — but the distance to approval is short, and none
of it is rework of the plan's structure. The graph is sound: batch arithmetic, the
bijection, the collision check and the DAG all pass mechanically, and the line citations
are accurate throughout. What blocks approval is four missing rows/edges and one oracle
that cannot fail for the right reason:

1. **F-02** — add a task owning `pdlc/engine/LICENSE` **and** `package.json`'s `license`
   field, dependent on T05 and ordered against T25. Without it the suite is red from
   batch 2 to batch 11. (Or move T05 last; see the ERRATUM — the upstream needs to pick.)
2. **F-03** — give T41 (or a new b6+ row) ownership of `pdlc/engine/__tests__/run.test.js`,
   restate `run.test.js:41-50` in two-root terms, and require AF-3's restatement to assert
   a non-zero member count before its per-member equality.
3. **F-01** — mark T10 as extending an existing 9-test file and name the assertions that
   must survive; correct §5.1's "eighteen" to sixteen.
4. **F-04** — for each of C-a…C-e, name the reachable entrypoint and assert the recorded
   `_git` argv, not the presence of `provenance.line` in the source.
5. **F-05** — state T18's file set as `git ls-files` over a named non-`docs/` subset.

The Medium findings (F-06…F-13) are all one-line-per-row edits: two `Deps` additions
(T30 → T35, T02 → T18), one header carve-out, one present-tense correction, a coverage
floor in §7, two falsifiers, and naming the generated-input tasks. Address those in the
same pass and the next round should be a straight approval.
