Revision 2.1: MVP-first delivery strategy

Supersedes the previous infrastructure-first schedule. Reuse the existing headless PDLC engine. Week 1 proves a real implementation. Week 2 delivers a usable feature-to-PR workflow with CI repair. Week 3 adds bounded independent model review. Week 4 adds GPT and Claude provider routing. Week 5 adds only the missing recovery mechanisms. Weeks 6–7 introduce Terraform staging release. Week 8 adds enterprise approvals, optional Jira integration and a basic decision report. Weeks 9–10 validate three real feature deliveries.

No Temporal or Ptah dependency is required for MVP. Do not implement SQLite unless the existing workflow recovery mechanisms fail controlled tests. Each new milestone must be built using the usable capabilities from the previous milestones whenever safe. See the revised milestone index.

Stop rule: If the same blocker fails twice, end the agent session with evidence and a proposed narrow fix. Do not consume the remaining budget on speculative rewrites.

Product policy

Decisions and tracking

GitHub Issues is the default record for engineering decisions. Jira is an optional employer extension for Solution, Epic, and Story tracking. GitHub PRs record implementation and review.

Review

The original model raises the PR and repairs findings. An independent model reviews the PR. The model-review episode has at most two reviewer passes. Unresolved High or Critical findings block progress. In employer mode, check the actual GitHub approval rule. The rule usually requires one or two human approvals. Continue human review until blocking issues are resolved and valid approvals are in place. Do not bypass required human reviews.

CI

Monitor checks for the current head SHA. The original agent investigates failures and pushes repairs. Use a separate bounded repair budget. Do not count a failed check from an old commit as a check on the current commit.

Terraform and identity

Use Terraform for both personal and employer deployment flows. Save and evaluate a Terraform plan before apply. Google Cloud permits ADC and service-account impersonation for approved local use. Unattended workflows can use workload identities or attached service accounts. They do not need to use personal human credentials. Apply least-privilege access and employer policy.

Model permissions

Personal profile: user-provided access includes GPT-6 and approved Claude models. Employer profile: GPT-5.2 and Opus 5.5. Enforce an allowlist before invocation. Do not transfer employer data to personal model accounts.

Safety

Never treat model confidence as proof. Use executed tests, security checks, valid approvals, and deployment health evidence. Do not treat review-budget exhaustion as approval.

Program success criteria

  • Demonstrate a personal low-risk feature through a full release path.
  • Resume safely after stopping the local process.
  • Use different approved providers for author and reviewer.
  • Prevent merge on an unresolved High/Critical finding or missing human approval.
  • Repair ordinary CI failures without manual commands, within the defined budget.
  • Deploy a staging revision through an approved Terraform plan and identity.
  • Measure human hands-on minutes and engineering quality against the baseline.
Success does not mean that an AI agent can deploy any change without authorization. Every step must follow a versioned policy.

Writing rules for this pack

This pack uses a project writing profile that is based on ASD-STE100 principles. It is not a claim of official ASD-STE100 compliance.

  • Use short sentences. Put one main instruction in each sentence.
  • Use an active verb. Name the actor when it affects the result.
  • Use one term for one meaning. Do not change between gate, check, and approval.
  • Define technical words at first use. Keep exact code symbols unchanged.
  • Use steps in the order in which the agent must do them.
  • Separate observed facts, proposed changes, and assumptions.
  • Use an explicit PASS, FAIL, BLOCKED, or NOT TESTED result.
  • Keep code, paths, and configuration keys in their exact technical form.
