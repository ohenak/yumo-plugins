Prove first delivery with CLI help

Deliver one small feature in yumo-plugins through deliver-feature-chain. The operator creates the pull request manually.

Current result: The user settled the visible behavior in issue #86. A draft requirement exists with ready: false. The delivery chain must wait for operator sign-off on that requirement. The local CLI still exits with an error for all three help forms.

Scope and decision

The accepted user behavior covers pdlc --help, pdlc help, and pdlc <command> --help. Each form must exit successfully without credentials or project setup. The first two show general usage. The command-specific decision requires that the third show that command's syntax and flags. Record any remaining design choice in issue #86 before building its dependent behavior.

regime-ledger is an external consumer project for a later experiment. Its issue #1 does not block M1. yumo_bak and the old GitHub Yumo repository are deprecated historical context.

Implementation sequence

  1. Pin the yumo-plugins commit and work in an isolated checkout because the source checkout has unrelated local edits.
  2. Review the draft requirement against issue #86. Record operator sign-off in the issue, then change the requirement's ready flag.
  3. Use the feature chain to inspect the CLI seam and write FSPEC, TSPEC, DECISIONS, PLAN, and PROPERTIES artifacts. Review each artifact before implementation.
  4. Write a failing test for each required form, implement the smallest change, and run the relevant tests.
  5. Record the feature-chain commands, result, elapsed time, human work, failures, and model use where available. The successful pdlc dev ... --dry-run --plugin-root pdlc produced a 31,821-byte preview without dispatch. Treat a full engine run as a separate decision because its automatic pull request phase conflicts with the operator-created pull request boundary.
  6. Review the diff. The operator creates the pull request. Check required continuous integration on the pull request's current head commit SHA.

Exit evidence

  • The accepted issue record and feature commit are linked.
  • All three help forms pass tests and work without credentials or project setup.
  • The feature-chain commands, dry-run compatibility result, scoped test result, and complete test result are recorded.
  • The manual pull request URL and required continuous integration result refer to the pull request's current head commit SHA.
  • Elapsed time, human work, failures, and model use are measured or marked UNKNOWN.

A passing doctor or dry run checks compatibility only. It does not satisfy the feature delivery gate or show that the full engine delivered this feature.
