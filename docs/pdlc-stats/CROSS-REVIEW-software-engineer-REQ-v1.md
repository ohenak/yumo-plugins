| F-01 | High | Local | REQ-STATS-03/C-5 define the headline metric as equal to "the round window the review-loop driver would derive". A *window* is not a *count*. `deriveRoundWindow` (`pdlc/workflows/orchestrate-dev.js:10192`) returns `{startIndex, endIndex}` where `startIndex = max(existing rounds) + 1` (`:10236`) and `endIndex = startIndex + MAX_REVIEW_ROUNDS - 1` (`:10254`) — i.e. the *upcoming* round budget, not rounds already completed. Implemented literally, the P0 metric reports off-by-one, or a two-number range where a count is required. Contrast REQ-STATS-04, which correctly names an outcome ("the highest version `N` found on disk"). Fix: state the outcome directly — the count is the highest round index present for that document type (equivalently `startIndex - 1`) — and keep C-5's fidelity clause as the *no-independent-parsing* rule it is. | REQ-STATS-03, C-5 |
