## Positive Observations

- **The read-only pair is the strongest testing design in the document, and it avoids the flake this repo has actually seen.** AT-21 asserts both conjuncts against one invocation — snapshot set-equality *and* "stdout carried the metric set and exit was 0" — so the never-runs implementation that trivially satisfies read-only fails. The snapshot spans untracked paths and is compared against a second snapshot of the same tree rather than a fixed literal (§7.1 D-1), which is exactly the lesson `coveredViolations` taught this repository: a developer machine carrying a tool cache is not a source of flake under a two-snapshot comparison. AT-22 then repeats it on both failure paths, which is where a read-only claim usually breaks.
- **BR-10's near-miss is stated because the source really does bite.** `deriveDodRoundIndex` returns `max + 1` and returns `1` for a feature with no `CODE_REVIEW` file (`pdlc/workflows/orchestrate-dev.js:12384-12396`), so "report the driver's return value" is off by one on every feature and invents a DoD round for features that never ran one. BR-10 names both near-misses (not a count, not the next index) and AT-11 pins the literal `2` against a directory that exists. That is a rule an implementer cannot get wrong by accident and a test that can fail.
- **AT-17 resolves the REQ's standing Medium with three fixtures instead of prose.** REQ-STATS-06's negation scope was the one Medium left open at `CROSS-REVIEW-test-engineer-REQ-v3.md` F-01. BR-16 states the disjunction explicitly and AT-17 pins it on the two cases that separate the readings — cross-reviews intact with no `CODE_REVIEW`, and `CODE_REVIEW` intact with no cross-review — plus the precedence case against `n/a`. `docs/completed/pdlc-headless-engine/` is a real instance of the first, so the reading is checkable against a tree that exists rather than only against a constructed one.
- **The state-carries-inside-its-metric decision is what makes REQ-STATS-02's set-equality a real test.** BR-21's five literal keys plus BR-22's placement rule turn "the key set is set-equal to the printed metric set" into an assertion with one expectation, and AT-05 requires the fixture to exercise a malformed basename and a non-numeric state so the equality is tested where it would break. D-5's refusal to echo the feature name is consistent with the same rule rather than an aesthetic choice.
- **§7.3 raises upstream errata instead of quietly resolving them.** Four REQ wording defects from the v3 reviews are named, the reading this FSPEC derived from is recorded, and the ones that change no FSPEC behavior are marked as such. That is the behavior that keeps the two documents reconcilable without guesswork, and it is why F-01 and F-02 below are findings against this document rather than ambiguities inherited from the REQ.

## Recommendation

**Needs revision**

Three open High findings. This is a well-built behavior spec — the metric rules are decided rather
than deferred, the non-numeric states are named and given precedence order, and §6.10 traces all
thirty business rules to acceptance tests — so the revision is bounded and none of it is rework.

F-01 is the one that changes an operator-visible number: the pipeline writes a seventh cross-review
document type (`REVIEW`, from Phase CR, `orchestrate-dev.js:9245`/`:9364`) that `parseReviewFilename`
rejects as `bad_doc_type`, and four such files sit in `docs/completed/pdlc-advisory-wave-gate/` today.
Under BR-06 and BR-09 as written, the command's first run over this repository reports four
pipeline-authored artifacts as malformed and hides two rounds of implementation review — a confident
wrong number of exactly the kind §1's fidelity anchor says is worse than no stats command. Deciding
it needs one rule in §4.2 and one fixture on AT-09.

F-02 and F-03 are both about tests that cannot currently be written or cannot currently fail.
BR-23's two-key fleet document leaves EC-10's unclassified entry nowhere to go, so AT-19 has no
JSON expectation; and AT-13, the only acceptance test covering the constraint the whole feature
rests on, defines its expectation as the dependency's own output, so it agrees with any
implementation including a wrong one. The literal is available — the fixture's marker is
`RESOLVED: yes` — and adding a `RESOLVED: no` companion makes the test able to distinguish the two
classifications rather than merely echo one.

The six Mediums are the same class of gap one level down: a self-contradicting schema sentence
(F-04), a fleet rendering that quietly narrows the metric set REQ-STATS-07 requires (F-05), seven
untested edge cases with no EC→AT traceability (F-06), a byte-ratio fixture that checks containment
where the rule is an enumeration (F-07), and two oracles that assert absence or derivation where a
literal equality is available (F-08, F-09). All are single-clause or single-fixture edits.

None of the findings contests a decision this FSPEC was right to make. The command surface, the
exit-code allocation, the harvested/`n/a` precedence, the fixed row set and the two-snapshot
read-only proof are all sound, and the repository claims the document makes check out against source
line by line.
