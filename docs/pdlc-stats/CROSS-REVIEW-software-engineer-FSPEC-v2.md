## Positive Observations

- **The v1 F-03 fix is the best kind: it moved the claim rather than the citation.** §1's new paragraph states plainly that nothing in the driver classifies a `POSTMORTEM-*` listing, explains why selecting this feature's post-mortems is therefore this command's own match and not a C-5 divergence, and BR-12 carries the same reasoning to the rule. The temptation was to find some function to cite; the document instead named the boundary and raised the REQ's C-5 enumeration as an erratum. I checked the three constructing call sites again (`orchestrate-dev.js:8618`, `:9402`, `:15293`) and the reasoning holds exactly as written.
- **D-8 and the `REVIEW` case are a genuinely good find, and the document resisted the easy fix.** Four `CROSS-REVIEW-{role}-REVIEW-v{N}.md` files really do sit in `docs/completed/pdlc-advisory-wave-gate/`, written by `orchestrate-dev.js:9245`'s `roundDocType || "REVIEW"` fallback and rejected by the same file's own six-type catalogue at `:10105`. Inventing a third bucket would have been one line and an independent parsing rule; following the REQ literally and raising the wording as an erratum is the right call, and AT-09 pins it on the real directory with a checkable second assertion (`TSPEC` still reads `6`) so the test cannot pass by ignoring the directory.
- **The literal-not-derivation rule is now stated once and applied everywhere it was violated.** §6's preamble states it as a rule with the reason attached ("an expectation computed by the code under test agrees with a wrong implementation") and then permits re-measurement when the archive moves, which is the honest caveat that keeps the rule from being quietly abandoned later. AT-13's `RESOLVED: no` companion is the part I did not ask for and is the part that makes the test falsifying.
- **AT-15's removal probe converts the enumeration assertion from containment to set-equality in one clause.** "Removing any one of the nine changes its side's total by exactly that file's size" is stronger than listing the nine, because it fails for an implementation that enumerates eight — which was the defect. Same for AT-19's "three, no more" on the fleet key set.
- **AT-02 was rewritten away from a negative-only oracle without being asked.** v1's "no metric equals the sum of the two directories" became byte-identity against the same tree with the archive absent, and the document says why: the realistic BR-02 violation is a merged read that deduplicates by basename, which the sum check would not catch. That is a sharper test than the finding that prompted the neighbourhood.
- **A-3 was narrowed in the right direction.** The role catalogue stays inherited from the pipeline; the document-type catalogue is now explicitly enumerated and owned here, because D-4 makes the row set observable output — and D-8's `REVIEW` case is cited as the proof that a seventh spelling reaching the driver is not hypothetical. That is the assumption most likely to have rotted silently.
