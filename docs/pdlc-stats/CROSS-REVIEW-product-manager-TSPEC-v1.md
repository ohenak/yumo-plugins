| F-01 | High | Local | **`schemaVersion` does not appear anywhere in the TSPEC.** The string is absent from §3.3's public surface, §4.1's metric types, §4.2's `StatsOutcome`/`StatsReport`, and every oracle in §6. REQ-STATS-02 makes "one schema-version field" one of only two observable guarantees the P0 machine-readable mode owes its callers, and FSPEC BR-24 fixes it as an integer, `1` at first release, whose presence is REQ R-5's stability anchor (FSPEC BR-21, BR-23, BR-24, BR-30). The design as written has no type that can carry it and no test that would notice its absence. **Fix:** name `schemaVersion` in the JSON contract (a `renderJson` obligation, not a `StatsReport` field, since both renderers share one report value), and add it to §6.3's cross-mode oracle's asserted key set. | REQ-STATS-02, FSPEC BR-21/BR-23/BR-24 |
| F-02 | High | Local | **The JSON top-level key set is never stated, and the type that reaches `renderJson` carries two keys BR-21 forbids.** §3.3 types `renderJson(outcome: StatsOutcome): object` with no key set; §4.2 makes it a total pure function of `StatsReport`, whose `kind: "single"` arm is a bare `FeatureStats`; and §4.1's `FeatureStats` carries `feature` and `dir` alongside the four metrics. ## Positive Observations

- **REQ C-5 is discharged structurally, not by discipline.** §2.5's parser bundle plus §6.4's `===` identity oracle turns "do not re-implement the pipeline's grammars" from a coding-style request into something a test can fail. All four cited exports exist and carry the shapes §3.2 transcribes: `parseReviewFilename` (`orchestrate-dev.js:10134`), `deriveRoundWindow` (`:10192`), `deriveDodRoundIndex` (`:12384`), `parseResolvedMarker` (`:7601`). This is the single most important product constraint in the REQ and it is the best-defended thing in the document.
- **The near-miss arithmetic is named rather than assumed.** `deriveRoundWindow` returns `startIndex = max(indices) + 1` (`orchestrate-dev.js:10237`) and `deriveDodRoundIndex` returns `max + 1` (`:12396`); §4.3's `- 1` conversions and its `startIndex > 1` "any file present" test are both correct against that code, and REQ-STATS-03's "highest index present" and REQ-STATS-04's "highest version, not a count" both land exactly.
- **§3.2's early-return catch is real and load-bearing.** `deriveRoundWindow`'s collision branch does return before `skipped` is populated (`orchestrate-dev.js:10222-10229`), so BR-06's malformed list genuinely would be lost on an `unmeasurable` row had the design taken it from `w.skipped`. Catching that in the TSPEC rather than in implementation protects a REQ-STATS-03 observable.
- **Fail-closed halt resolution matches the pipeline's own rule.** `parseResolvedMarker` returns `ok: false` for absent, duplicated and unparseable (`orchestrate-dev.js:7603-7616`), and §4.3's single `(m.ok && m.resolved) ? "resolved" : "open"` maps all three plus read failure onto `open` — the same direction `checkPostmortem` takes. REQ-STATS-05's "exactly the pipeline's own marker rule" is honoured without restating the rule.
- **Every factual claim about the repository checks out.** `docs/completed/pdlc-advisory-wave-gate/` carries exactly four `CROSS-REVIEW-…-REVIEW-v{1,2}.md` files; `docs/completed/pdlc-headless-engine/` carries `CROSS-REVIEW-software-engineer-TSPEC-v13.md`, its `LEARNINGS-*`, and `POSTMORTEM-{D,F,I,T}-*`; `docs/completed/pdlc-loop-economics/` carries `CODE_REVIEW-…-v{1,2}.md`; `docs/completed/pdlc-wave-resume/` carries `POSTMORTEM-PR-*`; the loose files `docs/PLAN-pdlc-integration-boundary-gates.md`, `docs/completed/REQ-completed.md` and `docs/completed/QUEUE-HISTORY-rows-0-1.md` are all present; and the eight `NON_FEATURE_DIRS` are exactly the non-feature directories at `docs/`. §6.1's real-path fixtures rest on measured facts, not on hope.
- **Read-only is closed by capability, not by convention.** §2.3's four-member seam bundle carries no write and no `git` member, §6.4 pins it at four keys, and §6.5 pairs the snapshot with a liveness conjunct on the same invocation — which is precisely REQ-STATS-08's "read-only never suffices alone". §6.5 also anticipates the untracked-file flake that `coveredViolations` produces, and answers it with snapshot-to-snapshot set-equality rather than a literal.
- **The two FSPEC gaps the author found are routed, not silently patched.** §8.3 raises the missing feature-recognition predicate and BR-25's incomplete loose-file illustration as errata against the FSPEC instead of inventing REQ-level meaning in a TSPEC. That is the right channel and it is what F-07 asks only to be made provisional, not to be undone.

## Recommendation

**Needs revision**

Four High findings, so this is mandatory rather than a judgement on the document — which is otherwise
the most structurally-defended TSPEC this feature could have asked for. Three of the four cluster in
one place: **REQ-STATS-02's machine-readable contract is the one P0 the design does not pin down.**
The other is an oracle that cannot fire.

Exactly what must change before approval:

1. **F-01** — introduce `schemaVersion` into the JSON contract (§4.2), fixed at `1`, and assert its
   presence in §6.3's oracle. Today the identifier does not occur in the document.
2. **F-02** — state the emitted top-level key sets explicitly: five for single-feature
   (`schemaVersion`, `reviewRounds`, `dodRounds`, `halts`, `byteRatio`), three for fleet
   (`schemaVersion`, `features`, `unclassified`), three for the error object (`schemaVersion`,
   `error`, `feature`) — and name the projection that drops `FeatureStats.feature` and
   `FeatureStats.dir`. Assert each by set-equality against a literal transcription of BR-21 / BR-23 /
   BR-30, never by deriving the expectation from the type under test.
3. **F-03** — add the fifth anti-drift oracle: `NON_FEATURE_DIRS` set-equal to the non-feature
   directory names at the repository's `docs/` root, and map AT-19 onto it in §6.
4. **F-04** — repair §6.4's doc-type catalogue probe to use a real role slug
   (`software-engineer` / `product-manager` / `test-engineer`, per `orchestrate-dev.js:10037-10044`)
   and assert the accepted set by set-equality over the six rows.

The three Mediums (F-05 citation, F-06 unstated BR-16 reading, F-07 provisional discovery predicate)
and the Low (F-08 traceability granularity) should be addressed in the same pass but do not
themselves gate.

Nothing in §2, §3.1–§3.2, §4.3's metric arithmetic, §5 or §6.5 needs to change. The reuse decision,
the seam design, the fail-closed halt mapping and the read-only proof are all product-faithful as
they stand.
