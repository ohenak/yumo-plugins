## Positive Observations

- **AT-14b is the fix the finding asked for and one better.** It could have been satisfied with any two-halt fixture; instead it takes a real archived directory whose four post-mortems I re-verified on disk, asserts the *sequence* rather than the set, states plainly why ("an implementation ordering by directory-listing or insertion order passes any set-shaped oracle"), and then adds the `P` / `PR` leg so that the very case BR-13 cites as its reason for naming a collation is itself asserted. A rule that justifies itself by one example and a test that pins that example is a closed loop.
- **AT-15's skippability clause anticipates a failure mode that usually only surfaces in CI.** Marking the symbolic-link leg as the sole skippable one, and requiring the enumeration and removal-probe legs to run with a regular file in that member's place, prevents the ordinary outcome of a platform guard: a `skipif` at test scope silently taking BR-14's only set-equality oracle with it on Windows. Very few FSPECs think one level past the skip.
- **AT-25 and AT-23 both converted from relational oracles to transcriptions in the same round.** "The other five rows carry their measured indices unchanged" became `3`, `2`, `5`, `1`, `4`; "a caller can distinguish" became a three-key set-equality with `error.reason` exactly `not_found` plus a same-run comparison against AT-26's empty directory. Both changes state their own reason inline, so the discipline travels into TSPEC with the test.
- **D-9 and §7.3 route the REQ conflict rather than paper over it.** The FSPEC decides the better behaviour (a root failure, not a re-spelled not-found), records why REQ-STATS-09's *Given* sweeps the case in, and raises the wording as an erratum instead of quietly narrowing a P1 criterion. Same for BR-27's narrowing of REQ-STATS-07's "as missing". Two disagreements with upstream, both visible, neither hidden in a rule body.
- **BR-20's rewrite states the rot it defends against.** "The rule is stated as always-but-one rather than path-by-path because the enumeration is what rots" is the right instinct; F-01 exists only because the document already contains the path the new rule did not enumerate, which is the argument's own evidence.

## Recommendation

**Needs revision**

One open High finding. Everything I blocked or flagged in v2 is resolved, and resolved at the level of a rule or an oracle rather than a wording patch — AT-14b, AT-25's literals, AT-23's key-set equality, AT-13's temp-root fixture clause and AT-15's skippability rule are each stronger than what I asked for. The revision broke nothing I had approved: I re-measured every real-path literal this round touches (`POSTMORTEM-{D,F,I,T}` in `pdlc-headless-engine`, `doctor`'s flag row at `cli.mjs:184`, `FLAGS_BY_COMMAND`'s membership) and they hold.

The block is a hole this round's own widening opened. BR-20 now guarantees a JSON document on every path but a usage error, and BR-30 now closes the error shape to two `reason` values — but EC-11's single-feature exit-1 path is a third path, so the two rules cannot both be implemented, and AT-27's single-feature half asserts nothing about stdout there. That is a machine-facing contract with no transcribable oracle, and it is one clause to fix in BR-30 plus one conjunct in AT-27 (F-01). While that edit is open, F-02's missing `feature` conjunct on the D-9 path sits in the same AT and should land with it. F-03 is independent: EC-21's credit moved to an AT that tests a narrower condition, so the catch-all degradation still has no test. F-04 and F-05 are single-clause corrections.
