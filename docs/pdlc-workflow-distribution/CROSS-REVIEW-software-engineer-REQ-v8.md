## Positive Observations

- **Every v7 finding was answered on its merits, and two of the answers are better than what I asked for.** AC-1.2's four-row reason→condition→remediation table makes the plugin/consumer symmetry checkable in one place instead of inferable across five ACs, and AC-0.1's single union rule (`{row ids} ∪ {retired basenames}` pairwise distinct *and* charset-conforming) replaces three narrower rules with one that provably has no hole in the filename-interpolation position. AC-3.4 now cites both halves of it as the reason its grouping key is well-defined.
- **§0 fact 14 continues to re-derive.** I re-ran the printed four-pattern grep at `HEAD`: 28 hits (v7's block recorded 27 and predicted the growth), and after the exemption **rule** the covered set is byte-for-byte the same five files the REQ names. The measurement/invariant separation introduced in v7 is holding across revisions, which is exactly what four hand-maintained lists failed to do.
- **AC-2.8's `in-sync` row is the right correction, and for the right reason.** Scoping "not reachable" to `generatedBy: "sync"` — rather than to the condition — recovers the feature's most common configuration (all rows `in-sync`, legacy `.js` still on disk) as a first-class fixture with an expected string, and the per-surface `supersedingState` measurement table in AC-2.6 makes the resulting surface-specific golden outputs a stated consequence instead of a discovery.
- **AC-6.5's "Invariant it proves" row is the kind of clause that survives implementation pressure.** Naming *the bootstrap works against the code in this checkout* as the invariant, and recording both failure modes of the rejected `git clone` design, means an implementer who repoints the fixture has to argue against a stated invariant rather than silently satisfy a mechanism. F-05 is a residual on the same row, not a reversal of it.
- **`plugin-artifact-unreadable` closed the loop on remediation correctness.** Four `unknown` reasons, all blocking the queue and exiting 3, differing *only* in the remediation — with AC-2.5 requiring all four to be distinguishable in the output and AC-4.2 printing them in level-separated blocks — is a genuinely testable operator contract, and it is the first revision in which no `unknown` row points at a command that cannot fix it.

## Recommendation

**Needs revision**

Must change before FSPEC:

1. **F-01** — decide and state who creates `.claude/workflows/` for the non-sync writers. As written, the hook's mandated drift-state write (AC-2.4/AC-2.6) has no defined target on the fresh-consumer population, and AC-0.3b's only documented interim escape is unreachable because the flag travels through a file that is never created.
2. **F-02** — add write-failure paths: delete conditional on a verified backup (AC-3.9), an IO-failure outcome in AC-3.3's exit table and in the drift state file, and stated partial-copy behaviour for AC-3.1. Backup-then-unconditional-delete is a specifiable path to the exact loss AC-3.9 says it exists to prevent.
3. **F-03** — replace "readable parent/directory" with traverse permission (`[ -x ]`) wherever the operation is *path resolution* (AC-1.1's ancestor walk, AC-0.5 step 1(b), AC-1.0's `plugin-root-unreadable`). Measured on this platform, the current predicate mis-classifies `--x` (absence establishable, reported `unknown`) and `r--` (file present, reported `missing`) in opposite directions.
4. **F-04** — qualify AC-1.8(i)'s four-value mapping table against (ii)'s precedence, or add the dominating `unknown` rows; the cell `{hash tool absent} × {pluginPath absent} × {parent-absent}` currently has two correct answers.
5. **F-05** — state the fixture source precisely (`--cached --others --exclude-standard`, or the `git add` precondition) and how the non-executable copied script is invoked; otherwise AC-6.5's RED phase fails for a reason unrelated to its assertions, which is the failure the row was rewritten to remove.
