## Positive Observations

- **AC-2.9(2a) is the right shape even though F-01 is a residual on it.** A ladder ordered by the *permission each step needs* — `unlink` (directory write) then `O_TRUNC` (file write) — with the common real-world failure (a directory that turns read-only while its files stay writable) explicitly identified as the one step 2 exists for, and with no new queue rule required because AC-4.1 row 1 already blocks on `schemaVersion != 1`, is a genuinely economical fix. Three falsifying tests are mandated, including the residual case. My F-01 is about which AC-4.1 row the sentinel lands on, not about the mechanism.
- **The `readBytes_hash` / `readBytes_json` split is the correct generalisation, stated generally.** Naming the rule (`readBytes_R(p)` = "the reader this artifact is actually read by exits `0`"), requiring every call site to name `R`, and then observing that the two readers fail *independently* in both directions (hash absent ⇒ baseline `resolved`, all rows `hash-tool-absent`; JSON absent ⇒ `unresolved`, no rows) is what makes NFR-5's degradation matrix a two-dimensional claim rather than a sentence. F-02 is about the implementation form of one of the two, not the split.
- **The `3` / `4` exit-code boundary is now stated as a *fact about the world*, not a code path.** "Exit `4` means we tried to write and could not" versus "no write target" is the kind of distinction that survives refactoring, and v10 propagates it to all six places that encode it (AC-2.4's new two-row table, AC-2.6, AC-2.9(2), AC-3.3 row 1 + derivation, AC-3.8's population row 3, AC-4.1 rows 1 and 3, §4's exit-code row) rather than fixing the one row that was flagged.
- **Classify-then-create is argued from what would go *silently* wrong, not from taste.** Noticing that a create-first order leaves AC-6.5 green while making its stated invariant chain false — "the assertion still passes, because the state is `missing` either way, but it passes for a different reason than the AC gives" — and then mandating an assertion on the *written drift state file* so the order is pinned rather than inferred, is exactly the falsifiability discipline AC-1.1's ancestor rule was rewritten for.
- **Both v9 High measurements were reproduced without correction.** `git update-index --chmod=+x` ⇒ index `100755` / worktree `-rw-r--r--` / exit `126`, and a commitless `git init -q` satisfying AC-0.5 step 1 — both exactly as v10 states, including the corrected error code. Dropping `add -A && commit` while naming the `-c user.name=… -c commit.gpgsign=false` form for any future need is the right way to close a measured finding without losing the reason it was raised.
