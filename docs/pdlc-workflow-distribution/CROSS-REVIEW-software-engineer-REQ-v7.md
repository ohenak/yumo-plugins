## Positive Observations

- **AC-0.5 step 1 is now correct and, unusually, provably so.** `git worktree list --porcelain`'s first record is a work tree by construction, and check (c) re-derives it through an independent command, so the submodule and `--separate-git-dir` layouts that defeated v6 cannot be accepted. Pairing that with "inside a git repo, a failure goes straight to `repo-root-unresolved`, never to the walk" — justified by the same *a wrong root is worse than a refusal* argument that already justified the `$HOME` rejection — makes the three degraded-git cases (absent / too-old / bare) each have exactly one stated answer, all three declared as required fixtures. The minimum version is right: `git worktree list --porcelain` is 2.7.0, not 2.31.
- **§0 fact 14 is now mechanically re-derivable and I confirmed it byte-for-byte.** Pasting the real 27-line `git grep -l` output *and* recording that the output is expected to grow by a line or two per review round while the *difference* is what AC-6.4 asserts is the correct separation of a measurement from an invariant. Four revisions of a hand-maintained list ended here.
- **AC-6.4's answer to F-01 is better than the one I asked for.** I asked for an exemption rule; v7 ships the rule *and* moves the RED/GREEN fixtures out of the work tree entirely, and then states why neither alone is sufficient — the untracked-fixture door (`git ls-files` discovery ⇒ the RED case passes proving nothing) and the tracked-fixture door (permanently red repo-root assertion) are named as two distinct failures with one mechanism each. The `**/__tests__/**` rationale — *fixtures are inputs to the oracle, not instructions to a reader* — is the sentence that makes the rule non-arbitrary.
- **The `retiredPresent: { path, supersededBy, supersedingState }` shape is the right structural fix.** Conditioning the remediation on R's state is only assertable if R's state is *in the artifact the golden test reads*; carrying it in the drift state file rather than recomputing it in the message is what makes AC-4.2's report a pure function of the file. The derivation of why plain sync cannot clear `retire-skipped` for an R in `local-edit` (AC-3.9's guard re-runs, retires nothing, AC-4.1 row 7 blocks again — a non-converging loop) is stated from the failure, not asserted.
- **NFR-5's "exactly two external tools" correction is the kind of consistency defect specs normally carry to implementation.** Declaring `git` as the third tool *and* distinguishing it as the one whose absence is not a correctness degradation (step 1 simply does not apply; AC-3.9's tracked-path detection is already best-effort) is more precise than the two ACs that motivated it.
