| F-03 | High | Cross-Feature | **The `stale` / `local-edit` discriminator is mtime-based and therefore nondeterministic — the two states cannot be reliably distinguished by any test.** AC-1.1 defines `local-edit` as "consumer differs **and the consumer's copy is newer**". mtime is not content, which also contradicts NFR-1 ("content hashing and file comparison"). A fresh `git clone` or a `git checkout` stamps every file with checkout time, so ordering is an artifact of clone sequence, not of authorship; CI will classify the identical byte-state as `stale` or `local-edit` depending on which tree was materialised first. A test can only pin this by fabricating mtimes, which pins the fixture rather than the behaviour. A deterministic discriminator is required — e.g. a sync manifest recording the hash last written by sync: `consumer == manifest` → `stale`, `consumer != manifest` → `local-edit` — plus an explicit AC for the **no-manifest** case (first run on a repo that has never synced), which is the common case and currently unspecified. Until this lands, AC-2.3 (the "do not recommend sync" safety branch) has no falsifiable trigger. | REQ-DIST-01 AC-1.1; REQ-DIST-02 AC-2.3; NFR-1 |
| F-04 | High | Local | **The queue-integration state table is incomplete, and the bootstrap self-reference is unaddressed.** AC-4.1 names an outcome for exactly one of six states (`stale` → `blocked`). Behaviour is unspecified for `missing`, `local-edit`, `unknown`, `not-managed`, and `in-sync`-with-`unknown`-siblings. `missing` in particular is arguably more severe than `stale`, and AC-1.2's whole point is that `unknown` must not be treated as `in-sync` — yet at the queue seam it silently is. I cannot write the queue integration test matrix from this. Separately: the queue runs *from* the possibly-stale artifact, so the drift check can only exist in versions that already contain it — a stale consumer will never report itself stale via AC-4.1. No AC acknowledges the bootstrap gap or names the independent path (the SessionStart hook, which ships from the plugin, not the copy) that covers it. | F-05 | Medium | Local | **AC-3.4 is self-contradictory: a recorded hash cannot recover content.** The AC permits "backup **or** a recorded hash sufficient to recover", and states the purpose as making an unintended `--force` overwrite *recoverable*. A hash is a one-way digest; the hash-only branch satisfies the AC's letter and defeats its stated purpose, and a test written against the AC as worded would pass on an unrecoverable implementation. Drop the hash alternative and specify: backup location, naming, whether it is overwritten on repeat syncs, and retention. Add a falsifying AC — "Given `--force` overwrote a `local-edit`, When the backup is restored, Then the file is byte-identical to its pre-sync content" — since restore is the only oracle that cannot be false-greened. | REQ-DIST-03 AC-3.4 |
| F-06 | Medium | Local | **No property-based strategy for the drift classifier, which is a textbook parameterisable component.** Its input space is a small product — {plugin bytes present/absent, consumer bytes present/absent, equal/unequal, manifest present/absent} — mapping to one of six states. ACs 1.1–1.5 are five examples over that space; example coverage of a classifier is a Medium by project standard. The REQ must state the invariants the tests will hold, because they are requirements, not test detail: (i) **totality** — every input combination yields exactly one state, no undefined fall-through; (ii) **mutual exclusivity** — the six states are disjoint; (iii) **determinism** — same inputs, same state, repeated (this is what NFR-1 actually asserts and nothing currently tests); (iv) **convergence/idempotence** — `sync` then `sync` is a no-op, and AC-3.5 only covers a single round for files that were copied, not files skipped as `local-edit` or `not-managed`. | REQ-DIST-01; NFR-1; AC-3.5 |
| F-07 | Medium | Local | **NFR-2 is not measurable as written and will produce a flaky gate.** "Under 500 ms" states no input size (how many managed scripts? the bundles are 92 KB and 120 KB — hashing cost scales with them), no host baseline, no percentile, and no cold-vs-warm-cache condition. Either restate as a budget against a fixed fixture (e.g. "≤ N scripts totalling ≤ M bytes, p95 on the CI runner") or demote it to a non-gated observation and say so, so no one writes a timing test against it. | NFR-2 |

## Positive Observations

- AC-1.2 states the right instinct explicitly ("Absence of evidence is not evidence of sync") — that is the correct oracle discipline for a detector, and it should survive into the FSPEC verbatim. It just needs the hook-side AC (F-09) to actually hold.
- AC-1.5 / NFR-3 protecting repo-local workflows from the sync path is a real destructive-operation guard, and the rationale paragraph after AC-1.5 makes the negative case concrete enough to test.
- NFR-4 (detection automatic, modification always explicit) is a clean, testable separation and it is consistently honoured by REQ-DIST-02 and REQ-DIST-03.
- NFR-1's "no LLM in the check path" makes the whole feature deterministically testable — a rare and valuable property for this pipeline.
- AC-2.4 (hook must never block a session) is the correct fail-open choice for a warning-only hook and is directly testable by fault injection.

## Recommendation

**Needs revision**

Blocking changes required before FSPEC:

1. Resolve the managed-artifact identity (F-01) — name whether bundles are in scope, and if so define "in-sync" for a generated file and state how the build reaches a consumer.
2. Fix the plugin-source path and add resolution ACs for the installed layout and the multi-version cache (F-02).
3. Replace the mtime-based `local-edit` discriminator with a deterministic one and specify the no-manifest first-run case (F-03).
4. Complete the queue-integration state table for all six states and state the bootstrap boundary (F-04).
5. Repair AC-3.4 (F-05) and add the restore-is-byte-identical criterion.
6. Add the classifier invariants — totality, exclusivity, determinism, sync idempotence (F-06).
7. Make NFR-2 measurable or explicitly non-gated (F-07).
8. Specify version-stamp location, scheme, missing-stamp behaviour, and hash-vs-version precedence (F-08).
9. Specify hook behaviour for `unknown` (F-09).
