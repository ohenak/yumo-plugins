## Positive Observations

- **AC-2.9(2a) is the strongest single addition in this document's history, and it is written as a *permission* argument rather than a procedure.** Step 2 exists because `O_TRUNC` on an existing file needs write on the *file* while `unlink` needs write on the *directory*, and the common real failure — a directory that goes read-only while its files stay writable — is covered by step 2 alone. Reusing AC-4.1 row 1's existing `schemaVersion != 1` block for the `{}` sentinel means the fix adds no queue rule and no new queue input. Three falsifying tests are mandated, one per rung. That is a remediation that comes with its own falsifying tests, which is the discipline the oracle-falsifiability checklist asks for and rarely gets.
- **`readBytes_R` is the right generalisation of my v9 F-01, not a point patch.** Splitting the probe would have closed the finding; stating "the reader `R` that this artifact is actually read by" and then requiring every call site to name `R`, plus the explicit both-directions independence claim (hash absent ⇒ `resolved` + all rows `unknown`; JSON absent ⇒ `unresolved`/`json-tool-absent` + no rows), closes the whole class and gives NFR-5 two separable fixtures.
- **The *attempted vs no-target* distinction is applied at all seven sites, not just the one I cited.** AC-3.3, AC-4.1 (both rows), AC-2.4 (as a new two-row table with per-surface exit codes), AC-2.6, AC-2.9(2) (as an explicit negative clause), AC-3.8's population row and §4's exit-code row. Every one of them now yields the same expected value for the same fixture; that is the property I could not assert in v9.
- **The `add -A && commit` removal is a measured simplification of the feature's only end-to-end oracle.** Naming the two failure modes it removes (no git identity on a container, `commit.gpgsign`) and pre-committing to the `-c user.name=… -c commit.gpgsign=false` form should a commit ever be needed is exactly the right level of foresight for a fixture that gates the bootstrap.
- **AC-1.1a's uid-0 table now distinguishes the two kinds of test and names what root cannot verify.** "Filter, do not skip", the reason printed once, and the three named unverified invariants means a filtered CI run reports its own coverage hole instead of quietly shrinking the state space.
