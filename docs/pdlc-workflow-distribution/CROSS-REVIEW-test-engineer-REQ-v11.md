## Positive Observations

- **The record-first ladder is a better mechanism than the one I reviewed, and it is argued from the permission bit rather than asserted.** Making the invalidated file a *schema-valid record* rather than an absence, so it lands on AC-4.1's `unresolved` row instead of its absent row and leaves the `checkEnabled` row reachable, converts a permanent unescapable block into an announced one — and mandated test (d) is exactly the falsifying test that argument needed. The remaining defect (F-01) is in which rung is reachable, not in the shape of the fix.
- **Retracting the `pdlc/hooks/scripts/*.sh` citation is the right kind of correction.** v11 went back to HEAD, found that the shipped loop is interpreter *discovery* reading no path and that the one shipped read is `json.load(sys.stdin)` under a bare `except Exception`, said so with line numbers, and forbade reusing it. A REQ that names its own earlier citation false is doing the verification work the checklist asks for; the nonexistent-authority pattern has shipped in this repo before.
- **AC-6.5 now separates the state assertion from the ordering oracle and says which is which.** "AC-6.5 keeps its state assertion as well … but that one is *not* the ordering oracle and is not claimed to be" is the sentence that stops a future reader from treating a passing green as proof of the order. The oracle it picks is the cheaper one and it is stated once, in one place, with two other ACs citing it rather than restating it.
- **The uid-0 rule is now a predicate with a checklist, not an enumeration.** "If removing a permission bit is what makes the fixture's expected outcome differ from the all-permissions outcome, this rule applies" is total by construction and survives the next AC that adds a `chmod` fixture — which is what my v10 F-04 asked for and more than it asked for.
- **Axis 2 of AC-1.8(iv) is justified from this repo's own hazard.** Recording that the only verification surface *is* a marker-present tree and that AC-6.5 builds fixtures by copying it, so `plugin-root-unset` would never have been generated at all, is the kind of fixture-provenance reasoning that keeps a property test from silently shrinking its own space.

## Recommendation

**Needs revision**

Blocking changes before FSPEC:

1. **F-01** — resolve the ladder's reachability. Under AC-2.6's temp-sibling+`mv` replace, every world
   that reaches the ladder has an unwritable directory, so step 2's `unlink` cannot succeed and test
   (b)'s fixture never enters the ladder. Re-derive the rungs, change the primary write, or delete
   step 2 — and give whichever rungs survive a satisfiable fixture each.

   runtime adapter's; NFR-5 puts the classifier in bash. Name the bash tracing/shim mechanism (and do
   the same for AC-0.5 step 2's injected-`traverse` oracle) or the P0 ordering has no oracle again.

   {marker present, repo root unresolved}.

   overlap fixture for `drift-state-invalidated`'s top-of-precedence claim.

   skip row, which now hides the whole invalidation ladder and the escape-hatch proof.
