| F-14 | High | Local | **AC-1.8's totality property is unsatisfiable against AC-1.1's state table — the property test cannot be written to pass.** AC-1.8(i) declares the input space includes `plugin bytes present/absent`, but AC-1.1's seven-state table contains no state for *"manifest row exists, baseline resolved and readable, but `pluginPath` is absent or unreadable"*. `unknown` is scoped by AC-1.2 to the **baseline** being unreachable, not to an individual row's plugin-side file; `missing` is defined solely as `consumerPath absent`; `not-managed` is defined by the *absence* of a manifest row, which is the opposite case. This is not hypothetical: it is exactly what a truncated/partial plugin install or a manifest row that outlived its artifact produces, and it is the state that would occur today if the manifest shipped before AC-6.1's `dist/` output existed. A property test asserting "every input combination maps to exactly one of the seven states" fails by construction; a test author's only options are to weaken the property (defeating its purpose) or to invent a state the REQ does not authorise. Either add an eighth state (e.g. `plugin-missing`, and say where it lands in AC-3.3's exit precedence and AC-4.1's queue precedence — I would expect `blocked` / exit 3, since it means nothing was verified for that row) or narrow AC-1.8(i)'s declared input space and add an explicit AC stating that a manifest row whose `pluginPath` is absent is a packaging defect handled as `unknown` with its own reason code. Silence here also leaves AC-3.1's copy loop undefined for that row: it is in neither the copy set nor the skip set. | REQ-DIST-01 AC-1.8(i) vs AC-1.1, AC-1.2; AC-3.1 |
| F-15 | High | Local | **AC-4.1's first precedence row has no falsifiable trigger — the queue cannot observe "the current session start".** The row *"drift state file … older than the current session start → `blocked`"* is the fail-closed guard that stops a queue run against a state file left over from a previous session. But NFR-1 is explicit that the workflow runtime has no `fs` and no `process`, that all IO arrives through `runtime-adapter.js` as `agent()` calls, and that the queue performs **one** injected read of the drift state file and "makes no classification decision". Nothing in the REQ names a source for the session-start instant: it is not in the drift state file schema (AC-2.6 carries `generatedAtUtc` only, i.e. the *other* side of the comparison), not a second injected read, not a queue parameter, and not in §4's table of configured values (which per its own preamble forbids ACs citing values absent from it). A test author cannot construct the RED case — there is no input to vary — so the branch would ship as either dead code or a guard that always passes, which is the "test that can only pass, never fail" failure mode. Fix by making the freshness signal an input the test can set: e.g. have the hook write a per-session token/nonce into the drift state file that the queue receives through an existing injection point, or drop the freshness clause and rely on AC-2.6's guarantee that the hook rewrites the file at every session start (in which case say so, and state what happens when the hook did not run at all — currently only "absent / unparseable" is covered). Also reconcile the wording: comparing timestamps *is* a classification decision, contradicting NFR-1's claim that the queue makes none. | REQ-DIST-04 AC-4.1 (row 1); NFR-1; AC-2.6; §4 |
| F-16 | Medium | Local | **`not-managed` is unproducible under AC-0.1 as written, and if it is producible the four state files pollute every report.** `not-managed` (AC-1.1, AC-1.5) is defined by *"a file in `.claude/workflows/` with no manifest row"* — detecting it requires enumerating the consumer's `.claude/workflows/` directory, yet AC-0.1 declares the manifest the "**sole** enumeration authority" and states "Directory globbing of `workflows/` is prohibited" without scoping that prohibition to the plugin side. A test author cannot tell whether the check must list the consumer directory. If it must, §4's closing sentence ("All four consumer-side state files live under `.claude/workflows/` and are `not-managed` by definition") means every report and every `--check` run enumerates `.pdlc-sync-manifest.json`, `.pdlc-drift-state.json`, `.pdlc-backups/` and `.claude/pdlc.config.json`(sic — §4 places that one at `.claude/`) as `not-managed` rows — including the drift state file listing itself, whose content changes on every run, making AC-3.7's "leaves the sync manifest byte-identical" and any golden-output assertion self-referential. Decide and state: (a) is the consumer directory enumerated at all, (b) if yes, what exclusion rule keeps `.pdlc-*` state files and the backup directory out of the reported rows, and (c) does `not-managed` appear in the drift state file's `rows` array (AC-2.6) or only in human-facing output? Each answer changes the test fixture materially. | AC-0.1 vs AC-1.1/AC-1.5; §4 closing paragraph; AC-2.6 |

## Positive Observations

- §0 Grounding is the right response to F-12: measured hashes, named paths, a superseded premise explicitly withdrawn. Every subsequent AC that cites a fact cites a number a reviewer can re-derive. This should survive into the FSPEC as the fixture spec.
- AC-1.6/AC-1.7 replacing mtime with a sync manifest, plus the new `unverified` state, is exactly the deterministic discriminator F-03 asked for — and routing the no-provenance case to a *distinct, always-surfaced* state rather than defaulting it into `stale` or `local-edit` is the safe choice in both directions.
- AC-3.3's precedence table with "highest applicable code wins" and the explicit gloss "exit 0 asserts every managed row was compared against a resolved baseline and matched" turns AC-1.2 into an enforceable exit code. That is a falsifiable oracle, not a slogan.
- AC-3.5 (restore ⇒ byte-identical) is the correct un-false-greenable oracle for the backup requirement, and AC-3.6/AC-3.7 give convergence and idempotence as first-class criteria rather than leaving them to the test author.
- REQ-DIST-04's preamble stating that the queue check is secondary and cannot be relied on for first adoption is a genuine boundary declaration — it stops the test suite from pretending AC-4.1 is total coverage.
- NFR-2's "no test asserts wall-clock time … anyone tempted to write a timing test should read this clause" is the clearest possible way to prevent a flaky gate.
- §4's single table of every configured value with location, default and owner removes an entire class of "a test cannot set the flag it asserts on" findings.

## Recommendation

**Needs revision**

Blocking changes required before FSPEC:

1. **F-14** — close the totality hole: define the state for a manifest row whose `pluginPath` is absent/unreadable, and place it in AC-3.3's exit precedence and AC-4.1's queue precedence, or narrow AC-1.8(i)'s declared input space to match the table.
2. **F-15** — give AC-4.1's freshness guard an observable input the test can vary, or remove the clause and specify the "hook did not run at all" case instead.
3. **F-16** — resolve the AC-0.1 glob prohibition against `not-managed`'s consumer-side enumeration, and state the exclusion rule for the four `.pdlc-*` state artifacts.
4. **F-17** — state how `yumo-plugins` itself behaves under its own check, so AC-3.3 exit 0 and AC-2.2 silence are reachable on real inputs.
5. **F-18** — fix the single writer contract for `.pdlc-drift-state.json` and say whether a sync refreshes it.
6. **F-19** — supply a pre-release, in-CI oracle for AC-6.2's packaging guarantee.

Low findings F-20–F-22 should be folded into the same revision but do not independently gate.
