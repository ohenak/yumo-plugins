## Positive Observations

- **AC-2.9 answers both v8 High findings with one AC, and it decides rather than defers.** Naming the chosen reading (*read-only surfaces create the directory*), tabulating the rejected alternative with the three concrete consequences that killed it, and then arguing that the resulting queue block is *correct* rather than spurious ("the runtime loads bundles from that directory, so a repo where it cannot exist cannot host this pipeline") is the shape of specification that survives implementation pressure. F-01 is a residual on its interaction with AC-4.1, not a reversal of it.
- **AC-1.1a is the right abstraction and it is placed where it can be cited.** Four probes, each with a `test` form, one composite (`established-absent`), a measured table of the `0111`/`0444` divergence with the opposite-direction consequences named, and every downstream axis-value name restated in that vocabulary. I re-derived the upward-ancestor walk under the new probes and it is self-consistent: a path under an untraversable ancestor reports `¬exists`, so the walk's "first existing ancestor" is exactly the untraversable directory the rule wants to test. That is the first version of this rule in nine that does not need a reader to reconstruct it.
- **AC-2.9(3) picks re-read-and-compare for a stated reason.** "Because a short write on a full filesystem can exit `0`" is the correct justification for not trusting an exit code, and noticing that AC-3.5's restore oracle already mandates the same comparison — so the rule needs no new mechanism — is the kind of reuse argument that keeps a spec from growing a second verification path.
- **The reason-precedence work is symmetric and honest.** A *declared* precedence rather than "first failure encountered" (correctly identified as an artefact of code order and not assertable from outside), a rationale in remediation order, an explicit note that it is evaluated only after the state is `unknown`, plus AC-1.8(iv) so the property suite asserts it against the generated overlap. F-03's request is to apply the same treatment one level up, at AC-1.0.
- **§0 facts 15 and 16 are both real and both load-bearing.** I re-ran them: all three sibling scripts are `100644`, `hooks.json` invokes three bare paths, and `build-runtime.mjs:23-25` imports `fs`/`path`/`url` and nothing else. Fact 15 also surfaces a pre-existing latent defect in shipped hooks and fixes the class rather than the instance, which is the right call even though F-02 shows the mandated mechanism does not yet reach the worktree.

## Recommendation

**Needs revision**

Must change before FSPEC:

1. **F-01** — reconcile AC-2.9(2) with AC-4.1's "No freshness clause". A failed drift-state replace over a pre-existing file yields *proceed silently* at the queue seam on stale data; AC-4.1's justification paragraph is currently false of AC-2.9. Either invalidate the old file when it cannot be replaced, or add a queue-visible input.
2. **F-02** — mandate the **worktree** execute bit, not only the index mode (or build AC-6.5's fixture from the index). Measured: `git update-index --chmod=+x` leaves the file `-rw-r--r--`, so the `git ls-files -s` pin passes while the bare-path invocation exits 126. Fix fact 15's error code while you are there.
3. **F-03** — parameterise `readBytes` by the reader (the manifest is read by the JSON tool, not the hash utility) and declare a precedence over AC-1.0's seven manifest-level reasons, which v9 just gave an overlap without one.
4. **F-04** — give `writeFailures[].operation` a closed value set and either define or delete `stage`; both are printed to the operator and read by the queue with no domain and no oracle.
5. **F-05** — drop AC-6.5's `add -A && commit` (measured: `git init` alone satisfies AC-0.5 step 1 (a)–(c)) or pin identity and `commit.gpgsign=false`; as written the only end-to-end bootstrap oracle can fail on a container or a signing config for reasons unrelated to its assertions.
