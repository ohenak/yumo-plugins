## Positive Observations

- **AC-1.1a is the single most valuable addition in this document's history for a test author.** It does not merely define the predicate I asked for — it *measures* both error directions on a real fixture (`chmod 111` → `[ -r ]` false but absence establishable; `chmod 444` → `[ -r ]` true but a present file reports absent) and names the second as a silent-overwrite path through the very state `missing` was narrowed to prevent. That is a spec paragraph that pre-empts a bug class rather than describing a convention.
- **AC-1.8 clause (iv) is the correct generalisation, not a minimal patch.** "Asserted against the *generated* overlap rather than against a hand-picked example" is exactly the discipline that makes the reason precedence falsifiable, and pairing totality (`reason: null` for every non-`unknown` state) with single-valuedness closes both halves in one clause.
- **AC-2.9(3)'s verify-before-destroy rule is stated as a property, with the reason the obvious implementation is insufficient** ("a short write on a full filesystem can exit `0`"), and it reuses AC-3.5's existing restore oracle rather than inventing a mechanism. Permitting `mv` while naming why it needs no verification shows the property, not the procedure, is the requirement.
- **AC-6.5's Isolation row is now a buildable script.** Three numbered steps, a stated reason for each (`--others --exclude-standard` for the RED phase, `git init` for AC-0.5 step 1, mode preservation for the bare-path invocation), plus the `realpath` and `HOME`-outside-the-fixture rows. I could write this test today without asking a question about the fixture itself.
- **AC-3.8's population table decides the case rather than deferring it**, and grounds the refusal in AC-0.5's own "a wrong root is worse than a refusal" argument with the one-command remediation named at AC-2.5a. That is the second time this document has answered a reachability question by narrowing scope to what is actually true instead of deleting the claim.
