## Positive Observations

- **The ladder was re-derived rather than defended, and the measurements are in the document.** `mv` over a `chmod 444` file in a writable directory succeeding is the fact that killed v11's test (b), and putting all three measurements in a table next to the conclusion — "every world reaching the ladder through a *permission* failure has an unwritable directory, the bit `unlink` needs, so step 1 covers the whole permission space" — is what makes the re-scoping of step 2 to `ENOSPC`/immutable/directory-at-the-path an argument instead of a preference. Keeping the rung with a declared fault seam, and *arguing* that choice against deleting it and against an uninducible real trigger, is the right disposition of a rung with no cheap fixture.
- **Renumbering `readBytes_json` out of CPython's reserved range is a small change with a real failure mode behind it.** The reasoning is the strong part: exit `2` collided with the interpreter's own usage exit, so a stubbed or shadowed `$PY_BIN` produced the one outcome that is permission-derived and therefore *already skipped at uid 0* — invisible on both runners. Also checking the new codes against `sync-workflows.sh`'s own `0`–`4` is the kind of second check that usually gets skipped.
- **Test (e) is the right shape for a precedence claim.** A top-of-precedence member excluded from the property generator's codomain had its ordering asserted nowhere, and every isolated fixture would also pass an implementation that reported the upstream reason. Choosing `manifest-malformed` for the overlap *because it reaches the writer* (unlike `repo-root-unresolved`, which has no write target) shows the codomain was reasoned over, not sampled.
- **The uid-0 skip row now names its cost once, and the coverage floor is scoped to a non-root runner.** Declaring the 85% branch floor asserted on a non-root runner only — with the reason (the skipped set *is* the write-failure branch set) and the dependency recorded on D-DIST-06 — converts a number that would have quietly dropped into a stated prerequisite.
- **Superseded dispositions keep being annotated in place.** SE v10 F-02/F-04/F-07 and TE v10 F-01/F-07 all carry "(superseded at v12 …)" notes rather than being rewritten, so §10 remains a history at twelve revisions.

## Recommendation

**Needs revision**

Must change before FSPEC:

1. **F-01** — scope the trace-ordering assertion to one classification invocation and make the property computable from the trace grammar. As written, the only form the test can evaluate is red against a correct implementation of AC-6.5's own `sync` + `--check` block, and the intended form ("the last probe of the last row") cannot be recovered from `probe <kind> <path>` lines at all. This is the document's single oracle for a P0 ordering.
2. **F-02** — remove the third, unannounced exception to NFR-6: an unrecognised `PDLC_FAULT` token must not make the SessionStart hook exit non-zero. AC-2.4 says "for any reason", NFR-6 says "exactly two exceptions".
3. **F-03** — AC-0.5 step 2's oracle must assert observables that exist in the `repo-root-unresolved` state (the AC-2.5a stderr line and `--check` exit `3`), and its fixture must be one in which step 2 actually runs — a git work tree routes a failed step 1(b) straight to step 3.
4. **F-04** — `pluginVersion` is a string from the consumer's plugin cache, not a number; either emit `null` in the `printf` fallback or state the quoting obligation, and correct the "four closed-domain scalars, nothing to escape" justification accordingly.
