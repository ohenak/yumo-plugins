## Positive Observations

- **The F-01 fix is argued in the direction that makes it durable.** The count-vs-set table does not just adopt multiset equality, it records *what each weaker form misses*, so a future reader who "simplifies" (a) back to a set comparison has to walk past the row naming the failure that reintroduces. Same construction on `assertPostCopyNarrow`, cross-referenced rather than restated.
- **F-02's fix went further than the finding required, in the right direction.** I asked for a phase per op; v2 additionally made the grammar rule *self-enforcing* — `parseTrace` throws in **both** directions, and `assertPhaseOrder` re-asserts it so a helper used without `parseTrace` cannot skip the check. The run-length collapse is the right formalisation of "never interleaved": I checked it against `[as-found, post-copy, as-found]` and it fails, which is what the prose claimed but v1's "drop the `run` records" phrasing could not deliver.
- **§5.2's closure argument for tokens 15/16 is the strongest paragraph added in v2.** It distinguishes "a guard inside the enumeration's stated granularity that was simply missed" from "a token per untestable branch", and then holds the line on the enumeration guard and the tool probes with the original reasoning intact. A weaker revision would have either widened the set silently or made §1.4's floor capability-aware; both were available and both were correctly rejected, with the reason (a root container is exactly where nobody reads a skip line) stated.
- **R-2's rewrite names the v1.0 claim as factually wrong rather than quietly restating it.** Combined with R-11's "closed, not accepted" and R-12's refusal to invent FSPEC message text, §17 is now an honest ledger — the residual section is doing the job residual sections usually fail at.
- **R-12 is the right call and is defended on the right grounds.** AC-5.3's rendered lines have no FSPEC string to match (§8.2's W-2/W-3/W-4/W-5 shapes name no version line), and V-4 asserts what *is* assertable — both record fields **present**, `null` permitted but absent not, which is a real discrimination. Declaring the rest residual with the trigger that would change the assessment beats manufacturing an assertion against invented text.
- **§7.4's `syncCommand` assertion is string equality with the two companion conjuncts**, and the reason is stated exactly right: `toContain` on the tail passes against the literal `${CLAUDE_PLUGIN_ROOT}/…` that is the failure being guarded. The W-5-agreement conjunct (the hook's own expansion is byte-equal to the record's field) catches a divergence nothing else in the suite would see.
- **§1.4a's negative-direction test is what makes the silence oracle real.** `expect(() => expectHookSilent(run)).toThrow()` over `staleRow` closes the "helper degraded to `return true`" hole that every silence assertion invites. Conjunct 5's construction is right in kind (see L-06 for the one-token strengthening).
- **§12.1's table now discharges O-19(b) for real**, and row 4's added validator constraint is flagged as a TSPEC test-design decision rather than smuggled in as an FSPEC reading — which is the honest way to handle a clause id the FSPEC's literal text would assign differently.
- **§6.1 note 4 keeps the wrong cell's history.** Recording *why* the v1.0 cell would have been believed rather than exercised (note 3 means the P column is unused) is the kind of annotation that stops the same error being reintroduced by someone tidying the table.
