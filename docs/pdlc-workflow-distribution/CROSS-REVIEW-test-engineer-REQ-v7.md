| F-01 | High | Local | **AC-2.8's new remediation table declares the feature's primary scenario "not reachable", and the same AC mandates warning in exactly that scenario two paragraphs later — so the most common `retired-present` warning has no specified remediation and its golden output is unwritable.** The table's last row reads: *`in-sync` → not reachable — the guard passed, so `p` was retired and is not present*. That is true only **after a sync run**. AC-2.8's surface is the **SessionStart hook**, which never copies and never retires; AC-3.3 row 4 likewise reports "any retired path present" at `--check`, which "copies nothing". A consumer whose managed rows are all `in-sync` (bundles already synced, or hand-copied) but which still holds `.claude/workflows/orchestrate-dev.js` is therefore both **reachable and universal at rollout** — and AC-2.8's own next sentence says so verbatim: "a consumer whose **every managed row is `in-sync`** but which still holds `.claude/workflows/orchestrate-dev.js` **is warned**, because §0 fact 8 makes that the exact configuration in which the runtime may execute the stale artifact". The AC thus requires clause (iv) ("names, **per path**, the remediation conditioned on R's state") for a state its own lookup table has no entry for. Consequences for the suite are concrete and in both directions: (a) the AC-2.8 golden-output test for the highest-value fixture (all rows `in-sync`, legacy `.js` present — the §0 fact 7/8 configuration, the one BL-05 is about) has **no expected string**, so it will be written as an absence-only oracle or dropped; (b) AC-4.2 defers to this table for a non-empty `retiredPresent`, and AC-4.1 row 7 blocks the queue in precisely this state, so the queue's blocking report also has no remediation for its most common block; (c) the natural implementation is a `case` on R's state whose `in-sync` arm is missing, which emits nothing — reintroducing the "warned about something else / warned about nothing" hole that AC-2.8 exists to close (TE v4 F-03).
