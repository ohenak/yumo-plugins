## Positive Observations

- **DEC-10 is the finding-response this document needed.** It does not merely record that a gap exists — it prices three options, names the one product question (is the capability's loss acceptable?), and puts it where product decisions belong. Option B's rejection is the strongest sentence in the revision: substituting a human ritual for a deterministic pass "would also hand PROPERTIES an unfalsifiable contract: no oracle distinguishes 'the human did the pass' from 'nobody did'". That is the right test to apply to a capability claim.
- **The owning-oracle column turns the decision table into a traceability instrument.** Three cells honestly read **None yet** (DEC-06, DEC-09, DEC-10) with the reason stated for each, rather than being filled with a plausible-sounding assertion. A reviewer can now see at a glance which decisions are witnessed and which are promises.
- **DEC-03's new paragraph anticipates a redundant fix.** Naming the two near-miss oracles — `mergeGuard.test.js`'s `assertDefaultsUntouched()` comparing against a `JSON.parse(JSON.stringify(...))` snapshot of the array itself (`:45`, `:48`), and `effectiveGuardPaths(undefined)` asserted `toEqual([...MERGE_GUARD_DEFAULTS])` (`:56`) — and identifying the real one (`consolidationRoute.test.js:106`–`:110`, a `new Set(...)` set-equality against the four literal members) is exactly the implementation-echo distinction the review bar asks for, recorded so nobody re-derives it.
- **DEC-08 now names the weak assertion instead of inheriting it.** `consolidationPreflight.test.js:208` really is `expect(postWavePathspecs).toContain("pdlc/workflows/dist/")` over a one-element array, and routing class 10 to tighten it to `toEqual([...])` applies C-6's set-equality-not-containment rule to the one place in the config surface where the shipped oracle was weaker than the rule.
- **DEC-09's "positive oracle required" paragraph found a real hole.** `advertisedVersionViolation()` returns `S_NOTHING_STAGED` when `git status --porcelain -- pdlc/workflows/dist/` is clean (`pdlc/workflows/lib/document-oracles.mjs:593`–`:596`), so it genuinely cannot witness the bump commit — and FSPEC class 9 edits that very check. Naming the replacement as a `satisfiesRange` call rather than a transcribed comparison keeps the assertion from becoming dead config.
- **Every re-verified anchor held.** Nine adapter cite sites, five tracked `dist/` entries, 119 `*.test.js` modules (L-5's 119 − 22 = 97 premise), `1209` lines / `56713` bytes for `runtime-adapter.js`, `306` + `203` = `509` test lines, `OPERATOR_ONLY_SKILLS` at `startup.mjs:52`, `satisfiesRange` at `handshake.mjs:93`, `0.23.1` against `^0.23.0`.
