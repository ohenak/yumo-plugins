| F-01 | High | Local | **§5.5's swept-surface table does not enumerate the surface its own membership rule defines: at least three more surviving `*.test.js` modules are edited by this sweep and are silently outside the join.** The rule is stated as "modules this sweep creates, deletes, reduces in place, or adds assertions to, plus any surviving host of an R-8 re-home", and the table then lists four members. But §2.8/§2.9 dispose of three further surviving modules as *edited in place by this sweep*: `pipelineWiring.test.js` (§2.9 class 7 — its `devMeta()` `DEV_META` comparison at `:543`–`:560` is deleted in the class-7 commit), `consolidationPreflight.test.js` (§2.9 class 7 for the `T00 — BL-PREREQ` block at `:99`–`:109`, **and** class 10 for `:205`–`:208`'s source-text expectations), and `documentOracles.test.js` (§2.9 class 9 — D-1/D-2 corrected with the CLAUDE.md prose they guard). All three exist in the tree today (`pdlc/workflows/__tests__/pipelineWiring.test.js`, `consolidationPreflight.test.js`, `documentOracles.test.js`) and all three survive the sweep. Under the stated rule each is in-surface; under the table each is out. The consequence is the exact defect AT-1.3 exists to catch: a bare `it.skip` parked in `pipelineWiring.test.js` while class 7 rips out the `DEV_META` assertions — the single most likely place in this sweep for an implementer to defer a broken assertion — is invisible to the oracle, and the oracle stays green. This is not a wording nit: §5.5's child invocation is specified as an **explicit file list** derived from this table, so the table is the executable domain, and erratum 10's requested FSPEC limb is the wider rule, not the narrower list — so the two will diverge further once it lands. Fix: either extend the table (and the child's file list) to the full set the rule names, or state per omitted module why an edit that deletes assertions is not "reducing in place" — and disposition `pdlc/engine/__tests__/ci-arrangement.test.js` (§5.3, corrected in the class-1 commit) explicitly as out-of-scope because it lives outside `pdlc/workflows/__tests__/` and outside the child run's glob, which is currently left to inference. | §5.5 (swept-surface table), §2.8, §2.9 |
| F-02 | Medium | Local | **The compensating source-level check reds on its own source text as written, and no falsifying construction is stated for it.** §5.5 part 3 specifies that the host asserts "no `it.skip`, `test.skip`, `describe.skip`, `it.todo` or `.skip.each` token appears in `consumerCleanup.test.js` outside comments". Those five tokens must appear *as literals in the scanning code itself*, which lives in `consumerCleanup.test.js` — the check therefore matches itself and fails on its first run, and the only carve-out stated is comments. Since this static check is the **sole** guard on the one module this feature writes from scratch (the host is carved out of the join precisely to stop recursion), the likely repair under time pressure is a weakened pattern rather than a stated one — the same silent-narrowing hazard the recursion paragraph is written to prevent. Fix: name the resolution rather than leave it to the implementer — put the token list in the fixture-side module or a helper outside the scanned file, or scan with tokens assembled at runtime, and state which. Then give the check its own falsifiability construction the way the join has one: run the same scanner over `__tests__/fixtures/skipJoinFalsifier.js` (which carries one bare `it.skip`) and assert it reports a hit, so a scanner whose pattern silently stops matching reds instead of passing vacuously. | §5.5 (recursion guard, part 3) |
| F-03 | Medium | Local | **The spawn-argument assertion is specified in a form that permits an implementation echo, and is not stated as a set-equality.** Part 1 says the exclusion "is asserted (the spawn argument list is compared to the derived surface-minus-host set)". If both sides come from one computation — the file list handed to `spawn` and the "derived surface" it is compared against — the assertion is tautological and cannot red on the re-widening it exists to catch, which is the failure mode the paragraph names. This is the "no implementation echo" rule: the expected side must be a literal transcription of §5.5's table (post-sweep: `hookCompatibility.test.js`, `consolidationBuild.test.js`, plus the fixture — and whatever F-01 adds), not a value derived from the code under test. "Compared to" also leaves containment open; the domain is an enumerated contract, so it needs **set-equality** over the full enumeration such that a dropped member reds. Fix: state that the expectation is a literal path set transcribed from the §5.5 table and that the assertion is set-equality against the actual spawn argument list. | §5.5 (recursion guard, part 1) |
| F-04 | Low | Local | **The child invocation is now fully pinned except for its `globalTeardown`, which is still left as an unresolved disjunction.** §5.5 pins the child's `--testPathIgnorePatterns`, its explicit file list, its `PDLC_SKIP_SINK` redirect and its sentinel env var — but the earlier sentence still reads that "the nested run's own `globalTeardown` must be disabled or its sink copied before it exits". `helpers/skipSinkTeardown.js` reads then `rmSync`s the sink directory, so the two branches leave the parent reading different artefacts, and the right set of the join depends on which one an implementer picks. With everything around it now pinned, this is the one remaining free variable in an otherwise executable spec. Fix: pick the branch (a `--globalTeardown` override on the child, or a copy step named before the child exits) and state it alongside the other child flags. | §5.5 (where the join runs) |
