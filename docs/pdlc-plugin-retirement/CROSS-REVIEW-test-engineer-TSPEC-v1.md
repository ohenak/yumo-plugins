## Positive Observations

- **The build-step reduction is verifiable line by line and it checks out.** Every kept and deleted symbol in §2.3 exists where the document says it does — `OUT_DIR:32`, `banner:45`, `stripModuleSyntax:56`, `wrapModule:66`, `moduleImportLines:87`, `devSource:94`, `adapter:97`, `QUEUE_META:308`, `CONS_META:324`, `DEV_META:346`, `CLI_DEV_EXPORTS:499`, `cliSource:513`, `CLI_SOURCES:530`, `cliArtifact:532`, `bundles:694`, `RETIRED_DIR:767`, `manifestRows:773`. The claim that `bundles` reduces to one row is exactly right: the fourth row is `{ file: "pdlc-cli.mjs", id: "pdlc-cli", contents: cliArtifact }` and the three above it are the `.bundle.js` rows. A reviewer can re-run this check in a minute, which is what an implementation contract should feel like.
- **§2.8 is the best kind of TSPEC section: dependents found by reading, with the commit that reds each one named.** `pipelineWiring.test.js`'s `devMeta()` (`:544`, anchor `const DEV_META = \``) and `consolidationPreflight.test.js`'s `T00 — BL-PREREQ` block (`:99`–`:109`, requiring `QUEUE_META`, `QUEUE_ENTRY`, `bundles`) are both real and both would have gone red mid-sweep. Routing them as errata rather than absorbing them keeps the upstream literals honest.
- **The all-or-nothing classification order in §2.5 is stated as an observable, not an implementation note** — "the script performs **no** deletion before its classification pass has finished over the whole directory" is exactly what makes AT-4.3's byte-identity clause checkable from outside, and AT-4.3 already carries the positive conjuncts (expected entries present *and* byte-identical, unexpected entry byte-identical, path on stderr, exit exactly `3`) rather than an absence-only "did not delete".
- **Exit `3` is pinned as a value, with the reason stated** (`127` and `1` must not be able to green the criterion), and the five-status shape genuinely mirrors `sync-workflows.sh` (exits `0`–`4` at `:70,:84,:250,:718,:722,:725`). Fixed statuses are the difference between a testable CLI and a non-zero shrug.
- **§4.5's "excluded key-path list, complement value-compared" is the right shape** for AT-5.2 — the exhaustive-exclusion framing means a new report field defaults to *compared*, which is the safe direction for a deletion sweep. F-02 is a gap in one rule inside a design that is otherwise well chosen.
- **§5.5's "deleted, never skipped", scoped repo-wide rather than to M-8's modules**, closes the obvious escape hatch before anyone reaches for it.

## Recommendation

**Needs revision**

Five High findings. F-01 and F-02 are the ones that matter most: as written, AT-3.3 clause 2 would be implemented against a false oracle for one hook and would silently omit a fourth, and AT-5.2's field-set rule can red on a correct sweep. F-03 undermines a data section the PLAN and PROPERTIES will transcribe. F-04 and F-05 leave the only artifact this feature actually builds without coverage of its documented invocation path and of two of its own five contract rows.

None of this touches the document's architecture. The dispositions, the class map and the erratum routing are sound; the revision needed is in §4.5, §4.7, §5.1 and §5.2 — restate three measurements from a reproducible scan, fix one comparison rule, and add four test rows.
