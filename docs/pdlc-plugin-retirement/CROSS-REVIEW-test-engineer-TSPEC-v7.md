| F-01 | High | Local | **The oracle's domain is not determinate: three of the four modules §5.5 enumerates are not hosts of an R-8 re-home, and §4.4 — the section §5.5 cites as the enumeration — says so.** §5.5 defines the domain as "M-8's deleted modules … plus the surviving hosts of R-8's re-homes (`consumerCleanup.test.js`, `hookCompatibility.test.js`, `orchestrateQueue.test.js`, `consolidationBuild.test.js`; §4.4 enumerates the re-homes)". §4.4 states the opposite for two of them: L-6 row 1 "**resolves to no re-homed assertion**" (the four `orchestrateQueue.test.js` titles are *protected pre-existing* assertions, discharged "by measurement rather than by a move"), and L-6 row 2 ends "**Nothing is re-homed for this row**" for `hookCompatibility.test.js`. `consolidationBuild.test.js` appears nowhere in §4.4; it hosts TT-5, a **new** test extending the T32 block (§5.2), not a re-home. So under §4.4's own measurements the landed surface is `{consumerCleanup.test.js}` plus M-8's deleted modules, and an implementer cannot enumerate the domain without asking which text binds — the "write the test right now" check fails on the oracle's own domain. This is not cosmetic: it decides whether F-01's downstream work (ten conversions plus ten inventory rows, below) is owned at all. Fix: pick one definition and make both sections say it — either narrow the domain to §4.4's measured re-home hosts, or state the intended wider rule ("every `*.test.js` this sweep creates, reduces, or edits") and route it upstream, because the landed FSPEC clause says "M-8's **deleted** modules and the surviving modules that **host R-8's re-homed assertions**" and neither limb covers a reduced-in-place module or a new host of new tests. | §5.5, §4.4 |
| F-02 | High | Local | **The nested run's file set contains the module that spawns it, so the join oracle as stated recurses without bound.** §5.5 places the join as "new assertions in `consumerCleanup.test.js` that **spawn a nested jest run over the swept-surface files**", and the same paragraph's domain puts `consumerCleanup.test.js` inside the swept surface. The nested run therefore collects `consumerCleanup.test.js`, whose join test runs as an ordinary collected test in that child run — `isInsideRunningTest()` (`helpers/driftCapabilities.js:292`) is a `driftCapabilities` guard and does not gate this — and spawns a grandchild, and so on. Nothing in §5.5 states a recursion guard. This is the classic self-spawning suite: it does not false-green, it hangs the gate, and the first person to hit it will "fix" it by dropping the host from the nested file set, which silently narrows the left set so the oracle can never see a skip introduced into `consumerCleanup.test.js` itself. Fix: name the guard and its consequence — either an env sentinel the nested invocation sets and the join test checks before spawning (so the host stays in the domain and the child's copy of the test is a no-op, which must then be a *registered* skip, not a bare one, or the oracle reds on itself), or an explicit `--testPathIgnorePatterns` exclusion of the host plus a stated compensating assertion for the host's own skips. | §5.5 |
| F-03 | Medium | Local | **The falsifying fixture is placed exactly where the nested run cannot collect it.** §5.5's red construction is "a fixture module under `__tests__/fixtures/` — excluded from the outer run by `testPathIgnorePatterns`, so it costs the real suite nothing — carries one bare `it.skip`", and the nested run is "pointed at that fixture". `testPathIgnorePatterns` is a *config-level* filter (`pdlc/workflows/package.json`, `"jest"` block: `"/node_modules/"`, `"/__tests__/helpers/"`, `"/__tests__/fixtures/"`), and jest applies it to explicitly-passed paths too — the nested run inherits the same config and collects nothing, so the join compares two empty sets and the red-construction assertion fails for a reason that has nothing to do with the property. It fails loudly rather than silently, which is why this is Medium and not High, but the construction as written does not run. State the override the child invocation carries (e.g. `--testPathIgnorePatterns=/node_modules/`, or `--config` with a fixture-scoped config), and state it as part of the oracle, not as an implementation detail — it is the thing that makes the falsifiability proof real. | §5.5 |
| F-04 | Medium | Local | **Adding ten `"bash"` rows to `SKIP_INVENTORY` contradicts the inventory's stated derivation, and no section dispositions that contradiction.** §5.5 converts the ten `hookCompatibility.test.js` fallbacks to registered skips and says the widening "is part of class-6's reduction scope". But `SKIP_INVENTORY` is not a free-form ledger: `helpers/skipSink.js`'s header states its derivation — "`SKIP_INVENTORY` is spec-derived — exactly TSPEC §1.3's table plus PROPERTIES §11.1's two leaves" — and that derivation is the stated reason closure is *not* enforced, and the reason "widening the inventory past the spec … is a spec change, not a test change". Every one of the sixteen live entries is `capability: "uid-nonroot"` and named for a spec id (`helpers/driftCapabilities.js:93`–`:118`); ten `"bash"` rows named for `hookCompatibility` test titles are the first entries with neither property. Either the header's derivation claim must be edited in the same commit (and then it is an owned edit to a surviving helper, i.e. §5.5's class-3 rule, not class-6 reduction), or the ten skips should be dispositioned some other way. As written the change makes a load-bearing comment false and leaves the "which document does the inventory transcribe?" question with two answers. | §5.5, §2.9 |
| F-05 | Low | Local | **`itOrSkip("bash", …)` transcribes the API in the wrong argument order.** The signature is `itOrSkip(name, capability, unverifiedInvariants, body)` (`helpers/driftCapabilities.js:324`), so `"bash"` is the first argument only if it is the test *name*. §5.5's spelling reads as capability-first. A copied call site fails immediately rather than silently, hence Low, but the row's join key is the leaf title and the spelling here is what a reader takes the title from. | §5.5 |
| F-06 | Low | Local | **The fixture's filename is unconstrained, and one spelling of it perturbs the L-5 count literal.** §5.5 says the fixture "joins no test count L-5 fixes". That holds for §4.4's measurement, which is the top-level glob `pdlc/workflows/__tests__/*.test.js` = 119 → 99 post-sweep. AT-1.3's own wording is "`*.test.js` **under** `pdlc/workflows/__tests__/`", which a recursive reading makes 100 once a fixture named `*.test.js` lands in `__tests__/fixtures/`. ## Positive Observations

- **The upstream route paid off and the transcription is faithful.** §5.5 and §6.1 item 9 now read the landed FSPEC v0.7 text rather than a proposal, and I checked the clause word-for-word against BR-SWEEP-6 and AT-1.3 in `FSPEC-pdlc-plugin-retirement.md`: swept-surface scoping, sink-records exemption, and the explicit "not `SKIP_INVENTORY` membership" key are all present upstream, not invented here. The reason given for the key (the inventory is not closed over registered skips) is independently true of `helpers/skipSink.js`'s WHAT IS NOT ENFORCED block.
- **The placement analysis is correct where it rules things out.** "`globalTeardown` receives config only, never `assertionResults`" is right, and `helpers/skipSinkTeardown.js` does read-then-`rmSync` before throwing, so the sink genuinely is unavailable to any in-run assertion. Ruling out the cheap option explicitly is what makes the remaining choice reviewable.
- **The falsifiability paragraph is the right instinct.** "an oracle that silently matched two empty sets would pass forever" is exactly the failure mode a set-join oracle has, and naming a red construction for it — rather than asserting the join and moving on — is what F-03 has left to fix, not the idea.
- **Both join directions are stated with what each catches, and the cardinality restrictions are justified by construction rather than assumed.** The `describeOrSkip` and `isInsideRunningTest()` carve-outs both check out against `helpers/driftCapabilities.js`.
