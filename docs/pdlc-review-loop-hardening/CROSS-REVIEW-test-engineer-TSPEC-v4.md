## AT-43a's two fixtures — do both directions red?

**Yes, and the two fixtures red on *different* implementations, which is what makes the pair worth having rather than one test with two names.**

- **(a) Refresh succeeds — reds on the pre-loop-snapshot implementation.** Under an entry-time snapshot on a clean branch `present` is `{}` for the life of the phase, so round 2's optimizer is greenfield: the `mode: "revision"` conjunct is false, the "requires a trailer" conjunct is false (greenfield's terminal test is structural completeness alone, §5.6.2), and the third conjunct is false too — `roundIndex` would be `sel.round ?? startIndex = 1` for both round 1's and round 2's episodes, so they *would* share a budget. Three independent conjuncts red on that one regression, which is the right redundancy for a defect that has now shipped twice.
- **(b) Refresh fails — reds precisely on the v1.2 rule-4 wording, which is the implementation the author claims and I confirm.** Under v1.2, `_listFiles` failing at round 2's optimizer keeps the previous maps; the previous successful observation on a clean branch was the empty `{}`, so rule 4's "`present` holds a candidate round" precondition is unsatisfied ⇒ greenfield ⇒ no trailer required ⇒ the `mode: "revision"` and trailer conjuncts both red. It also reds on the near-miss implementation that returns `present: null` but tests it loosely (`present?.size === 0` ⇒ greenfield), which is the shape a hurried implementer would reach for.
- **(b) does *not* accidentally red on the correct implementation, and I checked the arithmetic rather than assuming it.** With the failure at round 2's optimizer, the last successfully observed `startIndex` is `1` (round 1's authoring episode and each round-1 reviewer episode all refresh at entry, i.e. *before* the `-v1` files are written), so rule 4's `max(1, startIndex − 1) = max(1, 0) = 1` and the fixture's "revision **for round 1**" assertion holds — the same answer a successful refresh would have given (`startIndex = 2`, candidate `1`). The under-naming does not bite in this fixture.
- **The two fixtures' assertion sets differ in exactly the right place.** (a) asserts the `roundIndex`-differs conjunct; (b) correctly **omits** it, because under (b) the kept `startIndex = 1` means round 2's episode *does* share round 1's `EpisodeKey` — which §5.6.1 rule 4 accepts in terms as a bounded cost. An author who had copied (a)'s conjuncts into (b) would have written a fixture that reds on the implementation the document specifies; this one does not. That is the detail I most expected to find wrong, and it is right.
- The one conjunct I cannot see how to write from the document is (b)'s "and the failure reported" — new **N-02** above.
