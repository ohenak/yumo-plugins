## The halt is the fail-closed disposition — checked structurally, not by argument

**Confirmed: there is no path on which a mid-loop listing failure yields less work.** The halt is raised *before* any of the machinery that could reduce work exists:

- **No greenfield selection.** The halt is on the line above `w ← deriveRoundWindow(r.files, docType)`, so `w`, `present` and `selectMode` are never reached on that path. Rule 4's domain therefore has no third value, which is what its new closing paragraph claims and what §3.7's comment ("`present` is always a Map") now types.
- **No `startIndex` reset.** `startIndex` is only ever produced by `deriveRoundWindow`, which is not reached; H-1's failure mode (a reset to 1) is structurally unavailable.
- **No approval granted.** §5.4's approval search runs once, at phase entry, before `reviewLoop` (§5.4's opening line, §2.5 step 3) — a mid-loop halt is strictly after the last instant an approval could be granted, and it prevents rather than causes a skip.
- **No episode reaches terminal.** `throw haltError` propagates: I checked for a swallowing `catch` between `reviewLoop` and `main()`. The only `try/catch` inside `reviewLoop` at HEAD wraps the POSTMORTEM agent (and `recoverVerdict`), not the episode path; the adapter's `rtParallel` is `Promise.all`, which rejects on the first rejection, so a throw from a *reviewer* episode's refresh — the case running inside `_parallel` — propagates too rather than being absorbed into a resolved array. `main()`'s catch sets `outcome: "halted"`.
- **Strictly more conservative than v1.3.** Halting does not merely avoid the fail-open; it also removes v1.3's two accepted costs (the round under-named by one, the shared `EpisodeKey` and budget), so no residual "fewer dispatches" hazard remains to reason about.

## Clean-branch non-regression — checked, because the downside is that every first run halts

**The claim holds, and it holds for a stronger reason than the changelog gives.** The changelog says `docs/{feature}/` exists because the REQ lives in it. Measured at HEAD, that is enforced rather than assumed: `main()` rejects a `reqPath` that does not match `docs/{feature}/REQ-{feature}.md` and then halts before any phase with `Error: REQ file not found at {reqPath}` / `Error: REQ file at {reqPath} is empty` — the same `_readFile`-based check that derives `featureName`. So on every path that reaches `reviewLoop`, `docs/{feature}` exists and `_listFiles` over it returns `{ ok: true, files }`, empty on a cross-review-free branch. §6.2 row 1's benign `dir_missing` disposition is therefore unreachable from `orchestrate-dev`'s phase path and is retained only for totality over the closed catalogue (DC-01) and for the seam's other consumers — which is correct, not dead weight, and is not a finding. **No first run halts.**
