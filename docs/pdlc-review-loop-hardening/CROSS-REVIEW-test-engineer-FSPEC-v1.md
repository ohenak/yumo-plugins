| F-01 | High | Local | **A later non-approving round is silently overridden by an earlier approving one.** §5.1 step 3 searches round indices *descending* and stops at the first round satisfying 3(a)–(c). §10 then compares only the document's bytes. Concrete reachable scenario: round 2 is dual-approving; an operator force-runs Phase F (§11.4 — runs at round 3, "the prior approval record is left intact"); round 3's two reviewers write `Needs revision`; the invocation is then killed (or the operator stops) **before** the authoring pass edits the document. On the next invocation the descending search skips round 3 (non-approving) and lands on round 2, whose hash still matches the untouched bytes ⇒ `FRESH` ⇒ **Phase F is skipped and round 3's findings are discarded silently**. This is precisely the "silent loss of a review round" R-1/AC-3.5 scope (d) exist to prevent, arriving through the skip path instead of the terminal path. §5.1's justification ("a resumed history can legitimately hold a non-approving round above an approving one only in one situation … which AC-4.4's staleness test then governs") is wrong: the staleness test cannot see a round that produced findings but no edit. Required: specify that an approving round is usable only when **no higher round index exists** for that (feature, doc-type), or that any higher round carrying a non-approving parseable verdict denies the skip. No edge case and no AT covers this — AT-28 stops at the forced run and never asserts the *next* invocation's decision. | §5.1, §10.1, §11.4, E-11 |
| F-02 | High | Local | **The no-overwrite guard deadlocks a wrapped review episode's own re-dispatch.** §4.5 runs `_checkFile` on the exact target path **"before each reviewer dispatch of a round"** and treats `{ok: true}` (non-empty file present) as a pipeline-level operator error. §16.3/E-57 simultaneously require that a re-dispatch onto a **partial** cross-review "must continue it, never rewrite it". Those two rules collide on the common case: dispatch 1 of a review episode is stall-killed after writing a non-empty partial cross-review; §15.3 scores progress; §15.4 re-dispatches; §4.5 then sees a non-empty file at the instructed path and raises the operator error. Either the mandated continuation is unreachable, or the guard is silently exempted for intra-episode re-dispatches — the FSPEC says neither, and §4.5's reachability table asserts cases (i)–(iii) are "the complete set", which this fourth case falsifies. A test writer cannot decide which behaviour to assert. No AT covers a re-dispatch onto the episode's own partial artifact (AT-07 covers only the fresh-file guard). | §4.5, §16.3, E-57 |
| F-03 | High | Local | **A duplicated verdict field makes a finished cross-review permanently non-terminal, halting the phase.** §16.3 fixes cross-review completeness as "§6's persisted verdict field, parseable as exactly one catalogue value"; §6.3 makes two `VERDICT: ` lines unparseable. So a cross-review that a reviewer genuinely finished, but which carries two verdict lines, is **never** structurally complete ⇒ never terminal ⇒ the wrapper re-dispatches to `MAX_AUTHORING_DISPATCHES` (6) and then **halts the phase** (§15.4/§15.6), demanding a queue-row reset. E-58 answers only the approval half of the question ("fail closed: phase runs") and does not notice the terminal half; §16.3's own last row has the same blind spot. This is the same class of false halt as E-44 (a converged round halted) that the trailer mechanism was introduced to remove. Required: state the terminal criterion for a duplicated verdict, and either specify a remediation prompt that may delete the duplicate (an edit, not the AC-3.1a-forbidden whole-file rewrite) or make a duplicate terminal-but-non-approving. No AT covers the terminal direction — AT-11 asserts only that the phase runs. | §16.3, §6.3, E-58 |
| F-04 | Medium | Local | **The episode key does not separate a round's greenfield episode from its revision episode, so a healthy round-1 convergence can halt.** §15.1 fixes `episode = artifact set × phase × round index × invocation` and §15.4 says the counters "reset on each new review round **and** on each fresh invocation". Within one invocation of Phase F, round 1's *greenfield* authoring episode and round 1's *revision* episode share **all four** coordinates (same set, same phase, round 1, same invocation) — §15.2 rule 2 explicitly re-enters "the same round". Under the tuple as written, a greenfield pass that legitimately used 4 dispatches on a large FSPEC leaves the round-1 revision episode 2 dispatches, and a normal 3-dispatch revision pass halts the phase on `MAX_AUTHORING_DISPATCHES`. §15.1's opening sentence ("`dispatchAndVerify` wraps one dispatch loop") implies one call = one episode, which would fix it, but the document states both readings and the arithmetic differs between them. Since the reviewer's charge is that a healthy five-round convergence *provably* cannot halt, the key must be disambiguated — e.g. add mode (or "each `dispatchAndVerify` call") as a coordinate — and AT-42 must assert the greenfield→revision transition inside one round resets both counters. AT-42 as written only exercises one dispatch per round and therefore cannot distinguish the two readings. | §15.1, §15.4, AT-42, E-51 |
| F-05 | Medium | Local | **§15.5's "first unwritten section" walk is undefined for three of the four wrapped artifact classes.** The determination is specified as "walk the artifact's top-level headings … return the first whose body does not satisfy §16's criterion **for that artifact class**". §16.3 (cross-review), §16.4 (code-review) and §16.5 (LEARNINGS approval-record exclusion) are not per-heading criteria at all — §16.3 is a single whole-file verdict-field test. ## Positive Observations

- The REQ's two undecidability measurements are respected exactly. §8's trailer replaces "returned normally"; §15.3 is one mode-independent byte-change test; §15.7 states plainly that **no oracle for emitted bytes exists** and forbids TSPEC/PROPERTIES from asserting one. §15.8's proxy is explicitly advisory and non-halting, with its own honest limits (E-62 states the undetectable case openly). This is the right shape.
- The falsifier-bearing acceptance tests the REQ named as non-optional are all present **and carry their negative case in the AT text**: AT-12 (round-1 hash must be the reviewed bytes, "fails if the hash is sourced from a pre-episode pacing measurement"), AT-15 (pre-harvest edit ⇒ phase runs, "a test that passes only because the hash was recomputed at harvest … must fail"), AT-35/AT-36 (trailer-without-write terminal / complete-without-trailer non-terminal), AT-43 (mode survives the invocation seam on the same round), AT-39 (greenfield partial-section kill scores progress, three kills do not halt), AT-18 (record-less LEARNINGS **passes** the guard then fails closed — the inverted falsifier §9.7 demands). AT-19 is a good bundle-level oracle for the `await` hazard C-2 creates.
- §18's fail-closed direction is uniformly correct where it is specified: E-08, E-10, E-12, E-18, E-21…E-24 all run the phase, and §10.1 keeps `STALE` and `UNEVALUABLE` distinguishable in the report while identical in effect.
- Scope discipline holds: D-RLH-01…05 are named only to record why something is *out* of scope, never specified (§15.1, §15.4, §20, §21.1). `docs/requirements/traceability-matrix.md` pre-dates this feature (added under `pdlc-workflow-distribution`) and this feature appended a section in the same shape as the two existing ones — consistent maintenance, not unrequested scope.
- §21.3's retraction table is an unusually good review aid: it lets a reviewer check mechanically that no withdrawn rule was reinstated, and I found none reinstated.

## Recommendation

**Needs revision**

Three High findings each describe a reachable wrong outcome that §19 cannot currently detect: F-01 is a
fail-open skip that discards a completed review round (the exact failure class this feature exists to
close), F-02 and F-03 are false halts of healthy episodes (the failure class the trailer mechanism was
introduced to remove). F-04's counter-scoping ambiguity must be resolved before anyone can claim a
healthy convergence cannot halt. F-05…F-09 are gaps where a wrong implementation passes the stated
acceptance tests.
