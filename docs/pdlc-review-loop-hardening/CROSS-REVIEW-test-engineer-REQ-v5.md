| F-01 | High | Local | **AC-3.5b's revision-mode terminal condition is defined over "the dispatch returned normally", which §4a A-8 measures as unobservable and AC-3.5e is explicitly written not to distinguish — so the condition is either undecidable or fail-open in exactly the direction v1.4 closed the mode flip to prevent.** AC-3.5b: "'Terminal' is structural completeness (AC-3.4) in greenfield mode, and, in revision mode, the completion of the dispatched revision — the artifact is structurally complete **and the dispatch returned normally** having made progress." A REQ that quotes its own wrong sentence before replacing it is far cheaper to re-review than one that quietly reworded.
- AC-3.5 scope (a)'s population table is the strongest change in v1.4. Naming every dispatch, its wrapped-ness, its measured artifact set **and the bound that covers it when unwrapped** converts an ambiguity into a fixture list: a test author can enumerate the wrapped rows directly, and O-19(f)'s "an excluded code-writing dispatch is demonstrably not wrapped" is a negative test with an obvious oracle. R-11 and D-RLH-05 record the residual gap with a successor row rather than hiding it.
- AC-3.5 scope (c) solves the naming problem the right way round: it noticed that "document type" was already load-bearing for the *reviewed* doc type, coined **wrapped artifact class**, and then fixed two of the four criteria at REQ altitude instead of delegating all of them. Reusing AC-4.2's verdict field as the cross-review terminal marker — and observing that it is written last and is the same check AC-4.2a performs — is a genuine simplification, not a restatement.
- AC-4.2d's "tier 1 → tier 2 is a copy, not a re-derivation" is the correct invariant and is argued from its consequences (no history walk, the tiers can never disagree, survives a squash merge). O-14's new fixture is stated as a mutation test on the old rule ("this test passes only because the hash is recomputed at harvest — the falsifying case AC-4.2d must fail"), which is exactly the form a load-bearing oracle should be specified in.
- AC-2.7a is a complete recovery contract in one clause — the act, what is refused until it happens, the difference between the two halt classes, and where it is documented — and A-10 measures the claim it rests on against the real `selectNextPending` rather than against CLAUDE.md's prose alone.

## Recommendation

**Needs revision**

Exactly what must change:

1. **F-01** — remove "the dispatch returned normally" from the revision-mode terminal condition and define terminal over script-observable state only. As written the condition is either undecidable (every revision round halts) or fail-open (a killed mid-edit dispatch reports success on a partly-unaddressed round), and A-8/AC-3.5e forbid depending on the runtime's return shape.
2. **F-02** — give revision mode a terminal route that does not require progress on the terminal dispatch. Today AC-3.5g makes a no-op the correct continuation output while AC-3.5b treats a no-op as a failed attempt, so a fully converged revision round halts the phase and commits a `halted` queue row. F-01 and F-02 should be fixed in one clause; a positive, agent-emitted completion marker parsed by the script satisfies both.
3. **F-03** — stop requiring a cross-review file to carry the sha of its own commit; record that sha at tier 2 only, or drop it.
4. **F-04** — delete or correct AC-4.2d's "(AC-3.5's pre-episode measurement)" parenthetical; name the read that actually produces the hash (the reviewed document in the working tree as sent for review).
5. **F-05** — state the greenfield progress predicate for a partial-section write, or restate the "on disk" clause as working-tree-versus-committed with no claim about the predicate.

F-06 and F-07 are one-token citation corrections. Everything else added at v1.4 — AC-2.7a, the scope (a) population table, scope (b)'s artifact set, scope (c)'s wrapped artifact classes, scope (d)'s stickiness, AC-3.5b bullet 2's prompt, AC-3.5d's recovery clause, AC-3.5f's re-argued classification, AC-3.6's population separation, AC-4.2b/AC-4.2d's copy-not-recompute rule, AC-4.4's pre-harvest window, A-10, D-RLH-05, R-10, R-11, and the O-7/O-14/O-19/O-21 extensions — is approved from a testing lens.
