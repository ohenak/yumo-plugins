## Positive Observations

- **The batch column is mechanically correct on every one of the 54 rows.** I re-derived `max(dep batch) + 1` independently; nothing is understated, nothing is a guess, and the three single-writer hazards §5 names are genuinely serialised by `Deps` edges rather than by adjacent prose. This is the check that most often fails, and it does not fail here.
- **§4's file-ownership manifest is auditable as promised.** Column-wise, no batch shows one path twice; the directory-entry-granularity note about `__tests__/fixtures/` is exactly the collision rule the wave partitioner uses, and the "no task may own `fixtures/` itself" clause forecloses the one way it could still collide.
- **The `[Fake first]` convention is observed where it matters.** `_bootstrap.mjs` (T12), `_run-suite.mjs` (T11), `_corpus.mjs` (T48) and `_replay-double.mjs` (T49) each precede their only consumers by a real edge, and §5 names the consumer for each.
- **Vacuous-green pressure is treated as the primary risk rather than a footnote.** §1's point 1 and §10's second risk row both identify that `observed ⊆ OUTCOMES` passes over the empty set, and the schedule answers it structurally — spine in batch 3, inheritance self-test in batch 2, emptiness guard inside T19 rather than in a later hardening pass. That is the correct place for it.
- **Several oracles are written as a positive plus its own falsifier in the same file**, which is precisely the form that cannot rot: T09's redaction scanner with a positive-control scratch file; T33's "a deliberate read under `.claude/workflows/` **must** fail clause 3"; T34's "the write-less double **fails** this test first"; T28's "three clauses each with the falsifying counterpart in the same file, deny-path performing the deletion it guards"; T02's trap that must actually fire.
- **T30's timeout oracle is a literal transcription, not an implementation echo.** "`dispatch.timeoutMinutes: 7` asserting the literal `420000` at the boundary and `7` in the report" states both expected values outright; nothing recomputes `7 * 60 * 1000` in the test.
- **T22 correctly transcribes TSPEC §3.4's two-part contract** — containment over `{model, cwd, timeoutMs, maxTurns}` plus required-key presence — rather than an instance-level set-equality that would fail on every real dispatch (`TSPEC:513-565`). The distinction is subtle and the plan got it right.
- **The T16 single-task rule is stated as a scheduling obligation with its mechanism.** Source edit, `build-runtime.mjs` run and regenerated `dist/` artifacts in one task, with `implementation.postWavePathspecs` named as what commits them — verified present at `.claude/pdlc.config.json:5`.
- **§11 quotes the pre-change spelling of every command it expects to change**, so the delta is checkable rather than remembered — including the honest observation that at HEAD `implementation.testCommand` runs the *workflows* suite, so this feature's own wave gates would be blind until T17 lands.
- **§10's deferral of prompt caching states its testing rationale**, not just its cost: a cache keyed after composition would corrupt `promptHash`, turning T50's row-4 pairing predicate into a false positive. That is a test-integrity argument, and it is the right one.

**Needs revision**

Five High findings. This is a strong plan mechanically — the batch DAG is correct on every row, the ownership manifest is genuinely auditable, and the citation discipline held under independent re-measurement — so the revision is targeted, not structural:

1. **F-01** — pick one no-bare-literal oracle (TSPEC §3.3's exactly-equal allow-list or DEC-ENG-05's no-exemption containment) and record the choice with its reason in T07's row.
2. **F-02** — name the task or operator step that produces the second platform's `M-ENG-09` row, or change §5's batch-5+ gate wording to state which platform's suite is expected red until it exists.
3. **F-03** — give AT-ENG-02, 05, 17, 18, 32, 40, 57 and 66 an owning row or an absorbing clause; AT-ENG-17/18 (billing abort, mid-run source change) need a real red task.
4. **F-04** — restate §9's Acceptance-tests column as set-equal to FSPEC §14.1, annotating any deliberate re-routing.
